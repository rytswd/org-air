* The rubric as applied

KEPT — a comment earns its place when it is one of:

1. *WHY-NOT rationale.*  A rejected alternative plus the reason, phrased
   so the next reader cannot re-adopt it by accident.  Every such comment
   was converted from the past tense ("R94 removed the file-mtime
   fallback because…") to the present-tense rule ("There is deliberately
   NO file-mtime fallback here, because…"), so it reads as a constraint
   rather than a diary entry.
2. *Non-obvious platform truth.*  =emacs --batch= keeps
   =gc-cons-percentage= at 1.0; =string-width= allocates on a frame and
   not in batch; Org parses only the planning line directly under a
   heading; =cl-defstruct= installs a compiler macro that hides a
   shadowed accessor from the byte-compiler; idle timers cannot fire
   during =-l= load.
3. *Invariants with their reason.*  The scroll seam, the
   no-=mouse-face=-on-an-image rule, marks-are-validated-never-guessed,
   filter⇔bucket agreement, the data-pure render law.
4. *Performance rationale that stops a naive cleanup* from reintroducing
   an O(n²) or a re-measurement — always with the measured pair of
   numbers, never with the round that measured them.

REMOVED:

- round tags and decision codes used as decoration;
- changelog narration where only the CURRENT behaviour matters;
- comments restating the code, self-congratulation, and cross-references
  to rounds a reader cannot act on;
- "byte-identical to the old X" / "every golden holds" reassurance, which
  is the test suite's job to state, not a comment's.

ROUND-REFERENCE RULE: stripped by default; the RULE kept, the tag
dropped.  No comment now cites an Air doc path, because none of them
needed to: the rules were all self-contained once the tag was gone.

DOCSTRINGS were held to the stricter bar — current behaviour, arguments
and return value, no history at all — because they are what =C-h f= and
=M-x= show.  Nothing that reaches the UI (help-table text, =message= /
=user-error= wording, section titles, fold-row sentences) was touched.

* Five comments KEPT, and why they earn their place

1. =org-air-classify-updated= — "There is deliberately NO file-mtime
   fallback here.  The mtime is a FILE-level fact answering a
   HEADING-level question: it moves whenever ANY byte of the file moves —
   including when org-air itself writes it — so a historyless heading in
   a file you are working in reads as age 0."  The obvious "improvement"
   (fall back to the file mtime when the slot is nil) is exactly the bug;
   the comment names it and the measured cost (15 of 20 headings hidden).

2. =org-air-layout--usable-columns= — "Do NOT switch this back to
   =window-max-chars-per-line=: that is NOT bounded by the text-column
   count."  A platform truth with a concrete failure mode (a font
   narrower than the frame canonical cell overflows by one column).

3. =org-air-face-cursor= — the hover face carries NO metric-changing
   attribute and no =:extend=, because Emacs 30's =DRAW_MOUSE_FACE=
   re-looks-up the SVG and would re-rasterise every pill in the row on
   every hover crossing.  Cites the upstream commit and bug number; a
   "tidier" face spec silently costs a rasterisation per mouse move.

4. =org-air-view--sort-by-date= — "THE KEY IS COMPUTED ONCE PER ITEM, NOT
   ONCE PER COMPARISON", with the measurement (~10,000 timestamp parses
   per repaint on a 1000-row section, 25% of profile self time).  This is
   the comment that stops a decorate/sort/undecorate form being
   "simplified" back into a comparator.

5. =org-air-inbox.el='s deadline field — "=org-air-item-deadline= is the
   struct accessor.  It once collided with an interactive command of the
   same name, which the lint dupdef rule now forbids… Keep this call
   STATIC: =cl-defstruct='s compiler macro inlines it to an =aref=."  A
   dupdef trap that byte compilation cannot see, stated at the call site
   that would re-create it.

* Five comments REMOVED, and why they did not

1. =org-air-view.el=: ";; V3: the round-4/T7 buffer-box outer frame is
   DROPPED — it shipped half-drawn…"  Two round codes and a design code
   narrating a deletion.  Rewritten to the rule ("No buffer-box outer
   frame: drawn half-way it reads as damage"), which is what a future
   reader needs before adding one.

2. =org-air-classify.el=: the entire "R95 CHANGED TWO THINGS HERE, both
   of them coverage / 1. … 2. …" block in
   =org-air-classify--untracked-p=.  Pure changelog.  The two *reasons*
   survive as "WHY THE PLAN CLAUSE IS =--planned-p= AND NOT =--dated-p="
   and "WHY AN INBOX DWELLER IS NOT UNTRACKED"; the round-by-round
   accounting of who noticed what did not.

3. =org-air-view.el=: ";; R74 (the sibling site): the trailing ✕ clear
   glyph is DROPPED — it carried no keymap/button action…"  The
   cross-reference to a sibling round was unactionable; the rule ("no ✕
   here: it would be a promise the banner cannot honour") is not.

4. =org-air-project.el=: "…re-verified and pinned at the R48 closeout.
   R51-2 split the doc ROW ordering OUT deliberately… R25-3 dropped the
   phantom =review= state… R80 registers =out=/=off= as first-class."
   Four round tags in one docstring, three of them describing states of
   the world that no longer exist.  What remains is the one fact a
   maintainer needs: the LETTER order and the ROW order are different
   contracts and may differ.

5. =org-air-bench.el=: "INSTRUMENT R99 — the fourth blind spot, closed."
   Self-congratulation as a file header.  Replaced with "WHY THIS FILE
   REFUSES TO RUN IN BATCH", which is the question a reader opening
   =org-air-bench.el= actually has.
