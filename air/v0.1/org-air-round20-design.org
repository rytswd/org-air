* R20-1 — async first load HANGS: make the first load synchronous-but-fast [CRITICAL]

** Reproduction — two real failure modes, both rooted in the R19-1 design
The R19-1 "chrome-first + timer-chunked query" loader (org-air-view.el) is
the source of both symptoms the user hit ("Loading your board… never
resolves" + "an EXTREMELY LONG message dumped to the echo area").

*** Symptom 1: "Loading your board…" never resolves
The loader chains =run-with-idle-timer 0 nil #'org-air-view--load-step= — each
step queries =org-air-view-load-batch= (=8=) files, then *reschedules another
idle-0 timer* (=org-air-view--load-step=, L4347–4374).  At 120 files that is
=(ceiling 120 8)= = *15 chained idle-timer ticks*.  Two ways this never
finishes:
1. *Idle-0 starvation under input.*  An idle timer fires only after Emacs has
   been idle for its delay; *every* input event resets the idle clock.  A
   user who keeps moving point / scrolling the skeleton while it "loads"
   keeps resetting the 0-second idle clock, so the next =--load-step= is
   postponed indefinitely → the board stays the empty skeleton forever.
2. *An errored step breaks the chain with no recovery.*  =--load-step= has
   *no* =condition-case= / watchdog / completion guarantee (verified: lines
   4327–4410 contain none).  If any batch signals (a transient org-element
   parse error, a marker into a half-saved file, an org-ql edge), the step
   throws, the *reschedule never runs*, and =org-air-view--loading= stays =t=
   forever.  =org-air-view--loading-guard= (L4392) then makes every data
   command =user-error= "Still loading your board…" permanently.

*** Symptom 2: the EXTREMELY LONG echo-area message
When a function run from a timer signals, Emacs's =timer-event-handler=
reports it with =(message "Error running timer ...: %S" ERR)= — the *whole*
error object, printed with =%S=.  org/org-element/org-ql errors routinely
carry large data payloads (parse fragments, marker/list data).  Measured: an
error whose data is a 2076-element list prints a *101,802-character*
echo-area message:

#+begin_src text
Error running timer 'org-air-view--load-step': (error "org-ql query failed" ((:title "x" ...) ...))   ⇒ 101802 chars
#+end_src

So a single errored batch both (a) wedges the board (Symptom 1.2) and (b)
spams a six-figure-character message.  This is intrinsic to running the query
from a bare timer with no error containment.

** Decision — DROP the chained-idle-timer path; first load is SYNCHRONOUS but fast
Per the user's steer ("org-ql should give us all the performance we need …
perf should come from org-ql being fast + the R18 caches, NOT fragile async
gymnastics"), and because the cold cost is a *one-time* ~2.9 s that the warm
org-element + R18 caches never pay again, the first load becomes
*synchronous with an honest fast paint*:

1. *Honest fast paint first.*  On a cold interactive =org-air-view=, after
   =pop-to-buffer= paint the chrome skeleton (=org-air-view--render-loading=,
   reused as-is) and force it visible with =(redisplay t)= so the frame +
   "Loading your board…" line appear within one paint — BEFORE the query
   runs.  This keeps the perceived-instant frame that R19-1 wanted, with zero
   timers.
2. *Then query + render synchronously.*  Run =org-air-query-items= and
   =org-air-view--render= inline (the existing cache-hit / =noninteractive=
   branch), wrapped in =unwind-protect= so =org-air-view--loading= is always
   cleared even on error.  No batches, no idle timers, no token generation,
   no progressive reflow.
3. *Surface errors cleanly.*  Wrap the query+render in =condition-case=; on
   error, clear =--loading=, render the normal empty board, and
   =(message "org-air: load failed: %s" (error-message-string err))= —
   a *truncated, single-line, human* message (never =%S= of the payload).

This removes =org-air-view--load-async=, =--load-step=, =--load-finish=, the
=--load-token= / =--load-remaining= / =--load-total= / =--load-accum= state,
and the =org-air-view-load-batch= / =org-air-view-load-progressive=
defcustoms.  Keep =org-air-view--render-loading= and =--loading= (now set/
cleared around the synchronous body) and =org-air-view--loading-guard= (still
guards the brief window during the synchronous load, harmless).

*** Entry-point shape (org-air-view, L4400)
#+begin_src elisp
(defun org-air-view ()
  (interactive)
  (let* ((buffer (get-buffer-create org-air-view-buffer-name))
         (cached (with-current-buffer buffer
                   (org-air-view-mode)
                   (and org-air-view--items
                        (equal org-air-view--items-key
                               (list org-air-files org-air-inbox-file))))))
    (pop-to-buffer buffer (or org-air-display-action '(...)))
    (with-current-buffer buffer
      (cond
       ;; Cache hit OR batch: synchronous, byte-stable (unchanged).
       ((or cached noninteractive)
        (unless cached
          (setq org-air-view--items (org-air-query-items)
                org-air-view--classify-cache nil))
        (org-air-view--render org-air-view--items org-air-view--tag-filter))
       ;; Cold interactive: honest fast paint, then synchronous query+render.
       (t
        (setq org-air-view--loading t)
        (unwind-protect
            (progn
              (org-air-view--render-loading)
              (redisplay t)               ; frame visible before the query
              (condition-case err
                  (progn
                    (setq org-air-view--items (org-air-query-items)
                          org-air-view--items-key (list org-air-files
                                                        org-air-inbox-file)
                          org-air-view--classify-cache nil)
                    (org-air-view--render org-air-view--items
                                          org-air-view--tag-filter))
                (error
                 (org-air-view--render nil org-air-view--tag-filter)
                 (message "org-air: load failed: %s"
                          (error-message-string err)))))
          (setq org-air-view--loading nil)))))))
#+end_src

** If any async is retained (fallback option — NOT preferred)
Should a later impl decision keep a deferred path, it MUST satisfy all three
or it does not ship:
1. *Guaranteed completion.*  A single =run-with-idle-timer= (not a chain) that
   queries ALL remaining files in its body, plus a *watchdog* =run-with-timer=
   (e.g. 5 s) that, if =--loading= is still =t=, forces the synchronous query
   and clears the flag.  Never depend on N chained idle-0 ticks.
2. *Error containment.*  The timer body is wrapped in =condition-case= (or
   =with-demoted-errors=) so a failed batch never escapes to
   =timer-event-handler=; on error fall back to the synchronous render.
3. *No giant message, ever.*  Any user-facing message is a single truncated
   line via =error-message-string=; never let =%S= of an error/payload reach
   the echo area.
The synchronous-with-honest-paint design above is strictly simpler and is the
recommended shipping path; the async fallback exists only to bound the impl's
options.

** Batch / noninteractive contract (invariant #3)
=noninteractive= keeps taking the cache-miss synchronous branch unchanged, so
=make regen-mockups= and every byte golden are byte-identical.  The
=redisplay= + =--loading= dance lives only in the cold-interactive =t= branch,
which batch never reaches.

Decoded structure (this is the contract — match the STRUCTURE, render it in
org-air's idiom; do NOT copy airctl's box-art bytes):
- *Top-level dirs* (=v0.1/=, =v0.2/= …) are the outermost groups.  Each opens
  with a *rolled-up header*: full state NAMES + parenthesised TOTALS over the
  WHOLE subtree, only states present, in the order *Ready · Complete · Dropped
  · Draft* (and Work-In-Progress · Review between Ready and Complete when
  present).
- Inside, a *nested directory tree*: the dir's OWN docs first, then child
  directories (alphabetical), recursively to any depth.
- *Per-directory state counts* on each directory's heading: =BADGE N (+M)=
  where =N= = docs of that state DIRECTLY in the dir and =(+M)= = the same
  state summed over descendant dirs; when =N=0= but =M>0= show =BADGE (+M)=
  (no number); when =M=0= show =BADGE N=.  Same state order as the header.
- *Docs are STATE-FIRST within a dir*: Ready, Work-In-Progress, Review,
  Complete, Dropped, Draft; ties broken by name (natural sort).  (The prompt's
  stated order =Ready, Complete, Dropped, Draft …= is honoured; this is also
  airctl's count-badge order.  airctl's doc LISTING happens to swap Draft↔
  Dropped — we normalise to ONE order for both the badges and the listing.)

** R20-5(a) — nested directory-tree grouping
Replace the flat =org-air-project--sections-by-directory= with a recursive
tree model and make =directory= the DEFAULT group (=org-air-project-group=
→ =directory=), since that is what =-Da= shows.

*** Data: build the tree from relpaths
New =org-air-project--directory-tree (docs)= → an ordered list of TOP-dir
nodes.  A node is a plist:
#+begin_src elisp
(:dir "air-template" :depth 1 :relpath "v0.1/air-template"
 :own-docs (… state-first …)        ; docs whose dirname = this node
 :children (… child nodes …)        ; sub-dirs, name-sorted
 :counts (("ready" 4 1) …)          ; (state direct descendant) per state
 :total-counts (("ready" 5) …))     ; rolled up (top node header only)
#+end_src
Derive a doc's directory chain from =(file-name-directory (org-air-doc-relpath
d))= split on ="/"=.  Each path prefix is a node; =own-docs= are docs whose
full dir equals the node's path; =children= are the next-segment dirs.
=:counts= are computed bottom-up (descendant =(+M)= = sum of children's
direct+descendant for that state).

*** Rendering: depth-indented sections, reuse the row primitive
- Each top-dir node renders a *box header* line: =▌ v0.1/= + the rolled-up
  state-name/total badges (reuse =org-air-view--rail-header='s marker idiom
  and the existing =org-air-project--state-badge= / =--state-title= /
  =--state-face=).
- Each directory node (including the top dir's own-docs node) renders a
  *count heading*: =▌·indent· dir/= + the =BADGE N (+M)= per-state cells.
  Indentation = =:depth= × 2 cols so the nesting is visible (org-air idiom,
  not airctl's =├─/└─= glyphs — though a faint connector glyph in the prefix
  cell is acceptable if it stays in the svg/TTY-fallback contract).
- Under each node, its =own-docs= render with the existing
  =org-air-project--insert-doc-block= (two-line block, =show-state= t),
  state-first; then recurse into =children=.
- Reuse the single comparator =org-air-project--sort-section-docs= for the
  within-state tiebreak so ordering stays uniform.
- =board-only= (narrow) orientation renders the SAME tree full-width (no
  rail), exactly as today's board-only path.

*** State order constant
Introduce =org-air-project--state-display-order= =
=("ready" "work-in-progress" "review" "complete" "dropped" "draft")= and use
it for BOTH the per-dir badges and the within-dir doc ordering, so the two can
never drift.  (=org-air-project-states= / =-sections= stay for the legacy
state/tag modes.)

** Reproduction

* R20-3 — view pane: close with `q' · debounce the live follow harder · clear boundary [HIGH]

** Reproduction
*** (a) cannot close while focused

* R20-6 — perf pass: snappy at 2151 items (org-ql + R18 caches + kill the O(N) re-render passes) [PERF]

** Profiled on 120 files / 2076 items (≈ the user's 2151)
=elp= over =org-air-view--render= on a warm buffer (R18 caches hot).  The board
DISPLAYS only ~35–52 lines (a sectioned summary with per-bucket
=seq-take= limits) — yet a warm re-render costs *~0.43 s*.  Breakdown
(per-render, averaged over 5):

| function                       | per render | why                                   |
|--------------------------------+------------+---------------------------------------|
| =org-air-view--compute-meta-widths= | *0.240 s* | measures date/tags/origin over ALL 2076 items |
| =org-air-view--items-for-bucket=    | 0.136 s | *17 redundant bucket passes* / render |
| =org-air-view--visible-items=       | 0.084 s | *21 redundant calls* / render         |
| =org-air-view--classify-cached=     | 0.050 s | *176 470 calls / 5 renders* = ~35 k/render (17×/item; cached, so cheap each) |
| =org-air-view--insert-section= (rows)| 0.020 s | only ~35 rows actually inserted       |
| inspector update (1 item)           | 0.00002 s | fine                                |
| =org-ql= cold query                 | ~1.5 s (1×) | first org-element parse             |
| =org-ql= warm re-query              | ~0.06 s | org-element cache hot                  |
| cold first render (uncached)        | ~1.4 s (1×) | warms classify + svg caches         |

*Diagnosis:* the cold costs are one-time (org-ql + warming the R18 caches —
exactly where the user wanted the perf to come from, and it does).  The
INTERACTIVE pain is the *warm re-render* (every live-filter keystroke / scope /
refresh): it makes ~17 full O(N) passes over all 2076 items
(meta-widths, per-bucket filtering, visible-items) even though it paints
~35 rows.  org-ql + the R18 classify/svg caches are NOT the bottleneck — the
redundant per-render passes are.

** Fixes — one pass per render, measure only what is shown
1. *Single bucket partition.*  Compute the visible set + the bucket→items
   partition ONCE per render (one classify pass), and have every consumer —
   sections, =--insert-summary= counts, the section-count badges, the
   calendar, AND =--compute-meta-widths= — READ that partition instead of
   re-deriving it.  Collapses the 17 =--items-for-bucket= passes and the
   17×/item classify to *1×/item*.
2. *=--visible-items= once.*  Compute it a single time at the top of
   =--render= (or alongside the partition) and thread it through; today it is
   recomputed 21×/render.
3. *Meta-widths over the DISPLAYED items only.*  =--compute-meta-widths=
   currently walks every bucket's FULL member list; instead measure date/tags/
   origin over only the rows that are actually inserted (the per-bucket
   =seq-take= subset, plus any expanded section).  Columns still align (the
   contract is per-render alignment of WHAT IS SHOWN), and the cost drops from
   2076 items to ~35 — the single biggest win (≈0.24 s → ≈0.005 s).
4. *Keep the R18 caches* (classify + svg + incremental inspector) intact —
   they are doing their job; this pass removes the redundant CALLERS, not the
   caches.

*Projected:* warm re-render ~0.43 s → *< 0.1 s* at 2076 items, so live filter/
scope/refresh feel instant; cold first render also drops (meta-widths over the
displayed subset).  Navigation (=n=/=p=) does not re-render at all — it moves
point + the debounced inspector (0.00002 s) + the view-pane follow.

** View-pane follow (the other interactive hot path)
Covered by R20-3(b): the per-change cost is the editable-indirect REBUILD, not
classification.  Reusing the indirect (re-narrow same-file) + the 0.2 s
debounce makes the follow cheap at 2076 items.  No separate work here.

** Invariants / byte contract
The render output is UNCHANGED — this is a pure compute-once refactor of the
SAME buckets/widths/visible set, so every byte golden stays byte-identical
(the displayed rows + their measured columns are the same items in the same
order).  Meta-widths measured over the displayed subset yields the SAME widths
as today *whenever* the widest displayed cell equals the widest overall (the
common case); where a hidden item was wider, the column now fits what is shown
— a deliberate, tighter result.  IF any fixture shifts, it re-blesses with a
design note; the expectation is zero shift for the current goldens (the
displayed rows already contain the widest cells in these fixtures — the test
seat verifies with =make regen-mockups= + a byte diff).

** Testability (R20-6)
- BENCH (not a gate): a repeatable =tests/org-air-bench.el= harness over a
  generated large set asserts the warm re-render stays under a generous
  ceiling (e.g. < 0.2 s) so a future O(N) regression trips — informational,
  excluded from =make check= timing-sensitivity (skipped under CI load via a
  =skip-unless= on an env flag).
- ERT (correctness, the real guard): the single-partition refactor yields the
  SAME bucket membership + the SAME section counts as the per-section path
  (compare old vs new partition for a fixture item set) — proves the
  compute-once path is behaviour-preserving.
- ERT: =--compute-meta-widths= over the displayed subset returns widths ≥ the
  widest DISPLAYED cell (alignment invariant) for a fixture set.
- =make regen-mockups= + byte diff = 0 on the existing board goldens (the
  contract); any shift is called out + design-blessed.

** Routing (R20-6)

=--render= (or a memo bound for the render's dynamic extent); refactor
=--insert-item-pane= / =--insert-section= / =--insert-summary= /
