* R32-1 — project hover highlights the whole doc block: mouse-face spans the row-separator newline [BUG]

** Root cause — the shared row primitive props the trailing newline too
Both the board (=org-air-view--insert-item=) and the project
(=org-air-project--insert-doc-row=) build a row through the ONE shared
primitive =org-air-view--insert-row=, passing =mouse-face
'org-air-face-cursor= inside =:props=.  The primitive applies them with:
#+begin_src elisp
(insert line "\n")
(when (or props face)
  (add-text-properties start (point)                 ; start .. AFTER the \n
                       (append props (when face (list 'font-lock-face face)))))
#+end_src
=(point)= is AFTER the inserted =\n=, so the row-separator NEWLINE
receives =mouse-face= too.  Emacs highlights the maximal run of
positions sharing an =eq= =mouse-face= value: when row N's trailing
newline AND row N+1's first glyph both carry =org-air-face-cursor=, the
two rows fuse into ONE hover region.  Any number of adjacent doc rows
therefore merge into a single block — exactly the report.

Why the PROJECT shows it and the BOARD does not (measured, not assumed):
- The project's =board-only= and =side-window= orientations call
  =(funcall left-fn width)= which inserts doc rows DIRECTLY into the
  real buffer, so the mouse-face-bearing newlines survive and adjacent
  rows merge.
- The BOARD always composes its body through
  =org-air-view--render-lines= (render into a temp buffer, SPLIT on
  newline into a list of line strings, then re-insert joined by FRESH
  newlines).  The split DROPS the original newline characters, so the
  re-inserted row separators carry NO props — board rows are already
  independent hover regions (verified: zero multi-line runs in
  board-only / two-pane / stacked).  The project's OWN =two-pane=
  orientation uses the same render-lines path and is likewise fine; only
  the project's DIRECT-insert orientations exhibit the merge.

Directory-node lines (=org-air-project--insert-dir-node=) and
section-heading lines (=org-air-project--insert-section-heading=) add
only =org-air-section= / =org-air-count-badge= — NO =mouse-face= (bol
and newline both nil, verified).  So there is nothing to REMOVE from the
dir/header lines; the requirement "dir/header get no hover" already
holds and is asserted below as a regression guard.

** Decision — scope mouse-face to the row's own text, in the shared primitive
One localized change in =org-air-view--insert-row= (no fork; fixes every
direct-insert caller at once): keep all row-identity properties
(=org-air-item= / =org-air-doc=, =org-air-marker=, the R21-2
=org-air-row-title= mark, =font-lock-face=) over the FULL row extent as
today, but apply =mouse-face= only over the row's own glyphs — i.e.
=start .. (1- (point))=, EXCLUDING the trailing newline:
#+begin_src elisp
(insert line "\n")
(when (or props face)
  (add-text-properties start (point)
                       (append props (when face (list 'font-lock-face face))))
  ;; A row-separator newline must not carry mouse-face, else adjacent
  ;; rows merge into one hover region (R32-1).  Scope it to the row body.
  (when (plist-member props 'mouse-face)
    (remove-text-properties (1- (point)) (point) '(mouse-face nil))))
#+end_src
Effect:
- PROJECT direct-insert paths (board-only, side-window): each doc row's
  =mouse-face= run is now bounded by its own newline (which carries no
  =mouse-face=), so hover highlights exactly the single row under the
  pointer, in all three groupings.  Verified in simulation (every run
  single-line).
- BOARD and the render-lines paths: byte- AND property-INVISIBLE — their
  re-inserted newlines never carried =mouse-face= to begin with, so
  stripping it there is a no-op (board still zero multi-line runs).
- CLICK / RET unchanged: =org-air-doc= + =org-air-marker= (and even the
  newline) still cover the row, so =mouse-1= / =RET= resolve the single
  doc under point exactly as before — only =mouse-face= (the HOVER paint)
  is narrowed.
- KEYBOARD highlight: there is no persistent keyboard row highlight to
  disturb — =org-air-face-cursor= is used ONLY as =mouse-face= (grep:
  two call sites, both the shared row's =:props=); point landing is the
  R21-2 title mark, and the jump-pulse
  (=pulse-momentary-highlight-one-line=) is a separate momentary effect,
  untouched.

Board scope note (per the round's instruction): the board does NOT have
the over-broad hover (render-lines already drops the separator props), so
no board-only change is needed; the shared-primitive fix covers the
project's direct paths AND future-proofs any new direct-insert row, and
is the SAME one-line change — so it is made once, in the shared floor,
not forked into the project.
