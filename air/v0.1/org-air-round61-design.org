* Summary

A new read-first surface — =org-air-review= — that answers "what
happened over this week / month": items completed, time clocked (rolled
up by tag / directory / origin), items started, and work touched but
not finished.  Period navigation mirrors the board calendar (=<= / =>=
/ =.=), plus a week ↔ month toggle.  The third leg of the family:
*board = now, revisit = evergreen, review = retrospect*.

This round DELIBERATELY does the thing R53's law forbade lightly: it
ADDS a data path — LOGBOOK state-change lines and CLOCK intervals are
new per-heading facts nothing today collects.  The design's job is to
prove the addition stays inside every R53 guarantee: it is harvested in
the SAME single work-buffer pass (no second file open, ever), it can
NEVER error a scan, it is BOUNDED at 5000+ files with years of
clocking, and the render stays data-pure — period navigation is a
filter+fold over cached integers, zero file I/O.

* Motivation

The requesting user wants a weekly / monthly report of what was
accomplished and where time went.  The absence of that report is the
stated reason clocking never became habitual — there is no payoff for
recording time.  Report first, clocking follows: the surface creates
the incentive loop, and it gets more accurate the more it is used.

Why in org-air and not stock Org: clocktable dynamic blocks are
per-file artifacts that need manual =:scope= wrangling and cannot roll
up by tag or directory across a tree; agenda log mode (=v l= +
clockreport) is day-oriented, noisy, and not a review surface.  org-air
already scans whole trees through org-ql with a persistent cache, and
Revisit set the precedent for a read-only sibling surface over the same
scan.  This is the natural third leg: board = now, revisit = evergreen,
review = retrospect.

Why not defer to an external reporting script: the value is in the loop
(review → notice a gap → clock more → better review), which only works
if the report lives one keystroke from the board.

** Goals

- Period-scoped view: ISO week or calendar month, navigable back /
  forward, defaulting to the current period.
- *Completed* section: items closed within the period, grouped by day
  (default) with a by-tag / by-directory regrouping toggle.
- *Time invested* section: CLOCK totals intersecting the period, rolled
  up by tag, by directory, and by origin file — "which part needs more
  time / work" at a glance.
- *Started* section: items created within the period.
- *Carried over* section: items with activity in the period (state
  change, clock, logbook note) still open at period end.
- Reuse the existing filter (=#tag= / free text) and scope machinery.
- Bookmark / activities / desktop-restore parity with the other
  surfaces.

** Non-Goals

- Editing or correcting clock data — org-clock owns that.
- A live clocking UI / currently-clocked indicator (possible future,
  separate doc).
- Export (org / CSV) in the first cut.
- Billing-grade accuracy — untracked time stays untracked; the report
  shows what was recorded, never estimates.

* R61-1 — the harvest: same pass, own body, never-error, capped

** Where and what

Inside =org-air-query--item-at-point=, after the existing probes (END
and =child-pos= in hand), the harvest scans the heading's OWN body —
=(heading-start . min(child-pos, END))= — with two anchored regexps:

#+begin_example
CLOCK line:  ^[ \t]*CLOCK:[ \t]*\[TS1\](?:--\[TS2\][ \t]*=>[ \t]*H:MM)?
State line:  ^[ \t]*- State "KW" … [TS]        (default org-log-note shape)
Note line:   ^[ \t]*- Note taken on [TS]
#+end_example

The OWN-body bound is CORRECTNESS, not economy: org-ql's action runs
once per heading, so a subtree-wide scan would credit every child's
clocks to the parent too and rollups would double-count.  Bounding to
the region above the first child (=child-pos=, already computed by the
R59 probe; for a leaf, the subtree END) attributes each line to
exactly the heading org-clock attached it to.  LOGBOOK drawers,
clock-into-drawer variants and loose (drawerless) clock lines all live
in that region, so no drawer parsing is needed — the line shapes are
the contract, exactly like every other probe in this function.

Per matched line: copy the match strings out FIRST (the
=org-parse-time-string= match-data clobber, verified above), then
parse to INTEGER epoch seconds via
=floor(float-time(encode-time(org-parse-time-string ts)))=.  Retained
shapes (all integers and interned symbols — no strings, no floats;
epochs are fixnums through year 2100+, measured):

- =clocks= — =(START . END)= pairs, CLOSED intervals with =END > START=
  only.  A running clock (no =--[TS2]=), an end-before-start pair, an
  unparseable stamp: that LINE is dropped, nothing else.
- =logs= — =(EPOCH . KIND)= with KIND ∈ =done= / =todo= / nil: =done=
  when the quoted keyword is in the buffer's live =org-done-keywords=
  (the file's own vocabulary under the R57-1 merged default — baked at
  scan time, coherent because the vocabulary is already a cache-key
  element), =todo= otherwise, nil for a plain =- Note taken on= stamp
  (activity signal only, never state inference).
- =created= — the =:CREATED:= property (=org-entry-get=, one
  properties-drawer read at the point org is already positioned),
  parsed to an integer epoch; nil when absent or unparseable.  The
  Started fallback ("earliest LOGBOOK entry") is derived at RENDER
  time from the retained stamps — never baked, so truncation can
  never fossilise a wrong creation date.

Both lists are sorted newest-first and truncated to =org-air-log-cap=
entries EACH (newest kept); hitting either cap sets =rtrunc=.

Known, accepted difference (documented in the docstring, R53 style): a
user-customised =org-log-note-headings= state template that no longer
matches the default =- State "KW" … [TS]= shape harvests nothing from
those lines — Completed then rides =CLOSED:= stamps (which
=org-log-done= writes regardless), Time is unaffected, and no error or
guess is ever produced.  Parsing arbitrary user templates is a
maintenance tax to adopt on demand.

** Never-error (the per-heading inner net)

The whole harvest body is wrapped in ONE =condition-case= per heading:
any signal (a pathological drawer, an =encode-time= edge, a regexp
stack overflow on adversarial input) degrades THAT heading to nil
review slots — the item is still built, the file still scans, the R53
P1b outer net (=--scan-file=) is not consumed, and nothing is echoed
(the scan paths already run under =inhibit-message=; the harvest
itself never messages).  Malformed individual lines don't even reach
the net: an unparseable stamp folds to nil and the line is skipped —
measured on a 100k-line buffer salted with a running clock, a
=CLOCK: [garbage= fragment and a =[not-a-date]= state stamp: 100 000
good lines harvested, 2 skipped, 1 never matched, zero signals.

** Cost (the single-pass budget)

Measured: 9.4 µs per log line (regexp match + two stamp parses).  A
heading with NO log lines costs two failing bounded regexp searches —
the same cost class as the four probes R53 already pays per heading.
The harvest is ALWAYS ON (not gated on the review surface having been
opened): the single-pass law demands it — a conditional harvest would
mean two cache populations and usage-dependent cache contents, exactly
the incoherence the R57 key discipline exists to prevent.  Users who
never clock pay the failing-search floor and four nil slots.  A
pathological 4 MB file of pure log lines (the =org-air-max-file-size=
ceiling, ~80k lines) adds ~0.8 s to ITS scan slice — paced background
work under R56, never a paint stall; and such a file pays this only
when its mtime changes.

=org-air-query--file-item= (R53 P3 headingless notes): nil review
slots — a file blob has no per-heading LOGBOOK; review sections ignore
='file= items entirely.

* R61-2 — cache v6: schema, key, and the bounding argument (the crux)

** Schema

Four new slots at the TAIL of =org-air-item= (v6): =clocks=, =logs=,
=created=, =rtrunc= as specified above.  On the struct, not in a side
table — RULED: per-heading facts belong on the per-heading record,
where they ride =--item-serialise= / =--cache-write= / =--cache-read=
/ the refresh machine's per-file item replacement FOR FREE.  The R54
file-meta table needed its own prune/persist/hydrate discipline
because its unit (the file) differed from the item store's; these
fields have the item's own unit, so a side table would duplicate the
merge/staleness machinery only to re-attach the data by identity
afterwards.  Item identity, mtime staleness, vanished-file pruning:
all inherited, nothing new to keep coherent.

=org-air-view--cache-version= 5 → 6.  A v5 cache is a version miss in
=--cache-read= ⇒ the documented one-time cold path (skeleton + R56
paced rescan, never a hang) — same as v3→v4→v5 before it.  The v6
docstring entry records that v5 records have the wrong record length.

=org-air-log-cap= (defcustom, org-air-query.el, beside
=org-air-max-file-size=; integer, default 5000) joins
=org-air-view--cache-key= as the SIXTH element: the cap shapes
scanned-and-persisted data, so a cap change must invalidate exactly
like a vocabulary change (R57: the key IS the detector; pre-R61
5-element keys also miss, on length).  The render-time knobs
(=org-air-review-suspect-clock-hours=, rollup basis, period) are
deliberately NOT key elements — they fold over cached data and take
effect on repaint.

** Bounded at 5000+ files with years of clocking

The shape is chosen for the arithmetic.  26.0 bytes/interval and
17.7 bytes/stamp serialised (measured); in memory two cons cells per
interval (32 B — epochs are immediate fixnums, symbols are interned
singletons, no strings anywhere).  Three regimes:

- /No clocking (most headings)/: four nil slots ≈ 16 B/item of cache
  text — ~250 KB at the R53 corpus's 15.9k items, read-time
  unmeasurable.  The feature is free for non-clockers.
- /Realistic heavy clocker/: 20 intervals/day × 5 years ≈ 36.5k
  intervals + a similar stamp volume ≈ 1.7 MB of cache text, 0.015 s
  of extra warm =read= (measured at 40k), ~2 MB RSS.  Warm paint
  stays firmly under the R53 <1 s bar (0.51 s measured baseline +
  hundredths).
- /Absurd ceiling/: 1M intervals = 26 MB cache text = 0.247 s extra
  warm read — still within the bar, and reaching it requires ≥55 MB
  of raw CLOCK text on disk (a corpus an order of magnitude past the
  design envelope, which R53 set as 5000 human-written files with
  =org-air-max-file-size= 4 MB).  Cache size is PROPORTIONAL to the
  log text the user actually wrote, at roughly HALF its on-disk
  byte cost — it can never invent volume.

The per-heading cap bounds the one case proportionality doesn't: a
runaway generated heading (a clocking bug, an auto-logger).  Default
5000 per list ≈ 13 years of daily clocking on a SINGLE heading (the
requesting user's habit files sit comfortably inside), worst-case
retention ~220 KB for that heading.  Truncation is never silent:
=rtrunc= renders an inline "⚠ history truncated" marker on affected
rows (T11), and period totals older than the retained window
under-report only on marked headings.

RULED OUT — a lookback WINDOW (drop data older than N days at scan
time), for three reasons.  (1) It breaks the mtime-cache law: the
window slides with the wall clock, so an UNCHANGED file's cached
fields go stale with no mtime change — correctness would need
time-based cache invalidation, a whole new staleness dimension.
(2) It amputates the surface: the user has YEARS of existing LOGBOOK
data and period navigation into it is day-one value; a window turns
old periods into silent zeros — a report that lies.  (3) The measured
arithmetic shows real corpora simply don't need it.  The cap is
content-relative (stable under time), visible when it bites, and
sufficient.

** No rescan on period navigation (+ R57/R59/R60 interaction)

Period kind/anchor and rollup basis are BUFFER-LOCALS of the review
buffer, applied at render as a filter+fold over the already-cached
integer lists.  =<= / =>= / =.= / the week↔month toggle repaint
without touching =org-air-query--scan-file= at all (T8's spy pins
this).  Interaction inheritance, all for free:

- R60: review's data flows from =org-air-query-files= (its cold fill
  literally calls it, and cache/board items were built from it), so
  exclusions apply and the R60-3 key guard keeps excluded rows from
  resurrecting.  An excluded tree's clocks do not exist for review.
- R59: pure containers are skipped in the per-ITEM sections
  (Completed / Started / Carried — =org-air-query-container-item-p=,
  slot-only, knob-gated).  Time invested deliberately folds EVERY
  heading's own-body clocks, containers included: time is attributed
  where it was clocked, and rollup rows are aggregates — no container
  ROW can appear by construction.  The R59 knob is already a key
  element; no new coupling.
- R57: the done-set is baked into log KINDs at scan time under the
  file's own vocabulary (merged default), and the vocabulary is
  already key element three — a vocabulary edit re-derives cold,
  exactly like the board.

* R61-3 — the period engine and the clock math

Pure functions in org-air-review.el, unit-testable without a buffer.

** Periods

=org-air-review--period-bounds (kind anchor)= → half-open integer pair
=[START, END)=: week = ISO Monday 00:00 local → next Monday 00:00;
month = 1st 00:00 → next month's 1st.  ISO math via the stock
=cal-iso= oracle (=calendar-iso-from-absolute= /
=calendar-iso-to-absolute= — verified: 2026-07-20 → W30/2026, Monday
2026-07-20; the year-edge cases in T14).  Boundaries are built with
=encode-time= on LOCAL calendar dates, so a DST-crossing period has
23/25-hour days and stays exact by construction — durations are pure
integer subtraction between two local-midnight epochs.

Navigation: =<= / =>= step one period (±7 days on the anchor, ±1
month); =.= returns to the current period; the week↔month toggle
(=m=) keeps the anchor DAY and shows the other kind's period
CONTAINING it (W30 → July; July → the week containing the anchor).
Anchor state: nil means "the current period", recomputed each render —
the default surface tracks today across midnight for free.

** Clipping and rollup (exactness laws)

An interval =[s, e)='s contribution to period =[P0, P1)= is
=max(0, min(e, P1) − max(s, P0))= — integer seconds.  A
boundary-crossing interval contributes complementary parts to adjacent
periods (measured: 90 min across a week edge → 60 + 30, sum exact);
nothing is dropped, nothing double-counted, and section sums are exact
integer arithmetic formatted as H:MM only at print time.

Rollup: ONE buffer-local basis — =day= (default) / =tag= / =directory=
/ =origin= — cycled by =f= and applied coherently: Completed groups
its rows by it; Time invested aggregates by it (for =day=, time by
day).  Attribution: directory = the file's parent directory name (the
item's =group= slot), origin = the file.  A multi-tag heading
contributes its full time to EACH of its tag rows — stated in the UI
contract: the tag rollup is a lens, and the section's headline total
comes from the item fold, never from summing rollup rows (T4 asserts
both numbers).

Suspect clocks: an interval longer than
=org-air-review-suspect-clock-hours= (defcustom, default 16, nil
disables) is EXCLUDED from every total and surfaced on its own line
under Time invested — "⚠ N suspect clock(s), H:MM excluded" — with the
owning headings listed.  Ruling: a forgotten 3-day clock swamping a
week's report is the common failure mode this surface exists to
repair; including it would make totals useless, hiding it would be a
lie, so it is loud and separate.  Render-time only: threshold changes
repaint, never rescan.  (True RUNNING clocks never got cached at all —
R61-1 skips open intervals.)

** Section predicates (the fold)

Over each non-container item (='file= items and R59 containers are
skipped in per-item sections):

- /Completed in P/: the =done= stamps in =logs= falling in P; if none
  AND =closed= ∈ P, the CLOSED stamp counts (fallback, not addition —
  the final done transition and CLOSED normally coincide, so stamps
  win to avoid double counting).  ONE row per item per period; N > 1
  done-stamps render a =×N= count chip (a daily habit reads
  "Habit ×7", not seven rows); day-grouping keys on the latest stamp
  in P.
- /Time in P/: the clipped, suspect-filtered clock sum > 0.
- /Started in P/: =created= ∈ P; fallback (draft-preserved): the
  EARLIEST retained log stamp ∈ P, taken only when =rtrunc= is nil — a
  truncated heading's oldest retained stamp is not its birth, so
  truncated headings never claim Started through the fallback.
- /Carried over in P/: activity in P — any log stamp (notes included)
  or any clock overlap — AND not-done at P's END.  Done-at-time-T
  inference, in order: the newest =done=/=todo= stamp ≤ T decides;
  else =closed= ≤ T ⇒ done; else, for the CURRENT period only, the
  live =donep=; else NOT done — the R59 house default (when in doubt,
  render): an unlogged, uncloseable item with activity shows as
  carried rather than silently vanishing.  An item completed after
  P's end correctly reads as carried in P; an item done and REOPENED
