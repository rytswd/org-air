* Decision 1 — SCOPE: which targets get frontmatter?

The rule, crisply:

#+begin_example
Synthesise frontmatter iff, at EXECUTE time:
  (1) org-air-refile-synthesize-frontmatter is non-nil,      AND
  (2) the target buffer has NO "#+title:" keyword
      (a brand-new file trivially satisfies this),           AND
  (3) the value is `always, OR the target file lies under an
      Air tree.
Otherwise the target is written exactly as today (bare).
#+end_example

- =org-air-refile-synthesize-frontmatter= — defcustom, =:group
  'org-air=, =:type '(choice (const :tag "In Air trees (default)" t)
  (const :tag "Every new/frontmatter-less target" always)
  (const :tag "Never" nil))=, default =t=.
- "Under an Air tree" — new cheap predicate
  =org-air-inbox--air-tree-p (file)=:
  =(locate-dominating-file file PRED)= where PRED is exactly
  =org-air-detect-air-project='s marker test (org-air-project.el:222:
  =air-config.toml= present OR an =air/= subdirectory) — inlined
  locally so org-air-inbox.el does not grow a hard requirement on
  org-air-project.el — ORed with membership under any configured root
  when org-air-project IS loaded: =(fboundp 'org-air-project-roots)=
  → =file-in-directory-p= against each root (covers an explicit
  =org-air-projects= entry whose root carries neither marker).
  Wrapped =ignore-errors=; nil on any failure (degrades to bare —
  today's behaviour, never an error).  Cost: O(path-depth)
  =file-exists-p= stats, ONCE per execute, never at prompt time —
  R53-lawful (no scan, no enumeration).

Why Air-gate by DEFAULT (the argument): =#+state:= and =#+FILETAGS:=
are *Air vocabulary* — the R53 context is a 5000-file Denote-style
notes silo where refile targets are ordinary org notes that are NOT
Air documents; silently stamping =#+state: draft= into a fresh plain
note would be org-air imposing its schema on files it does not manage
(the same posture R57 took for =org-todo-keywords=: supplement, never
replacement).  The reported bug is precisely the Air-workspace case —
airctl only ever classifies files under an Air tree, so the Unknown
symptom cannot even occur outside one.  =#+title:= alone is arguably
universal org hygiene, which is what ='always= is for — one setting,
user's explicit choice; splitting the block per-keyword (title
everywhere, state Air-only) was considered and rejected as a
harder-to-state rule with no reported need behind it.

The user's repro passes the gate: =Tasks/Coding/Infra/Syncthing.org=
sits inside the Air workspace, whose root carries =air-config.toml= —
the probe resolves the root from a file three directories down.

* Decision 2 — placement, idempotence, atomicity

** Where step 0 runs (the marker probe rules it)

Step 0 runs in the TARGET buffer *before* =--resolve-target= (:485),
i.e. the engine order becomes:

#+begin_example
0. ensure directory (R66-3) → find-file-noselect target →
   synthesise frontmatter when the rule fires   (buffer only, NO save)
1. --resolve-target  (may create OLP parents — unchanged)
2. cut               (source save — unchanged)
3. atomic-change-group: paste + metadata + save-buffer   (unchanged)
   unwind: restore source                                 (unchanged)
#+end_example

Why NOT inside the R64 =atomic-change-group= (the naive "same
atomicity" reading): the parent =(MARKER . LEVEL)= from
=--resolve-target= pre-dates the group, and the probe shows a marker
at position 1 does NOT advance past a =point-min= insertion — in a
new file whose OLP parents were just created at buffer top, a
frontmatter insert inside the group would leave the parent marker
pointing at the =#+title:= line, and the very next
=(goto-char (car parent)) (org-end-of-subtree)= would
=org-back-to-heading= into "before first headline" — a crash in the
exact scenario being fixed.  Synthesising FIRST dissolves the hazard
by construction and yields the correct file shape for free: OLP
parents created in step 1 land BELOW the frontmatter
(=org-refile-new-child= appends at end of buffer/subtree), so
("Infra") on a fresh file reads =#+title:= → =* Infra= → the item,
never headings above keywords.  Moving =--resolve-target= itself into
the group was also rejected: R64 deliberately resolves BEFORE the cut
so a bad target fails while the item is still untouched — step 0
inherits that same safety (it can only fail before anything moved).

** The atomicity contract, precisely (composing with R64)

The unit of atomicity is the ON-DISK file, and it is preserved
exactly: step 0 writes the BUFFER only; the target's disk state still
changes solely via the ONE =save-buffer= at the end of the successful
=atomic-change-group=.  On ANY failure (signal or quit, before or
during the transaction) the target is never saved — a brand-new
target therefore *never comes into existence on disk* (T7: no
half-written file, no title-less file, NO file at all), and an
existing frontmatter-less target's disk bytes are untouched.  The
source restore leg is unchanged (byte-identical restore, R64 fix2).

In-buffer residue on failure — unsaved frontmatter in a never-saved
buffer — is the SAME class as R64's unsaved OLP parents, and it is
retry-safe by design because idempotence is checked against the
*buffer*, not the disk:

- The check: a =#+title:= keyword anywhere before the first heading
  (the =org-air-project--read-keyword= regexp idiom, wide buffer) ⇒
  synthesis is a NO-OP, byte-for-byte.  A retry after a failed
  attempt finds the residue and writes nothing twice; a target that
  already had frontmatter is never touched at all (T2); running the
  refile N times into the same file yields exactly one block (T6).
- Insertion point: =point-min=, EXCEPT when the buffer's first
  element is a file-level =:PROPERTIES:= drawer (org requires it
  first; probed: =org-element-at-point= at bob reports
  ='property-drawer= with its =:end=) — then insert at that drawer's
  =:end=.  The block is followed by ONE blank line, matching
  =--ensure-file='s shape.

Same-file edge (target = source, source lacks =#+title:=): step 0
titles the buffer, and the cut's existing source =save-buffer=
persists it even if the paste later fails.  Accepted and documented:
that disk write happens today anyway (the cut), the residue is a
strictly-valid improvement (the file gains its own frontmatter), and
the restore leg still lands the item back byte-identically below it.

** The synthesised block (exact bytes for the repro)

#+begin_example
#+title: Set up syncthing
#+state: draft
#+FILETAGS: :#Nix:

* TODO [#A] Set up syncthing :#Nix:
#+end_example

- =#+title:= — Decision 3's derivation.  Lowercase key, matching
  =--ensure-file= and every Air doc in this repo (readers are
  case-insensitive either way).
- =#+state:= — the verbatim value of defcustom
  =org-air-refile-new-file-state=: =:type '(choice (const "draft")
  (const "ready") (const "work-in-progress") (const "complete")
  (const "dropped") (string :tag "Custom"))=, default ="draft"= — a
  freshly refiled item is un-triaged planning material; users who
  treat refile-out-of-inbox as commitment set ="ready"= (T4).
- =#+FILETAGS:= — colon-wrapped, order-preserving, exactly the shape
  =org-air-project--parse-tags= (:289) and airctl read.  Source set =
  the moved heading's EFFECTIVE tags: the TAGS argument when non-nil
  (=:none= ⇒ empty), else the item's own tags — i.e. what the
  transient preview shows — MINUS =inbox= (leaving the inbox is what
  refiling is; same rule as the R64 form pre-fill :remove at
  =--form-init=).  Empty set ⇒ the line is OMITTED entirely.  The
  heading's own tags are NOT touched by synthesis (the item stays
  self-describing if refiled again; org de-duplicates inherited +
  local tags on display).

Deliberately NOT synthesised: =#+created:= /​ =#+date:= —
=org-air-project--doc-created= (:317) already falls back to the
file's ctime, which for a brand-new file IS the creation moment;
adding a keyword would duplicate truth.  (Non-goal.)

* Decision 3 — deriving =#+title:= with org's own parsers

New helper =org-air-inbox--derive-title=, called *in the source
buffer with point on the item's heading, at cut time before
=delete-region=* — placement is the R57 point: the TODO strip must
use the SOURCE buffer's own merged vocabulary
(=org-todo-regexp=, set from the user's globals + the file's
=#+TODO:= line per R57-1), and the probe proves it (=WAIT= is
stripped exactly when the buffer declares it).  Step 0 runs before
the cut, so the engine derives the title while still resolving the
item (order: derive at the same =org-back-to-heading= the cut path
already performs — one extra read, zero extra file visits).

The recipe (probed, no hand-rolled heading regexp anywhere):

1. =(org-get-heading t t t t)= — org's own parser strips the TODO
   keyword (buffer vocabulary), the =[#A]= priority cookie, the
   trailing =:tag:= list and the =COMMENT= keyword in one call.
2. Statistics cookies via org-element, not a regexp:
   =org-element-parse-secondary-string= with
   =(org-element-restriction 'headline)= parses the remaining text;
   =org-element-map= collects the ='statistics-cookie= objects;
   =org-element-extract-element= removes each;
   =org-element-interpret-data= re-serialises.  Probed: =[1/3]=
   trailing and =[33%]= mid-title both vanish, and NON-cookie
   bracketed text (org link markup) survives verbatim — a title may
   legitimately carry a link; airctl reads the raw line; fine.
3. =substring-no-properties= + =string-clean-whitespace= (collapses
   the doubled space a removed inline cookie leaves).
4. Empty result (probed degenerate =* TODO [1/2]=) ⇒ fall back to
   =(file-name-base target-file)= — the same fallback
   =org-air-project--read-doc= uses for a title-less doc, so the
   board name and the file name agree.

* Non-goals

- No retro-fix pass over EXISTING frontmatter-less files (refile is
  the only writer this round; a bulk "adopt into Air" verb is its
  own design).
- No =#+created:= / =#+date:= synthesis (ctime already carries it
  for a new file); no file RENAME to match the derived title.
- No transient field for editing the synthesised title/state at
  refile time (the defcustoms are the knobs; a form field is future
  work if ever reported).
- No per-keyword scope splitting (title-everywhere/state-Air-only) —
  one crisp rule, three values.
- No rmdir-on-failure for the folded-in directory creation (inert
  residue, argued in Decision 4).
