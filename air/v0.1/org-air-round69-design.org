* Decision 4 — R69-4: fit-driven column reflow, one shared emitter

** The strategy (reflow; not shorten, not drop)

New primitive in org-air-view.el:

- =org-air-view--insert-verb-rows (cells width)= — CELLS is the flat
  ordered list of =(KEY . DESC)= conses (reading order).  It:
  1. Measures every cell: =cellw = string-width(KEY) + 1 +
     string-width(DESC)= (=string-width=, matching the R50-1 rule
     that layout follows the DERIVED key text — the board's cells
     come from =--legend-key=, so a leader/evil rebind changes the
     arithmetic automatically).
  2. Picks columns-per-row =n= — the LARGEST n in {3, 2, 1} such
     that every resulting row fits:
     =inset + Σ_{j=1..n} colw_j + gapw × (n−1) ≤ WIDTH=,
     where the grid is CELLS chunked in order into rows of n,
     =colw_j= is the widest cell in column j, and =gapw= is the
     existing tier rule (4 when =width ≥ 38=, else 1).  The LAST
     column still emits unpadded (=--verb-cell … 0=, as today) but
     its =colw= counts in the fit test — the fit is judged on the
     widest possible row.
  3. Emits the rows via the UNCHANGED =--verb-cell= + =--pad-to=.
- Floor: at n=1 a single derived cell wider than WIDTH still
  ellipsizes via =--pad-to= — the documented last resort (requires a
  pathological rebinding; with the fallback keys the widest cell is
  =g r refresh= = 11 cols, safe at every tier ≥ the 28-col narrow
  rail).

Worked defaults (fallback keys, inset 3, gap 1): no-scope 3-col rows
need 34 cols (=11+1+10+1+8= + inset) — so the 31–32-col mid tier
reflows to n=2 (3 rows, widest =3+10+1+11=25=), and the 28-col
narrow tier (inset 1) likewise; the 41-col wide tier keeps today's
2×3 layout byte-for-byte.  With a scope active 3-col needs 32 — the
screenshot's exact =s sou…= case lands at n=2.

Why reflow wins over the two alternatives the round listed:
shortening verb labels ("sou", "refr") re-introduces truncation by
another name and breaks the derived-cell arithmetic the moment a
rebind lengthens a key; dropping low-priority cells makes the legend
LIE by omission — R50-1's whole point is that the legend never lies
about reachability.  Rows are the one axis the rail has to spare,
and the foot arithmetic already measures the Actions block
(=--render-lines= in =--insert-rail-1=), so extra rows shrink the
inspector's reserved region exactly like any other foot growth
(R26-3: the clamped side-window rail lets it reach zero).

** The four call sites collapse

The board (=--insert-actions-default= :4117), project
(=org-air-project--insert-actions= :1417), review
(=org-air-review--insert-actions= :1092) and revisit
(=org-air-revisit--insert-actions= :512) emitters are byte-level
copies of the same 3-column loop (the three static tables even
recompute =cellw= with =length= instead of =string-width= — same
values on their all-ASCII cells).  Each becomes: header + =(org-air-
view--insert-verb-rows (flattened cells) width)=.  The board
flattens its two derived rows (capture, filter, source, refresh,
reset|expand, help); the static 3×3 tables flatten row-major.  When
fit(3) passes the output is byte-identical to today BY CONSTRUCTION
(same column maxima, same gap, same last-column rule) — the
consolidation carries zero golden shift at standard widths; reflow
engages only where today truncates.

** The primitive

- =org-air-view--tag-chip-label (tag)= → =(if (string-prefix-p "#"
  tag) tag (concat "#" tag))=.  Placed next to
  =--filter-token-label= (the two label primitives read together).
  Collapse ONLY the org-air-prepended prefix: a tag literally named
  =##x= renders =##x= (we never rewrite the user's tag text).
- Face hashing is untouched: =org-air-faces-tag-face= keeps hashing
  the RAW tag name (=#Nix= and =Nix= are different tags and may
  carry different accents — correct, they ARE different tags).
- svg-tag-mode rationale preserved: the tag's own text keeps its
  =#=; org-air merely stops adding a second one on its chrome.

** Companion: the matcher's tag branch (keeps deduped chips live)

=org-air-view--filter-token-match-p= (:2068) resolves a =#…= token
ONLY as =(substring token 1)= tag membership — so the token =#Nix=
(what chip-clicking a =#Nix= tag toggles via =org-air-filter-toggle=,
and what CRM completion over the raw tag vocabulary returns) can
never match an item actually tagged =#Nix= (probed: nil).  The tag
branch becomes: match when the STRIPPED name OR the VERBATIM token
is a member of the item's tags (both sides downcased, as today).
=#Nix= then matches items tagged =nix= or =#nix= — the union is the
only reading under which both the plain-tag world and ryota's
literal-# world stay one-keystroke filterable.  Bare-token
semantics, token storage (R24-6), and the AND/OR fold are untouched.
