* Summary

USER NEED: the rail INSPECTOR (D-P7) shows WHEN an item was created
("Created 2026-06-01 (14d ago)") but never when it was last TOUCHED —
the user wants a last-updated / last-activity line, sourced from the
LOGBOOK (a note or a state change), falling back to a retrievable
last-modified time when no logbook exists.

GOOD NEWS (verified in-tree): the R61 harvest ALREADY caches everything
needed on each =org-air-item= — no new harvest, no query.el change:

- =logs= — LOGBOOK stamps, newest-first =(EPOCH . KIND)=; the harvest
  regexp (=org-air-query--log-line-regexp=, org-air-query.el ~447)
  matches BOTH =- State "KW" … [TS]= AND =- Note taken on [TS]=, so the
  R71 =n=-field notes are already in (KIND nil = note; ='done= /
  ='todo= = a state change classified against the file's own vocabulary
  under the R57-1 merged default, at scan time).
- =clocks= — closed CLOCK intervals, newest-first =(START . END)=
  integer epochs.
- =created= — the =:CREATED:= property epoch.
- =rtrunc= — set when either list hit =org-air-log-cap=; crucially the
  cap keeps the NEWEST entries, so the list HEADS — the only thing this
  round reads — are cap-invariant.

Two work packages, ONE file (org-air-view.el; this is a DOC-ONLY round —
the sibling R73 round is editing view.el in parallel, see Decision 5):

- *R74-1 (the Updated line)* — a pure, slot-only helper
  =org-air-view--item-updated= returns the NEWEST epoch across
  =logs[0]=, the newest clock's END, and =created=, plus a SOURCE label
  derived from the winning candidate (='note= / ='done= / ='state= /
  ='clock= / ='created=).  Rendered as one KV line in
  =org-air-view--inspector-item-fields=, directly AFTER the Created
  line: ="Updated  2026-07-21  (2d ago · note)"= — same =%F= + relative
  shape as Created, same faded face, key fits the 8-column
  =org-air-inspector-key-w=.
- *R74-2 (the fallback)* — when ALL three slots are empty (no LOGBOOK,
  no closed clock, no =:CREATED:= — including items built outside the
  scan), ONE bounded =file-attributes= stat on the item's file supplies
  a last-modified time, rendered with an honesty marker: ="Updated
  2026-06-10  (5d ago · ~file)"= — the =~= says file-level, not
  heading-precise.  Always-on (no knob), FUTURE-CLAMPED (an mtime after
  the render clock renders nothing — Decision 3, which is also exactly
  what keeps every frozen-clock golden byte-clean), and never a stat
  storm: the stat fires only for a slotless item, once per debounced
  inspector render, never in the classify/paint loop (R53).

Zero new defcustoms, zero schema/cache changes, query.el byte-untouched.

* Decision 1 — the value: MAX over the cached R61 slot heads, slot-only

=org-air-view--item-updated (item)= → =(EPOCH . SOURCE)= or nil.  Pure
and I/O-free — three slot reads, no file access, no marker hydration:

- candidate A: =(car (org-air-item-logs item))= → its EPOCH; SOURCE
  from its KIND — nil → ='note=, ='done= → ='done=, ='todo= →
  ='state=.  (The keyword STRING is deliberately not cached by R61 —
  only the done/not-done class — so the label names the CLASS, never a
  guessed keyword.)
- candidate B: the newest clock's END — =(cdr (car (org-air-item-clocks
  item)))=; SOURCE ='clock=.  The head's END, O(1), NOT a fold over the
  list: clocks are newest-first by START, and for well-formed sequential
  clocking newest-START is newest-END (an older-started interval that
  ends later means OVERLAPPING clocks — the pathology Org itself makes
  the user resolve via =org-resolve-clocks=; at the line's day
  granularity the difference is invisible anyway).  O(1) keeps the
  helper slot-access-shaped like every other inspector field.
- candidate C: =(org-air-item-created item)=; SOURCE ='created= — the
  floor: an item never touched since capture was last "updated" when it
  was created.

The winner is the strict MAX; ties resolve A ≻ B ≻ C (fold in that
order, replace only on strictly-greater — a note stamped the same
second as a clock-out gets the more descriptive label).  All three nil
→ nil (the Decision 3 fallback takes over at render).

/Rejected — reusing =org-air-classify--last-activity=/: its chain is
closed ‖ scheduled ‖ deadline ‖ subtree-ts ‖ mtime — scheduled and
deadline are commonly FUTURE dates, so it answers "when is/was this
RELEVANT", not "when was this last TOUCHED"; an "Updated: in 30d" line
is nonsense.  The classify slot and the stale bucket are byte-untouched
(Compatibility).

/Rejected — folding =closed= in as a fourth candidate/: the inspector
already renders Closed as its own line, and under =org-log-done= a
completion normally ALSO writes the =- State "DONE"= drawer stamp the
harvest catches — folding closed in would double-render one fact.  A
done item whose file logs no drawer states still shows its Closed line;
Updated then reports the honest drawer/created answer (Non-goals).

/The rtrunc lemma/: =org-air-log-cap= truncation keeps the NEWEST
entries (org-air-query.el, =seq-take= after the newest-first sort), so
a truncated item's heads are EXACTLY the untruncated heads — the
Updated line is cap-invariant and needs NO =⚠=/=~= marker on rtrunc
items (pinned r74-7).  The R61 precedent even blesses the direction:
"the Started fallback (earliest LOGBOOK stamp) is derived at RENDER
time from the retained stamps — never baked"; Updated is the same
derive-at-render shape at the other end of the list.

* Decision 2 — the line: key "Updated", Created's byte-shape, placed after Created

In =org-air-view--inspector-item-fields= (org-air-view.el ~4625), inside
the existing dates =delq nil (list …)= block, a new entry directly
AFTER the Created =when-let*= entry and BEFORE the Closed line — the
rendered order becomes Sched / Deadln / Created / *Updated* / Closed
(the line renders whether or not Created did — the fallback case is
precisely a Created-less item):

- key ="Updated"= (7 chars — fits =org-air-inspector-key-w= 8, same
  register as Created/Closed; rejected "Last activity": it does not fit
  the fixed key column and breaks the one-word key register);
- value =(concat (%F of EPOCH) "  " "(REL · LABEL)")=, whole value in
  =org-air-face-faded= — byte-parallel to the Created line's value
  shape, REL from the existing =org-air-view--inspector-relative=
  against the fields function's NOW (the frozen render clock), so
  "today" / "Nd ago" phrasing is shared, not re-derived;
- LABEL: ='note= → ="note"=, ='done= → ="done"=, ='state= → ="state"=,
  ='clock= → ="clock"=, ='created= → ="created"=, fallback →
  ="~file"=.  The =" · "= separator is already on the inspector surface
  (the bucket line's name join) — no new glyph vocabulary.
- Date-only =%F=, like Created: the stamps carry time-of-day but the
  inspector's date register is day-granular; the relative term carries
  the useful precision.

A forged FUTURE logbook stamp (hand-written) renders honestly as
="(in Nd · note)"= — the slot path trusts the drawer and is NOT
clamped; only the machine-derived mtime fallback gets the Decision 3
clamp (a machine signal with a machine failure mode).

* Decision 3 — the fallback: one bounded live stat, marked "~file", future-clamped

When =org-air-view--item-updated= returns nil, the line helper performs
ONE =file-attributes= call on =(org-air-item-file item)= and uses its
modification time.  Rulings, each firm:

- /Always-on, no knob/.  Zero new defcustoms (the R72/R73 discipline).
  The cost ceiling is one stat per debounced inspector render
  (=org-air-inspector-debounce= 0.1s), only for an item with EMPTY
  R61 slots, only while inspected — strictly cheaper than the
  already-sanctioned D-P7 Created hydration in the SAME fields pass
  (=org-air-view--item-created= does =find-file-noselect=).  An opt-in
  knob would buy nothing but a dead branch.
- /A LIVE stat, not the scan-time mtime alist/.  Rejected
  =org-air-view--items-mtimes=: it is buffer-local to the BOARD buffer,
  unreachable when the fields function runs for the popped-out rail
  host (R15 D-P2), and absent entirely for items built outside the scan
  — exactly the items most likely to need the fallback.  Rejected a new
  mtime item slot: a cache v7 bump + schema migration to serve a
  fallback that real headings (any LOGBOOK, any =:CREATED:=) never hit.
  The live stat is buffer-independent, always current, and its
  file-level imprecision is exactly what the marker admits.
- /The honesty marker/: the label is ="~file"= — file-level, not
  heading-precise (ANY save of the file moves it).  For a =kind 'file=
  item (the R53 P3 headingless note) the mtime is actually
  item-precise, but the marker stays — one rendering rule, no
  special case (pinned r74-10).
- /The FUTURE-CLAMP/: when the mtime is AFTER the render clock NOW, the
  line is OMITTED entirely.  A file cannot have been modified after
  "now"; an apparent future mtime means the signal is untrustworthy
  (clock skew, NFS drift, a restored backup — or a frozen test clock),
  and "Updated (in 3d · ~file)" would be nonsense.  The corollary is
  what keeps the goldens deterministic: the ONLY inspector-bearing
  mockups (=layout-mockup-*x50.txt=) inspect "Quick note about org-air
  idea" — no LOGBOOK, no clocks, no =:CREATED:= (tests/fixtures/
  inbox.org), so the fallback WOULD fire; but the mockup clock is
  frozen at Mon 2026-06-15 (=org-air-test-now=) while the fixture
  file's mtime at regen is the real wall clock — permanently AFTER the
  frozen NOW — so the clamp suppresses the line and every golden stays
  byte-clean, forever, by construction (pinned r74-6; Goldens below).
- /Never-error/: file nil, missing, or unreadable → nil → no line, no
  signal (the R53 degrade register).

* Decision 4 — the no-rescan / no-storm law (R53)

- The pure helper does ZERO I/O — pinned with spies (r74-8): no
  =org-air-query--scan-file=, no =find-file-noselect=, no
  =file-attributes= for any slot-answered item.
- The fallback stat is reachable ONLY from the inspector line renderer
  — never from classify, never from the board paint loop, never per-row.
  One item, one stat, user-driven and debounced: the same boundedness
  argument D-P7 already carries for the Created hydration, at lower
  cost.
- No rescan is ever triggered: the slots are the R61 cache, hydrated
  boards render them directly (R53 P2's data-pure law), and this round
  adds no scan-time work at all — org-air-query.el is byte-untouched
  (the prompt's "no new harvest" holds by construction).
