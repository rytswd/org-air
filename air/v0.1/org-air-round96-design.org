* Context

R95's test seat found, and the supervisor confirmed, a *compilation-masked*
defect: =org-air-query.el:223= declares

#+begin_src emacs-lisp
(cl-defstruct (org-air-item (:constructor org-air-item-create) (:copier nil))
  title tags file marker todo priority scheduled deadline group closed …)
#+end_src

so =org-air-item-deadline= is a *struct accessor*.  =org-air-view.el:13956=
then defined

#+begin_src emacs-lisp
;;;###autoload
(defun org-air-item-deadline (&optional date)   ; interactive command, key `d'
  (interactive) …)
#+end_src

Same symbol.  One function cell.  The COMMAND won it:
=(commandp 'org-air-item-deadline)= was =t=.

Why neither gate mode saw it: =cl-defstruct= installs a *compiler macro*
for every accessor, and a compiler macro fires during macroexpansion —
which happens in the interpreter too.  Every static call site
=(org-air-item-deadline item)= in the tree was therefore rewritten to an
=aref= before the function cell was ever consulted.  1342 tests passed
COMPILED and INTERPRETED on top of a symbol whose function cell held the
wrong thing.

Measured on the pre-fix tree (=main=, R95):

| reach                                    | pre-fix result                     |
|------------------------------------------+------------------------------------|
| =(org-air-item-deadline it)= static call | =1234.0= — the slot (inlined)      |
| =(funcall 'org-air-item-deadline it)=    | =user-error "No org-air item at point"= |
| =(mapcar #'org-air-item-deadline (list it))= | same =user-error=              |
| =(eval '(org-air-item-deadline it) env)= | same =user-error=                  |
| =(commandp 'org-air-item-deadline)=      | =t=                                |

A landmine, not yet a live bug: no current call site reaches the function
cell.  The next one written naturally would have.  R67 Decision 4
documented the hazard and deferred it; R68 renamed the *other* instance
(=org-air-item-todo= → =org-air-item-cycle-todo=) for exactly this reason
and left this one.  This is the second compilation-masked defect in two
rounds, so the RULE matters more than the fix.

* Decision 1 — the fix: rename the COMMAND, never the slot

The slot/accessor is load-bearing across the cache format (=org-air-item=
is serialised into the v7 cache; the accessor name appears at 20 call
sites in classify/calendar/view/query/inbox).  So the command moves.

*=org-air-item-deadline= (command) → =org-air-item-set-deadline=.*

Rationale for the shape: it keeps the =org-air-item-= prefix, so =M-x
org-air-item-= completion still lists it next to =org-air-item-schedule=,
and it inserts a verb the same way R68's =org-air-item-cycle-todo= did.

Preserved *exactly*:

- the =d= key on =org-air-view-mode-map= (=org-air-view.el:1766=);
- the =?= help entry — =("Triage" … (org-air-item-set-deadline . "set
  deadline"))= — same group, same position, same description string;
- the guided inbox walk's =[d]eadline= prompt and its
  =(?d (call-interactively #'org-air-item-set-deadline))= arm;
- the =;;;###autoload= cookie, the arglist =(&optional date)=, the
  =org-air-view--single-mutation-guard= call and the whole body.

*No =defalias=.*  Deliberate, and the reason is the whole point of the
round: a =(defalias 'org-air-item-deadline #'org-air-item-set-deadline)=
would re-take the same function cell and restore the bug *verbatim* —
=funcall=-reaching the accessor would then land in the command again.
Probe (a) in Decision 3 proves the new lint rule catches exactly that
attempt.  The old symbol is now, and can only be, the accessor.

* Decision 3 — the lint rule that makes the class impossible

Added to =tests/org-air-lint.el= (lint infrastructure, not ERT; no
=tests/*-test.el= was touched this round):
=org-air-lint--collect-duplicate-definitions=, a *package-wide* pass that
runs once over all 11 files after the per-file checkdoc / package-lint
passes, and feeds the same baseline machinery — so a new =dupdef= finding
FAILS the binary gate exactly like a new checkdoc finding.

What it does:

1. Reads every top-level form of every =org-air*.el= and *recurses into
   bodies* (=eval-and-compile=, =when=, =progn=, a sharp-quoted lambda),
   stopping at =quote= / backquote so quoted DATA that merely looks like a
   definition is never counted.
2. Records =(SYMBOL NAMESPACE KIND FILE LINE)= for:
   - *function* namespace: =defun=, =defmacro=, =defsubst=, =cl-defun=,
     =cl-defmacro=, =cl-defgeneric=, =define-inline=, =define-minor-mode=,
     =define-derived-mode=, =define-globalized-minor-mode=, quoted
     =defalias=, and — the point of the round — everything a
     =cl-defstruct= generates: accessors (=:conc-name= honoured, =nil=
     conc-name handled), predicate, copier, every constructor (a named
     =:constructor= suppresses the default =make-NAME=; an explicit =nil=
     option means "not generated" and is skipped).
   - *variable* namespace: =defvar= *with a value*, =defvar-local=,
     =defconst=, =defcustom=.
3. Fails on any =(SYMBOL . NAMESPACE)= with more than one record, naming
   every site, and calls out by name the case where one of them is a
   struct accessor — because that is the invisible one.

Deliberate exclusions, each load-bearing:

- =cl-defmethod= is *not* counted: many methods per generic is the point.
- The two namespaces are separate: a =defvar= and a =defun= of the same
  name is legal Elisp and the package uses it once
  (=org-air-query--work-buffer=).
- Bare =(defvar SYM)= is a declaration, not a definition — the package
  has dozens and they are correct.

* Decision 4 — the sibling class: where does correctness rest on inlining?

Question asked: is there anywhere else the package needs a compiler macro
to fire for *correctness* rather than speed — i.e. would =funcall=-reaching
an inlined helper misbehave?

*Answer: nowhere, now.*  Audited:

- =grep -n "defsubst\|define-inline\|define-compiler-macro" org-air*.el=
  → *zero hits*.  The package defines no inline functions and no hand-written
  compiler macros of its own.
- The ONLY compiler macros in play are the 32 generated by =cl-defstruct=.
  Before R96 exactly one of them (=org-air-item-deadline=) was
  correctness-critical: the inlining was the only thing keeping the tree
  right.  After R96, all 39 generated struct functions agree with their
  function cells (audit above), so inlining is now purely a *speed*
  optimisation everywhere — dropping it would cost cycles, not answers.
- =setf= on struct slots (=(setf (org-air-item-x it) v)=) goes through
  =gv=, not the function cell, and was never exposed either way.
- One SOURCE COMMENT encoded the old constraint and is now stale:
  =org-air-inbox.el:1324= told future readers "a STATIC accessor call —
  safe: cl-defstruct's compiler macro inlines … so the view.el COMMAND of
  the same name is never consulted.  *Keep it static.*"  That instruction
  was load-bearing under the collision and is misleading without it.
  Rewritten to record the history and say plainly that the call is static
  for speed now, not for correctness.  (No code change at that site.)
- One TEST encodes the same stale constraint —
  =org-air-r68-14=, which calls the command through =(funcall
  (symbol-function 'org-air-item-deadline) …)= precisely *because* of the
  collision, and says so in its own docstring.  See the re-bless shapes.
