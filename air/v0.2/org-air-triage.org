#+title: org-air — inbox triage flow
#+state: complete
#+FILETAGS: :ui:ux:inbox:triage:

* Summary
The user wants "more clear patterns to move items out of inbox."  This
spec defines two complementary patterns:
1. *Inline per-item triage* — single-key dispositions on any item row
   (and especially Inbox rows) without leaving the dashboard.
2. *Process-inbox mode* — a guided, mu4e/dired-style loop that walks the
   Inbox one item at a time with single-key dispositions and a live
   count-down to *Inbox zero*.

Both share one disposition vocabulary and one rule: *a disposition that
adds a plan or a home graduates the item out of Inbox*, so every action
visibly shrinks the inbox.

* Bucket membership ruling (screenshot 3)
*Symptom:* a user scheduled inbox notes for 16/17 Jun; the calendar
dutifully dots them, but *Upcoming 0 / "Nothing scheduled in the next 7
days"* — because S4's dedup hid inbox-dwellers from *every* non-inbox
bucket.  The calendar and the sections disagree.

*RULING — real-signal membership.*  An inbox item participates in *every
bucket it genuinely qualifies for*: scheduled within the window →
*Upcoming*; overdue → *Needs attention*; =[#A]= → *High priority*; and it
*also remains in Inbox until it is filed*.  So a scheduled inbox note
appears in *both* Inbox and Upcoming, and the calendar, Upcoming and
Inbox tell *one* story (the calendar dot now has a matching Upcoming
row).  Real schedule/deadline/priority is signal — honour it everywhere;
the summary =total= stays the *unique* count, so overlapping badges are
expected and honest.

*S4 narrowing (impl: =org-air-classify=).*  S4's dedup must suppress
*only* the *no-date DEFAULT* attention classification for inbox-dwellers
(the original bug: schedule-less inbox notes spuriously "needs
attention").  It must NOT suppress real scheduled / deadline / priority
membership.  Concretely: an inbox-dweller is excluded from the *no-date
attention fallback* but included wherever it carries a real timestamp or
priority.

*Graduation = FILING only.*  An item leaves Inbox only when it is given
a *home or removed* — refiled, filed-under-group, archived, marked DONE,
or deleted.  Scheduling, deadline, tagging and TODO-promotion are
*refinements*: they add signal (and bucket membership) but the item
stays in Inbox because it is still an *unfiled capture*.  The
process-inbox count-down therefore decrements on *filing* dispositions,
not on scheduling.

*Inbox affordance (the triage nudge).*  A dated-but-unfiled inbox row
carries a quiet trailing hint — e.g. =scheduled · file with r= in
=org-air-face-faded= — and the Inbox heading may note =N scheduled, still
unfiled=.  This keeps the "give it a home" nudge *inside Inbox* (where
the work is) instead of as an apologetic Upcoming empty-state, and ties
directly into the dispositions below.

* Pattern 1 — inline per-item triage (dashboard)
Keys active on the item at point; read-only buffer, so single letters
are free.  Additions to the v0.1 map (existing: =r= refile, =t= tag,
=d= schedule, =m= mark):
| Key | Command                  | Action                                   | Files out of Inbox?              |
|-----+--------------------------+------------------------------------------+----------------------------------|
| =s=   | =org-air-item-schedule=    | set =SCHEDULED= (quick-date sub-prompt)    | no — adds to Upcoming, stays      |
| =d=   | =org-air-item-deadline=    | set =DEADLINE= (quick-date sub-prompt)     | no — adds to Upcoming/attn, stays |
| =r=   | =org-air-refile-item=      | refile subtree to file/heading           | yes                              |
| =f=   | =org-air-item-file-group=  | fast refile under a category/group (=@…=)  | yes                              |
| =t=   | =org-air-set-tag=          | add/remove tags (=#…=)                      | no — refine, stays                |
| =T=   | =org-air-item-todo=        | cycle/promote TODO state                 | no — refine, stays                |
| =a=   | =org-air-item-archive=     | =org-archive-subtree= (to archive file)    | yes (out)  |
| =D=   | =org-air-item-done=        | mark DONE (optionally archive)           | yes (out)  |
| =k=   | =org-air-item-kill=        | delete the subtree (confirm)             | yes (out)  |
*Note the remap:* =s= becomes item-schedule (was =scope=); move =scope= to
=S= and =scope-clear= to =M-s= so the high-frequency triage verb gets the
short key.  (Flag for impl + the keybindings doc; non-breaking for evil
via the overriding map.)

*Quick-date sub-prompt* (shared by =s= / =d= and process mode), a single
keypress:
| Key | Meaning              |
|-----+----------------------|
| =t=   | today                |
| =m=   | tomorrow             |
| =w=   | next Monday (week)   |
| =e=   | this weekend (Sat)   |
| =+=   | +1 day (repeatable)  |
| =.=   | pick a date (=org-read-date=) |
| =0=   | clear the date       |
Echo after: =Scheduled "Call the plumber" → Tue 17 Jun.=

* Pattern 2 — process-inbox mode (guided)
=org-air-process-inbox= (bind =I= on the dashboard, and a global
autoload).  A focused loop over the current Inbox items:

** Behaviour
- Enter: point lands on the *first* Inbox item; the rest of the
  dashboard dims (=org-air-face-faded= overlay) so focus is on the item;
  a transient one-line *disposition bar* shows in the echo area / a
  header-line:
  : Inbox 5 ┆ [s]chedule [d]eadline [r]efile [f]ile [t]ag [a]rchive [D]one [k]ill ┆ [SPC]skip [q]uit
- Each disposition acts on the *current* item, echoes a one-line result,
  and *auto-advances* to the next Inbox item.
- The counter decrements on every *graduating* disposition; the bar
  updates: =Inbox 4 ┆ …=.
- When the Inbox reaches zero: clear the loop, restore the dashboard,
  and echo =Inbox zero — nice work.= with a brief popout flash on the
  Inbox count.
- =SPC= / =n= skip (leave in inbox, advance); =p= back; =g= refresh the
  item set; =q= / =RET= exit the loop at any time (partial progress kept).

** Keys (transient map, single key, no modifier)
The *Files out?* column drives the count-down: only filing dispositions
decrement the Inbox counter (per the membership ruling above).
Schedule/deadline/tag are refinements — they add real bucket membership
(Upcoming, attention, …) but the item stays in Inbox until filed.
| Key   | Disposition                                  | Files out? / advances |
|-------+----------------------------------------------+-----------------------|
| =s=     | schedule (quick-date sub-prompt)             | no — refine; advance   |
| =d=     | deadline (quick-date sub-prompt)             | no — refine; advance   |
| =r=     | refile to file/heading (=completing-read=)     | yes — decrement        |
| =f=     | file under category/group (=@…= fast path)     | yes — decrement        |
| =t=     | add tags (refine)                            | no — stay on item      |
| =T=     | promote/cycle TODO state (refine)            | no — stay on item      |
| =a=     | archive subtree                              | yes — decrement        |
| =D=     | mark DONE                                    | yes — decrement        |
| =k=     | delete subtree (confirm =y=)                   | yes — decrement        |
| =SPC=/=n= | skip to next (leave in inbox)                | —                     |
| =p=     | previous item                                | —                     |
| =u=     | undo last disposition (=org-air--triage-undo=) | —                     |
| =g=     | re-query inbox                               | —                     |
| =q=/=RET= | quit process mode                            | —                     |
A pragmatic flow: =s= to schedule (it now shows in Upcoming + calendar),
then =r= to file it — the =r= is what empties it from Inbox.

** Echo feedback (examples)
- =Scheduled "Idea: weekly review automation" → Mon 16 Jun.  Now in
  Upcoming; still in inbox — file with r.=   (refinement, no decrement)
- =Refiled "Read the Rougier paper" → learning.org.  Inbox 3 left.=
- =Archived "Cancel the SaaS subscription".  Inbox 2 left.=
- =Tagged "Follow up with Sam" #work #client.  (still in inbox)=
- =Inbox zero — nice work.=
Note how scheduling does NOT drop the count (it is a refinement that adds
the item to Upcoming + the calendar) — only filing does.  This is what
keeps the calendar, Upcoming and Inbox in agreement (screenshot 3).

** State preservation
The loop preserves filters/scope and, on quit, returns point to the
dashboard's first remaining Inbox item (or the Inbox heading when
empty).  Each disposition is a normal Org edit on the source file, so
=u= (undo) and the auto-refresh hook (U3) keep the dashboard consistent.

* Faces / visual
- No new faces required.  The disposition bar uses
  =org-air-face-faded= for the legend and =org-air-face-salient= for the
  active key letters in brackets.
- The dimming overlay reuses =org-air-face-faded=; the focused item keeps
  the normal palette so it stands out.
- Count-down uses the existing =org-air-face-count-attention= (popout)
  flash on decrement (reuse =org-air-flash-on-refresh=).

* Test plan
- Each inline disposition mutates the source file correctly and the
  dashboard reflects it on the next (auto) refresh.
- Real-signal membership: a *scheduled* inbox item appears in *both*
  Inbox and Upcoming and dots the calendar (Upcoming != 0 — the
  screenshot-3 contradiction is gone); a no-date inbox TODO is NOT in
  Needs attention (S4 narrowing holds); an =[#A]= inbox item shows in High
  priority.  The summary =total= equals the *unique* item count even when
  badges overlap.
- Filing graduates: only refile / file-under-group / archive / done /
  delete remove an item from Inbox and drop the Inbox count; scheduling,
  deadline and tagging do NOT.
- Process-inbox walks N items, single keys advance, the counter drops on
  *filing* dispositions, reaches zero, and the loop exits cleanly with
  the "Inbox zero" message.
- =u= undoes the last disposition and restores the count.
- Runs headless via the fixture inbox with a frozen clock.
