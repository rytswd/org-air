#+title: View-pane snapshot: bound the drawer :END: search + element-check the block-literal shape
#+state: ready
#+FILETAGS: :viewpane:bug:

* Summary

The R65 snapshot renderer's property-drawer fold walk searches for
=^[ \t]*:END:[ \t]*$= without a bound: an unterminated parent drawer (or a
literal =:PROPERTIES:= line inside a =#+begin_example= block — the review's
P5b probe) makes the fold cross a heading, display-hiding the parent body AND
the child heading.  Display-only, bytes sacred, never signals — ruled a
non-blocker in the R65 review — but the fix is small and named.

* Proposal

Two steps, per the R65 review's recommendation (=REPORT-r65.md= §3):

1. Bound the inner =:END:= search at the next heading:
   =(re-search-forward "^[ \t]*:END:[ \t]*$" (save-excursion
   (outline-next-heading) (point)) t)= — kills the heading-crossing case.
2. The fully correct version additionally checks the match is a real
   =property-drawer= / =drawer= element via =org-element-at-point= — also
   fixes the P5b block-literal shape.

Scope: the snapshot path only (=org-air-view--render-snapshot= walk,
org-air-view.el ~6782).  The default interactive pane goes through
=org-fold-hide-drawer-all= (org-parser-driven, immune).
