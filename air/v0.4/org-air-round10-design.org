* D-P1 [CRIT] — svg pill rework (fix clipping WITHOUT breaking alignment)
*Root cause (confirmed in =org-air-view--svg-pillify=, ~L709):* the pill
box is locked to =Ncols × char-width= (correct C2 alignment contract) but
the label is drawn at =:font-size (max 8 (- ch 4))= — a size whose glyph
run is *wider than the box* — so it spills past the rounded edge and the
last glyph clips.  Radius =ch/3= = a stadium (too round); =:fill= per chip
+ the 6-hue accent = a rainbow; there is *no internal padding*.

The fix has three independent parts: (A) reserve padding columns so the
label has horizontal breathing room inside the box; (B) *fit* the
font-size to the box so the glyph run can never exceed it; (C) calm the
look (radius, fill, border).

** D-P1.PAD [byte] — reserve padding columns in the underlying string
This is svg-tag-mode's technique and the new authoritative addition to
C2.  The pill label string carries =org-air-pill-pad-cols= reserved
*space columns on each side* in the *text layer*:

: chip text  =  (pad)#inbox(pad)         ; pad = org-air-pill-pad-cols spaces

- defcustom =org-air-pill-pad-cols= — integer, *default 1* (one reserved
  column L and R; the label sits in the middle =label-cols= columns).
- Because =org-air-view--compute-meta-widths= sizes columns from
  =string-width=, the reserved pad is counted automatically → the box is
  =reserved-Ncols × char-width= where =reserved-Ncols = pad + label + pad=.
  *V6 alignment therefore still holds* — geometry is still 100% text-layer
  driven; the pill is still a pure overlay.
- The reserved pad is *part of the pill box* (the rounded rect spans the
  full reserved-Ncols cells); the label is drawn centred so the pad cols
  become genuine internal margin — the label never reaches the rounded
  edge.  This is the structural fix to "no internal padding".
- Inter-pill gap is the *existing single unpilled space* between chips in
  the tag string (=#work␣#report=) — unchanged from round-9 D1.  Net TTY
  gap between two pills = pad + 1 + pad = 3 cells; acceptable and even.
- =[byte]=: pad cols change the tag/date *bytes* and the meta-column
  widths → a fixture regen for every fixture carrying a tag or date pill.
  *I bless these in a follow-up message with the exact change-id.*  TTY
  shows =␣#inbox␣= (the pad spaces are harmless, give the same breathing
  gap, and keep alignment identical with pills on or off).

** D-P1.FIT [gui] — font-size fits the box (clipping is now impossible)
Rewrite the built-in pill branch of =org-air-view--svg-pillify= so the
label can *never* exceed its drawable area:

- =cw= = =(frame-char-width)=, =ch= = =(frame-char-height)=.
- =ncols= = =(string-width text)= (includes the reserved pad).
- =box-w= = =(* ncols cw)=  (the C2 box — unchanged formula).
- =inner-w= = =(* (- ncols (* 2 org-air-pill-pad-cols)) cw)= — the width
  the label is allowed to occupy (box minus the reserved pad columns).
- =desired-fs= = =(max 7 (round (* ch org-air-pill-font-scale)))= where
  defcustom =org-air-pill-font-scale= = *0.66* (was effectively =(- ch 4)=
  ≈ 0.75–0.8 at common metrics, which over-ran the box).
- *Width fit (the actual clip fix):* measure the label's natural pixel
  width at =desired-fs=.  Prefer =(string-pixel-width (string-trim text))=
  inside a temp buffer whose default face = the frame default scaled to
  =desired-fs=; fall back to =(* (string-width (string-trim text))
  cw)= when =string-pixel-width= is unavailable (Emacs < 29).  If
  =natural-w > inner-w=, scale down:
  : font-size = (max 7 (floor (* desired-fs (/ inner-w (float natural-w)))))
  else =font-size = desired-fs=.  The label is now guaranteed ≤ =inner-w=,
  so *no glyph can reach the rounded edge → no clip, at any tag length or
  text-scale*.  Recompute on the C2 triggers (font / text-scale / width).
- Draw the label =:text-anchor "middle" :x (/ box-w 2.0)=, vertically
  centred on the cap height: =:y (round (* ch 0.72))= (tune so the glyph
  optical-centres on the line; this replaces the ad-hoc =(- ch (max 3 (/
  ch 4)))=).  Image =:ascent 'center=; pill height ≤ line height so line
  spacing is untouched.
- *Drop the =svg-tag-make= branch.*  Round-9 D3 already preferred our own
  =svg.el= pill; =svg-tag-make='s auto-sizing is exactly what we cannot
  control (it ignores our box), so the controlled built-in pill is the
  only path.  =org-air-tag-style= / =org-air-date-style= stay ='pill |
  'text; =svg-tag-mode= soft-dep is *removed* from the contract.

** D-P1.LOOK [gui + face] — gentler radius, calm colour, ONE accent
- *Radius:* defcustom =org-air-pill-radius= default =(/ ch 6.0)= (soft
  rounded, *not* a stadium).  =:rx :ry= = that value.
- *Fill → monochrome:* defcustom =org-air-pill-fill-alpha= default *0*
  (no per-chip fill).  The board stops being a rainbow of filled chips.
- *Border = ONE restrained muted neutral* (not the per-tag hue): defcustom
  =org-air-pill-border= — a colour string or =nil= to derive from
  =org-air-face-faded= foreground (a muted grey, e.g. light =#BDBDBD= /
  dark =#4C566A=).  =:stroke= that, =:stroke-width 1=, =:fill "none"=.
- *Colour lives in the LABEL only:* the tag label keeps its deterministic
  accent hue (=org-air-faces-tag-face=) as the svg =:fill= of the *text*;
  the date label keeps its semantic hue (overdue =critical=, deadline
  =popout=, scheduled =salient=, neutral =faded=).  Because the chip is
  now *border + coloured text on no fill*, the six hues read as calm
  coloured words inside identical quiet capsules — "ONE restrained accent"
  (the hue is the label, the capsule is monochrome), not six loud fills.
- Re-render border/label on theme change so light/dark track (round-9 D3).

** D-P1 fallback (mandatory, asserts the text)
When =(not (display-graphic-p))=, svg is unavailable, OR D-P1.FIT cannot
guarantee the label fits (e.g. =string-pixel-width= missing AND the
char-width estimate already exceeds =inner-w=), render the *plain coloured
label text* (accent/semantic face) — *including the reserved pad spaces* —
and no pill.  The byte gate always asserts this text; alignment is
identical with the pill on or off.

title LEFT (flex + truncate-last), a fixed-width right cluster (date /
tags / origin), svg pills over the cluster.  Extract its *body* into a
reusable primitive:

: (org-air-view--insert-row &key prefix title date-text tags origin-text
:                                origin-face widths props face)

  so both views line their clusters up down the list.
- =org-air-view--insert-item= becomes a thin caller (task item → row args).
- The project view calls the *same* primitive, so pills, truncation,
  alignment, faces and the cluster layout are shared, not re-implemented.

* D-P6 [PROPOSAL — approval gate] routines & journals
*Do NOT spec for impl yet.*  This is a concrete, minimal proposal for
orchestrator + user approval *before* any spec hardening.  Nothing here is
a contract; no fixtures are blessed for it this round.

** Problem
org-air today is a GTD board over dated Org tasks + an Air doc tree.  Two
recurring daily-driver surfaces are missing: *routines* (habits /
repeaters with streak + done state) and *journals* (today's entry).  Both
are first-class in the org/Denote ecosystem; the proposal is to *map onto
existing org/Denote machinery*, not invent storage.

** Model (minimal)
- *Routine* = an Org heading that is either (a) an =org-habit= (a TODO with
  =:STYLE: habit= + a repeating =SCHEDULED= =.+1d= / =++1w=), or (b) any
  repeater task.  State derived from the *LOGBOOK*: =done-today?= (a
  =CLOCK=/=- State "DONE"= state-change dated today), and =streak= (run of
  consecutive completed periods read from =LOGBOOK= state lines +
  =LAST_REPEAT=).  No new file format — a routine is detected, not stored.
  defcustom-style toggle: a routine source = tag =:routine:= or
  =:STYLE: habit=.
- *Journal* = a Denote =journal= note for today: a file matching the
  Denote journal identifier for =today= (=YYYYMMDDT...= with the
  =_journal= signature, per =denote-journal-extras=), or a configured
  single =journal.org= datetree entry for today.  "Today's entry" =
  exists? / first lines preview.

** Presentation (sketch, board-parity)
- A new *Routines* rail block (or board section): each routine a row —
  title LEFT, a streak chip (=🔥 4d= / TTY =4d=) + a done marker (=●= done
  today / =○= pending) in the right cluster, reusing the D-P5 shared row
  primitive + D-P1 pills.  Toggling done = =org-todo= on the heading
  (advances the repeater, writes the LOGBOOK line we read back).
- A *Journal* affordance: a one-line rail entry "=Journal: today ✓=" /
  "=Journal: today —=" with =RET= = open/create today's Denote journal
  note (=denote-journal-extras-new-or-existing-entry= when present).

** Mapping table
| concept       | org / Denote source                                  |
|---------------+------------------------------------------------------|
| routine       | =org-habit= (=:STYLE: habit=) or repeater =SCHEDULED=|
| done-today    | LOGBOOK =- State "DONE"= dated today / today's CLOCK |
| streak        | consecutive LOGBOOK completions + =LAST_REPEAT=      |
| repeat advance| =org-todo= done → org advances =.+1d/++1w= itself    |
| journal entry | Denote =_journal= note for today (denote-journal)    |
| journal open  | =denote-journal-extras-new-or-existing-entry=        |

** Open questions for approval
1. Routines as a *board section* vs a *rail block* vs a *separate view*?
2. Streak: derive purely from LOGBOOK (robust, read-only) — acceptable, or
   do we want a cached/denormalised streak?  (Proposal: derive, no cache.)
3. Journal: Denote-journal hard dep, or also support a plain datetree
   =journal.org=?  (Proposal: Denote-journal when present, datetree else.)
4. Scope: ship routines first (more GTD-aligned), journals as a thin
   follow-up?
