* D-P1 [HIGH] — a TRULY solid divider AND clearly-visible pills (rethink R12 D-P3)
*Diagnosis (confirmed in =org-air-view--svg-pillify=):* the pill is drawn
=(svg-create box-w h)= with =h = char-px= and displayed
=(svg-image … :ascent 'center :height h)=.  With =:ascent 'center= the
image is vertically centred on the text *centerline*, so a full-line-height
image extends *above* the line's ascent by a few px → *the pill row grows
taller than a normal line*.  The =│= divider glyph is drawn at the *normal*
font line height, so on the (taller) pill rows it cannot reach the next
row → the divider reads *broken*.  Round-12's =vinset= shrank the capsule
(making it fainter) but did NOT stop the row from growing, because the
*image height* (= =h=) and =:ascent 'center= were unchanged — so the gap
persisted and the pills lost contrast.  *Both failures share one root: the
pill image grows the line.*

** D-P1.A — clamp the pill image to the font line height (the real fix)
Fix the gap at the SOURCE: the pill image must occupy *exactly* the text
line's pixel box and never grow it (this is what svg-tag-mode / svg-lib do).
- Measure the *line pixel height* =lh= (the displaying window's default
  line height — =window-font-height=, the same C2/C3 metric source) and the
  *font ascent* =asc= (e.g. =(aref (font-info (face-font 'default)) 8)=, or
  svg-lib's ascent helper).
- Build the svg at height =lh= (NOT an arbitrary =char-px= that may differ)
  and display it with an *integer* =:ascent= = =(round (* 100 (/ asc
  (float lh))))= — baseline-aligned like text — *instead of =:ascent
  'center=*.  A line-height image with the text ascent never exceeds the
  line box, so *pill rows are exactly one normal line tall*.
- With rows no longer growing, the =│= glyph fills every row at
  =org-air-line-spacing 0= → *the divider is solid*, portably (TTY + every
  GUI), with zero per-row divider machinery.  Keep =org-air-divider-style=
  ='glyph as the default; the round-12 ='svg escape hatch stays for users
  who set =line-spacing > 0=.
- =box-w= and the C2 width contract are *unchanged* (the fix is vertical
  only), so V6 column alignment is untouched.

** D-P1.B — restore clearly-visible (but calm) capsules
Undo the round-12 faintness now that breathing no longer has to come from
shrinking the pill:
- =org-air-pill-vinset= default *2 → 1* (a 1px top/bottom inset — a hair of
  internal margin, but the capsule is essentially full height again).
- =org-air-pill-border-opacity= default *0.5 → 0.85* (a clearly visible
  border, still a single hairline stroke, not a heavy chip).
- =org-air-pill-fill-alpha= default *0 → 0.08* (a *very* light tint of the
  label hue behind the label) — this is what makes a capsule read at a
  glance without shouting; combined with the 1px border the pill is
  unmistakable yet calm.
- The label keeps its accent / semantic colour (unchanged).  Net: a
  visible, soft, tinted capsule with a crisp hairline border — calm but
  *clearly a pill*.  TTY fallback (plain coloured padded text) is intact.
- =[gui]= / display-only: image height/ascent + the three default knobs are
  all svg attributes; the pill *text* is unchanged → *fixtures HOLD*.

* D-P2 [HIGH] — priority badge → a tiny solid colour square (no letter/outline)
*Symptom:* the =[#A]= badge is too big.  Make it a *tiny solid filled
colour square* — red A / orange B / cooler C — *no letter, no outline*; red
already signals importance.

*Contract:*
- *Fixed compact slot.*  Replace the variable =[#A]=-or-nothing prefix with
  a *fixed 2-column priority slot* on EVERY item row (the square + one pad
  space; *two blanks* when the row has no shown priority).  Titles then
  start at the same column whether or not an item is prioritised → V6
  title-left alignment holds across all rows.  (Today the slot only exists
  on priority rows, so titles jump — this also fixes that.)
- *Glyph (byte/TTY layer):* new glyph =priority-square= = =("■" . "#")=
  (or =▪=); the slot text is =■ = (square + pad) faced in the priority
  colour, or =␣␣= when none.  TTY/non-svg shows the coloured =■=.
- *GUI svg:* on a capable GUI overlay the =■= cell with a *tiny solid
  filled square* — =svg-rectangle= filled in =org-air-view--priority-color=,
  *no stroke*, slightly rounded (=:rx= ≈ 1px) or sharp, sized ≈ 60–70% of
  the cell and centred (a small box, not the full cell), box-fit to the
  1-col cell (=1 × char-px=, reusing the D-P1.A height-clamp so it never
  grows the row).  New =org-air-view--svg-priority-square (char)=.
- defcustom =org-air-priority-style= gains ='square (the new *default*);
  ='badge keeps the round-12 =[#A]= capsule, ='text the plain cookie.
  =org-air-priority-colors= is reused unchanged.
- =org-air-priority-show= still gates which levels render a square (default
  =?A=); a non-shown priority renders the blank slot (alignment holds).
- =[byte]=: the prefix slot changes on EVERY item row (fixed 2-col slot;
  =■ = for shown priorities, =␣␣= otherwise — vs today's =[#A] = or
  nothing) → regen + *BLESS*.  The filled-square svg is a =[gui]= overlay
  over the =■= cell.

* D-P3 [MED] — responsive: drop the rail when the window is too narrow
*Symptom:* opening a file splits the window; a too-narrow displaying window
crowds board + rail.  *Drop the rail entirely (board-only) below a width
threshold; restore it when wide.*

*Contract:*
- defcustom =org-air-rail-min-width= (default *90*): the minimum displaying-
  window width that still shows the rail.  Below it the view renders
  *board-only* — a new =org-air-view--orientation= value ='board-only=: NO
  rail, NO calendar, NO inspector; the item pane uses the *full* window
  width (the round-9 C2 row renderer already flexes to any width).
- Orientation decision (in =org-air-view--render=): =width <
  org-air-rail-min-width= → ='board-only=; else the existing
  =org-air-view--two-pane-p= path (two-pane vs stacked).  Keep the
  =org-air-layout-hysteresis= guard so dragging across the threshold does
  not flap.
- *Hook the existing resize re-render* (round-9 C1): the view already
  re-renders to the displaying-window width via
  =org-air-layout-refresh-function= / =org-air-view--resize-refresh= — the
  orientation switch rides that, so splitting/opening a file flips to
  board-only automatically and back when widened.  No new hook.
- The inspector's =post-command-hook= no-ops in ='board-only= (no inspector
  band; =org-air-view--setup-inspector= already guards on two-pane).
- =[byte]=: existing fixtures render at wide widths (two-pane) → they HOLD;
  add *new* board-only fixtures at a sub-threshold width (e.g. 70) → *BLESS*
  the new narrow fixtures only.

** A — surface ORG repeaters (read-only, detection + presentation)
- *Detect:* an item whose =SCHEDULED= or =DEADLINE= timestamp carries an
  org repeater (=.+1d=, =++1w=, =.+2d/3d=, =+1m=).  Parse the repeater off
  the Org timestamp (already available on =org-air-item-scheduled/-deadline=).
- *Row marker:* a small repeat glyph (=↻= / TTY =~=) tucked into the date
  cluster next to the date pill — so a repeating item reads as recurring at
  a glance (a non-byte svg later; the glyph is the text contract).
- *Inspector "Repeat" line:* =Repeat   every 1w → next Mon 22 Jun= — the
  human repeat rule + the next occurrence (org computes the next via
  =org-get-repeat= / timestamp math).
- *No model change* — this is pure detection over org's own repeaters.

** B — custom WORKING-DAY repeat (org has no weekday/holiday notion)
Org's builtin =.+1d/++1w= cannot say "every working day / skip weekends /
skip holidays."  Propose a *minimal org-air property model* layered on top:
- *Property:* =:AIR_REPEAT: workday= (or =every weekday=) on the heading,
  optionally =:AIR_REPEAT: workday +2= (every 2 working days).  Holidays:
  =:AIR_REPEAT: workday holidays= opts into a holiday source.
- *Holiday source:* reuse Emacs =calendar-holidays= / =holiday-list= (the
  user's existing holiday config) — defcustom =org-air-workday-holidays=
  (a function or list); default = weekends only, no holidays.
- *Advance:* when the item is completed, *org advances its own builtin
  repeater first*; org-air then, IF =AIR_REPEAT= is workday, *rolls the new
  =SCHEDULED= forward to the next working day* (skip Sat/Sun + holidays) via
  an =org-after-todo-state-change-hook= shim (=org-air-repeat-advance=).
  This avoids double-advancing: builtin moves +N, org-air only nudges off a
  weekend/holiday.  (Open question: pure-workday repeats with no builtin
  repeater — org-air owns the whole advance.)
- *Presentation:* the inspector Repeat line shows =every weekday → next Tue
  18 Jun (skipped Sat/Sun)=; the row carries the same =↻= marker.
