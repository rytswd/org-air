* V6 \u2014 Fixed date column (read dates down the list)  [byte]
*Symptom (screenshot 7):* the date token (=OVERDUE 6d= / =no date= / =Today=
/ =Fri= / =\u00b7 273d quiet=) right-aligns as part of the cluster, so it lands
at a different column on every row and the eye can't scan it.
*Fix:* make the item-row metadata a *fixed-width right-aligned TABLE*, so
date / tags / origin each occupy aligned columns down the whole list:
: <state> [<prio>] <title>  \u2026flex\u2026  [date:Wd][tags:Wt][\u2302 origin:Wo]
- =date= \u2014 *left-justified* in a fixed width =Wd= (=org-air-date-column=,
  default *12*; fits =OVERDUE 12d=, =\u00b7 273d quiet=, =Tomorrow=, =no date=).
  All dates start at the same column \u2192 they line up vertically.
- =tags= \u2014 left-justified in =Wt= (cap 2, =\u2026= overflow, quiet accent text).
- =origin= \u2014 right-justified in =Wo= (=\u2302 <file>=, always whole \u2014 D2).
- The whole table is right-aligned (fixed total width =Wd+Wt+Wo+gaps=), so
  the columns are at fixed positions; the *title* flexes/truncates in the
  space before it (single title\u2192table gap, as today \u2014 no second void).
- Faces unchanged (semantic date faces, accent tags); only *placement*
  (padding the date to =Wd=) changes \u2192 *fixture regen*.
*Why a table, not just a fixed date offset:* fixing all three fields keeps
date, tags AND origin aligned (the airctl look), and avoids re-opening
the round-5 disconnected void (one gap only, before the aligned block).

* V3 \u2014 SVG tag + date pills (rougier svg-tag-mode style)  [gui + face]
The user wants *real* svg pills (nano-* / svg-tag-mode), not the crude
round-5 text =:box=.  Crisp rounded anti-aliased pills, GUI-only, with the
quiet coloured TEXT as the byte-testable fallback.
- Render each tag (and the R10/V6 date) as an *SVG image* via a =display=
  property over the underlying text.  Draw with built-in =svg.el= \u2014 *no
  hard dependency*; soft-detect =svg-tag-mode= and use it if present, else
  our own minimal pill.  Degrade to text when =(display-graphic-p)= is nil
  or svg is unavailable.
- *Colour:* the pill uses the element's existing face foreground (the
  deterministic tag accent; the semantic date face) as the pill's text/
  border; a very light tint fill (or none) \u2014 quiet, not the heavy fill of
  round-5.
- *CRITICAL for V6:* size each pill's SVG to the *column width of its
  underlying text* so the pill overlays exactly the text cells \u2014 the V6
  text-layer alignment (=Wd/Wt/Wo=) is preserved; the pill never shifts the
  columns.  The byte/fixture layer is pure text; the gate asserts the
  text, the pill is a GUI overlay.
- defcustoms: =org-air-tag-style= (='pill on GUI when svg, else 'text),
  =org-air-date-style= (exists; same choices).  =[gui]= non-byte; =[face]=
  no new face (reuse accents + semantic date faces).

* F5 \u2014 Air-docs project mode + configurable sources
org-air should render an *Air-managed doc tree* like =airctl status= \u2014 a
separate view from the GTD task board, grouped by state / directory /
tag, with the box-tree, state-emoji badges, version/folder nesting,
=name \u21bb date #tags=, and =(+N)= roll-up counts.

** F5a \u2014 Configurable sources  [defcustom]
One simple knob to point org-air at content:
#+begin_src elisp
(defcustom org-air-sources nil
  "Where org-air finds content.  A list of entries, each either:
 - a STRING directory of org files (GTD task board), or
 - (:air ROOT)  an Air project root (rendered as a doc tree), or
 - (:files (F...)) explicit files.
Air projects are also AUTO-DETECTED: any source dir containing
`air-config.toml' or an `air/' subdir is treated as (:air ...)."
  :type '(repeat sexp) :group 'org-air)
#+end_src
- =org-air-detect-air-project= (ROOT) \u2192 non-nil when =air-config.toml= or
  =air/= exists under ROOT.
- The existing =org-air-files= / =org-air-inbox-file= remain (the GTD
  board); =org-air-sources= is the new unified, simpler entry point and
  feeds *both* the task board (org dirs) and the project view (Air roots).
- =org-air-projects= \u2014 derived (or explicit) list of Air roots for
  =org-air-project='s picker.

** F5b \u2014 The Air project view (a separate mode/command)
- =org-air-project= (command): open the Air doc-tree view; with several
  configured projects, =completing-read= to pick one.  =org-air-projects=
  lists them.
- A distinct major mode =org-air-project-mode= (derived from the same
  =special-mode= base) \u2014 the renderer is the *tree*, NOT the GTD
  bucket/calendar layout.  Coexists cleanly: =org-air= = task board,
  =org-air-project= = doc tree; a key (=P=) on the board opens the project
  view, =q= returns.
- *Data model* \u2014 an Air doc is read from its =.org=: =#+state:= \u2192 state
  (draft/ready/complete/dropped), =#+FILETAGS:= \u2192 tags, the doc =#+title=
  or filename \u2192 name, and =\u21bb date= = the doc's last-updated date (Air's
  modified stamp, else file mtime).  The *version folder* (=v0.1/=, =v0.2/=)
  and any subfolders come from the path under the Air root.  (org-air's
  own =air/= tree is itself a valid Air project \u2014 dogfood target.)

** F5c \u2014 Groupings (mirror airctl -a / -Da / -Ta)
A grouping toggle in the project view (single keys, fresh keymap):
| Key | Grouping       | Top-level box       | Per-doc shows           |
|-----+----------------+---------------------+-------------------------|
| =s=   | by STATE (-a)  | a state (\ud83d\udcdd Draft) | =\u21bb date  #tags=          |
| =d=   | by DIRECTORY   | a directory (v0.1/) | =<state badge>  \u21bb  #tags= |
| =t=   | by TAG (-Ta)   | a tag (#ai)         | =<state badge>  \u21bb  #tags= |
Default = by STATE.  Within a top box, docs nest by version/subfolder
with =(+N)= roll-ups (direct count + descendants), exactly as the
reference.
*The three groupings MUST render DIFFERENT trees* (top boxes = states vs
directories vs tags), per airctl-status-{a,Da,Ta}: in -Da each top box
is a directory with a per-state count summary (docs show their state
badge); in -Ta each top box is a #tag, likewise.
*Round-8 regen DISPUTE:* the shipped =project-view-dir.txt= and
=project-view-tag.txt= are BYTE-IDENTICAL to =project-view-state.txt= —
-Da/-Ta are not yet implemented (both fall back to the state tree).  The
STATE view is correct (blessed); the dir/tag views must be re-rendered
to group by directory / tag before those two fixtures are blessed.

- *Box:* =\u250c\u2500 <badge> <group> (<count>)= top, =\u2502= left border, =\u2514\u2500\u2026\u2500= bottom
  rule \u2014 in =org-air-face-air-tree= (= pane-border, faded).  These are the
  v0.1-style boxes (org-air-layout-style =boxed=) reused for the tree.
- *Tree:* =\u251c\u2500= / =\u2514\u2500= folder branches, =\u2502= continuation; nesting indent =3=.
- *State badge:* emoji per state, with a =[byte]= TTY/text fallback:
  | State    | GUI | TTY |
  |----------+-----+-----|
  | Draft    | \ud83d\udcdd  | [D] |
  | Ready    | \ud83c\udfaf  | [R] |
  | Work In Progress | 🔨 | [W] |
  | Complete | \u2705  | [C] |
  | Dropped  | \ud83d\uddd1\ufe0f  | [X] |
  (Air has FIVE states; org-air-face-air-state-wip added for [W].)
  (emoji via =org-air-glyphs=; the gate renders the TTY text form \u2014
  byte-stable \u2014 and a GUI snapshot shows the emoji.)
- =\u21bb date= (=\u21bb= \u2192 ASCII =~= on TTY) in =org-air-face-faded=; =#tags= in
  accent text (V3 pill on GUI).  =(+N)= roll-up in =org-air-face-count=.
- Doc rows carry =org-air-doc= / =org-air-marker= text-props; =RET= visits
  the doc, =n/p= move docs, =TAB= folds a version/subfolder, =q= returns.
- *Width:* the tree right-justifies =\u21bb date #tags= to the window width
  (plain-space, like the board) \u2014 byte-testable at fixed widths; an
  =org-air-project-view-width= seam mirrors =org-air-view-width=.
