* R21-1 — cursor jumps to column 0 on motion when the rail side window is open [BUG — critical]

** Reproduction — the "point-preserving" re-render discards the column
The user's report: moving the cursor around the board (*especially moving
RIGHT*) snaps point back to the leftmost character, *only* when the rail is
popped into its side window (=*org-air-rail*=).  Measured root mechanism:

=org-air-view--render-current= (org-air-view.el L4547) is the re-render that
EVERY live event routes through and that documents itself as
"preserving point".  It saves a token, re-renders, and restores:
#+begin_src elisp
(defun org-air-view--render-current ()
  (let ((token (org-air-view--save-position)))
    (org-air-view--render ...)
    (org-air-view--restore-position token)))
#+end_src
=org-air-view--save-position= (L4502) DOES record =:column (current-column)=.
But =org-air-view--restore-position= (L4519) THROWS IT AWAY on the common
"same item survived" branch:
#+begin_src elisp
(cond
 (marker-pos                              ; same item found by marker
  (goto-char marker-pos)
  (org-air-view--beginning-of-visible))   ; <-- snaps to col 0 / first glyph
 (section-pos ...)
 (t ...))                                 ; line/column fallback ALSO ignores :column
#+end_src
=org-air-view--beginning-of-visible= (L3209) is exactly
=beginning-of-line= + =skip-chars-forward " \t"= — it parks point on the row's
first VISIBLE glyph and never consults the saved =:column=.  So *any* re-render
that is supposed to keep point actually moves it to the leftmost char of the
row.  Measured directly (tiny 3-item file, =org-air-view-width 120=):
#+begin_src text
BEFORE re-render: col=18 char=? (inside the title)
AFTER  --render-current: col=6 char=84 ("T")  same-item=t
==> COLUMN LOST (jumped to leftmost): t
#+end_src
Point moved from column 18 (mid-title) to column 6 (the row's first visible
glyph) while staying on the SAME item — the exact "jump back to the leftmost
character" the user saw.

** Reproduction — why ONLY with the side window, and why "esp. moving RIGHT"
The column-loss above is latent in EVERY re-render; what differs with the
rail side window is how OFTEN a re-render fires during plain motion:
- *Inline rail (two-pane, the default-ish before popout):* the board buffer
  also holds the rail columns + the =│= divider, so each row is full of
  content to the right; =right-char= traverses that content and a re-render is
  rare during motion — the latent bug stays hidden.
- *Side-window rail (popped out):* the board renders =board-only= at the
  shrunk board-window width, and =org-air-view--finalize-buffer-lines= (L3177)
  RIGHT-TRIMS each row (no trailing pad).  With =truncate-lines t= the narrow
  board auto-hscrolls as point moves right; and crucially the side window
  participates in the GLOBAL layout hooks — =org-air-layout--window-size-
  change= is on BOTH =window-size-change-functions= and =window-configuration-
  change-hook= (org-air-layout.el L456-460), and the board also carries
  =org-air-rail--reconcile= on =window-configuration-change-hook= (L886) plus
  the rail-inspector follow on =post-command-hook= (L872).  The side window
  sits the board right at the =org-air-rail-min-width= board-only threshold,
  so redisplay-time window churn (resize/scroll/inspector-follow as the user
  scrubs) drives the debounced =org-air-view--resize-refresh= →
  =org-air-view--render-current= far more readily than inline ever does.  Each
  such re-render fires the column-loss above → the visible "jump to leftmost",
  most noticeable while moving RIGHT (the motion that most reliably hscrolls
  the narrow board and re-evaluates the layout).
So there are TWO faults stacked: (1) =--restore-position= discards the saved
column (the real bug — point is NOT preserved); (2) the side-window layout
churns re-renders during ordinary motion, exposing (1) on nearly every move.

** Decision — make point actually preserved; stop the motion-time churn
*** (1) PRIMARY FIX — =--restore-position= honours the saved =:column=
On the "same item" (and the section / line) branches, after landing on the
target row, restore the saved column instead of snapping to the first glyph:
#+begin_src elisp
(defun org-air-view--restore-to-column (token)
  "Move point to TOKEN's saved :column on the CURRENT row, clamped (R21-1).
Never lands before the row's first visible glyph (so the cursor still reads
on a real character, S5a), never past end-of-line."
  (let* ((first (progn (org-air-view--beginning-of-visible) (current-column)))
         (want  (or (plist-get token :column) first))
         (eol   (progn (end-of-line) (current-column))))
    (move-to-column (max first (min want eol)))))
#+end_src
and use it in all three =cond= branches of =--restore-position= in place of
the bare =org-air-view--beginning-of-visible= (marker / section / line).  Net:
=--render-current= becomes genuinely point-preserving — a re-render that finds
the same item keeps point on the SAME glyph the user was on (clamped into the
row), so even when a re-render fires on motion, *point stays where the user
put it*.  (The token already records =:column=; this is a pure use-site fix —
no new state.)

This is the fix the prompt asks for ("Point must stay where the user put it");
it is also the belt that makes the secondary churn fix non-load-bearing.

*** (2) SECONDARY — do not re-render on PLAIN motion with the side window
Even point-preserving, a full re-render on every keystroke is wasteful and was
the trigger.  Tighten so plain motion never re-renders:
- *Strict dimension gate (already present, keep + harden).*  =org-air-view--
  resize-refresh= (L4556) re-renders only when =--render-width=/=--render-
  height= actually changed vs =org-air-view--rendered-width/-height=.  Confirm
  this gate holds under the side window (measured: with a live board window +
  a real =display-buffer-in-side-window= rail, =render-width/height= equal the
  stored =rendered-width/height=, so the gate returns "no re-render").  The
  hook may FIRE on motion-driven redisplay, but the gate must keep it a no-op.
- *Threshold hysteresis (root of the churn).*  The board sitting exactly at
  =org-air-rail-min-width= can oscillate board-only ↔ side-window between
  redisplays, each flip a real dimension change → a real re-render.  Add a
  small hysteresis band (reuse/introduce =org-air-rail-width-hysteresis=, ~2
  cols): once =side-window=, stay side-window until the board width drops more
  than the band below =org-air-rail-min-width=, and vice-versa — so a 1-col
  hscroll/redisplay wobble never flips the orientation.
- *Inspector follow + reconcile never re-render or move BOARD point on motion.*
  Confirmed by construction today (the whole-region rail-inspector update runs
  in the RAIL buffer under =save-excursion=; =--reconcile= no-ops while the
  rail is shown).  Add a regression assertion (Testability) that the rail-
  inspector update leaves board point byte-identical, so a future edit can't
  reintroduce a board-touching path.

** Interaction with R21-2 (point defaults to title)
R21-2 makes *motion commands and first-open* land point on the TITLE column.
R21-1's fix is about RE-RENDER restoring the column the user was ON.  They
compose cleanly: R21-2 changes where point lands when you MOVE; R21-1 keeps
that column across a re-render.  Concretely, =--restore-to-column= uses the
SAVED column (what the user was on) — never overriding it with the title — so
the two never fight.  The first-open / vanished-item FALLBACK (no saved item)
defers to R21-2's title normaliser for consistency (see R21-2).

** Byte / batch contract
=--restore-position= / =--render-current= run only on interactive re-render
(resize, reconcile, after-save, command refresh); the cold/batch path renders
once via =--render= (which still ends on =--goto-first-item=, unchanged) and
never restores.  =move-to-column= touches only point, not buffer text.  So
every board/project byte golden is byte-identical.  The hysteresis band is a
GUI dimension decision (inert under the =org-air-view-width= seam batch uses).

** Testability (R21-1)
- ERT (the real guard): render a board, place point at a non-zero column on an
  item row, call =org-air-view--render-current=, assert =(current-column)=
  EQUALS the saved column (clamped) and the same item — locks out the column-
  loss (this test FAILS on trunk today, passes after the fix).
- ERT: restore lands ≥ the first-visible column (never on indent whitespace)
  and ≤ end-of-line (clamp invariant), incl. a row whose saved column exceeds
  the new, shorter row width (clamps to eol, no error).
- ERT (no board-point side effect): with a side-window-style whole-region
  inspector target, call =org-air-view--maybe-update-inspector= and assert
  board =(point)= is byte-identical before/after (the follow never moves board
  point).
- ERT (gate): with stable dims, =org-air-view--resize-refresh= does NOT call
  =--render= (advice/flag); after a real width change it does — proves the
  gate, so plain motion (no dim change) cannot re-render.
- No new byte fixtures (interactive/point-only).

** Routing (R21-1)
org-air-view.el only: add =org-air-view--restore-to-column=; use it in the
three branches of =org-air-view--restore-position=; add the orientation
hysteresis band to the =board-only-p= / =side-window= decision in =--render=
(L4297) + a =org-air-rail-width-hysteresis= defcustom (org-air-faces.el knobs
or the layout group).  Test seat: add the column-preservation + clamp + no-
board-point + gate ERTs.

** Open questions (R21-1)
- Should =--render-current= ALSO preserve =window-start= / hscroll (so a re-
  render does not visually jump the viewport even though point is kept)?
  Proposal: yes, cheap insurance — capture =(window-hscroll)= /
  =(window-start)= in the token and restore via =set-window-hscroll= /
  =set-window-start= when the displaying window is live; keep it optional if
  it complicates batch.
- Hysteresis band width: 2 cols proposed; the test seat eyeballs that a slow
  drag across the breakpoint no longer flickers the rail in/out.

** Decision — render each doc as a ONE-LINE board-style row via the SHARED primitive
Replace =org-air-project--insert-doc-block='s two-line body with a single
=org-air-view--insert-row= call, mapping the DOC onto the row args exactly as
=org-air-view--insert-item= maps a task (invariant #4: parameterise the shared
primitive, do not fork).  The doc's STATE becomes the row PREFIX as an svg
badge (R21-4), not an emoji; the relpath becomes the ORIGIN cell on the right;
the updated stamp becomes the DATE cell; the tags become the SAME svg tag
pills the board uses.  The two-line layout (the old R14 D-P1.A requirement) is
DROPPED — consistency with the board wins.

*** Row mapping (the new =org-air-project--insert-doc-row=)
#+begin_src elisp
(defun org-air-project--insert-doc-row (doc width &optional indent-cols)
  "Insert DOC as ONE board-style row via the shared primitive (R21-5)."
  (let* ((state  (org-air-doc-state doc))
         (prefix (concat (org-air-view--item-margin)
                         (make-string (max 0 (or indent-cols 0)) ?\s)
                         (org-air-project--state-cell state)))   ; R21-4 svg badge
         (date   (org-air-project--doc-date-text doc))           ; "↻ 2026-05-01"
         (tags   (org-air-project--doc-tagstr doc))              ; shared svg tag pills
         (origin (org-air-project--doc-origin-text doc)))        ; "⌂ v0.1/alpha-feature.org"
    (org-air-view--insert-row
     :prefix prefix
     :title (org-air-doc-name doc)
     :date-text date
     :tags tags
     :origin-text origin
     :origin-face 'org-air-face-group
     :widths (list org-air-project--meta-date-w
                   org-air-project--meta-tags-w
                   org-air-project--meta-origin-w)
     :props (list 'org-air-doc doc
                  'org-air-marker (org-air-doc-file doc)
                  'mouse-face 'org-air-face-cursor)
     :face 'org-air-face-title)))
#+end_src
- *State cell* = a FIXED-width reserved prefix slot (mirroring the board's
  =org-air-view--todo-cell=) holding the doc state as the shared svg keyword/
  state badge (R21-4): GUI = the coloured badge; TTY/byte = the short token
  (=[R]= / =Ready=, see open question on the token text).  Fixed width so all
  doc titles share one left edge, exactly like the keyword column on the board.
  The state cell is ALWAYS shown in the project view (it replaces the section
  in the directory tree), so there is no =show-state= conditional anymore.
- *Date* = =org-air-project--doc-date-text= (already "↻ YYYY-MM-DD", faded) —
  reused unchanged as the board's date cell.
- *Tags* = =org-air-project--doc-tagstr= (already routes through =org-air-
  view--item-tagstr= → the SAME D-P1 svg pills as the board) — reused.
- *Origin* = =org-air-project--doc-origin-text= ("⌂ relpath"), right-justified
  in the origin column, =org-air-face-group= — same column/face as the board's
  origin.  (Keep the R17 D-P2 Denote de-slug for the leaf if desired; see open
  question — the relpath is the doc's identity / RET target.)

* R21-3 — NEXT keyword not handled correctly: recognise NEXT/WAIT/… so they are keyword cells [BUG]

** Reproduction — NEXT is SWALLOWED INTO THE TITLE
=org-air-query--item-at-point= (org-air-query.el L60) reads the keyword via
=(org-get-todo-state)=, which only returns a word as a TODO keyword when that
word is in the BUFFER's =org-todo-keywords=.  Org's DEFAULT keyword set is
=TODO | DONE= only.  So a heading =* NEXT Foo= in a file *without* a =#+TODO:=
line (and a user whose global =org-todo-keywords= lacks NEXT) is parsed as a
plain heading whose TITLE is "NEXT Foo" and whose todo state is =nil=.
Measured (frozen clock 2026-06-26):
#+begin_src text
--- A: no #+TODO header (default keywords TODO|DONE) ---
  todo="TODO" title="Plain todo no date"      buckets=(attention)
  todo=nil    title="NEXT Next item no date"  buckets=(attention)   <-- NEXT in TITLE
  todo=nil    title="WAIT Waiting item no date" buckets=(attention) <-- WAIT in TITLE
--- B: WITH "#+TODO: TODO NEXT WAIT | DONE" ---
  todo="TODO" title="Plain"        buckets=(attention)
  todo="NEXT" title="Next item"    buckets=(attention)              <-- correct
  todo="WAIT" title="Waiting item" buckets=(attention)
#+end_src
Consequences in case A (the common GTD config that org-air itself ANTICIPATES

*** (1) A defcustom for the actionable + done vocabulary

- *Preferred — augment the global default for the scan extent.*  =let=-bind

*** The builder

(defun org-air-view--svg-keyword-badge (text face)
  "Return TEXT carrying a small coloured keyword/state svg chip (R21-4).
Reuses `org-air-view--svg-pillify' with FACE's colour as BOTH the label and
the (salient, full-strength) border, so the chip reads as a coloured badge —
distinct from the calm monochrome tag/date pills.  Returns TEXT unchanged
when svg is unavailable (the plain coloured keyword text is the fallback)."

          (not (org-air-view--svg-available-p))
          (string-empty-p (string-trim text)))

* R21-2 — point defaults to the TITLE on row entry (not the keyword / priority cell) [POLISH]

** Reproduction — motion lands point on the keyword/priority, not the title
Every row-motion command and the first-open land via =org-air-view--beginning-
of-visible= (org-air-view.el L3209) = =beginning-of-line= + skip indent.  That
parks point on the row's FIRST visible glyph, which is the leading prefix —
the TODO/NEXT keyword (or, with =org-air-priority-style= = =square=, the
priority square slot), NOT the title.  Callers: =org-air-next-line= /
=org-air-prev-line= (L4875/4881), =org-air-next-item= / =org-air-prev-item=
(L4887/4897), =org-air-toggle-section= (L4958), =org-air-view--goto-first-item=
(L3215), and the project equivalents.  So pressing =n=/=p=/=j=/=k= or opening
the board leaves the cursor sitting on "TODO"/"NEXT"/the priority square — the
user wants it on the TITLE (the row's identity), which reads better and is
where editing/peeking intent points.

** Decision — mark the title boundary in the shared row, normalise to it
The title is the first character AFTER the reserved prefix (margin + keyword
cell + priority slot), but the prefix WIDTH varies (keyword present/absent,
priority shown/blank) and the row-wide =font-lock-face= =org-air-face-title=
is applied over the WHOLE row in =org-air-view--insert-row= (it is appended to
the props over =start..point=, prefix included) — so neither the face nor the
=org-air-item= span distinguishes the title.  The robust fix is to MARK the
title boundary when the shared row is built, then normalise to that mark.

*** (1) Mark the title start in =org-air-view--insert-row=
=--insert-row= already computes =left = (concat prefix title)=; tag the first
glyph of the TITLE with a one-char property so any caller can find it:
#+begin_src elisp
;; in --insert-row, after composing LEFT, before inserting:
(when (> (length title) 0)
  (put-text-property 0 1 'org-air-row-title t title))   ; on the title's 1st glyph
#+end_src
This is a text PROPERTY, not visible text — byte goldens (which assert the
visible characters) are byte-identical.  Both the board's =--insert-item= and
the project's =--insert-doc-row= (R21-5) flow through =--insert-row=, so BOTH
views get the mark for free (invariant #4).

*** (2) Normalise to the mark
#+begin_src elisp
(defun org-air-view--row-title-pos ()
  "Return the position of the TITLE start on the current row, or first-visible.
Finds the `org-air-row-title' mark `--insert-row' put on the title's first
glyph; falls back to the row's first visible glyph (section headings / rows
with no title)."
  (save-excursion
    (let* ((eol (line-end-position))
           (bol (line-beginning-position))
           (pos (if (get-text-property bol 'org-air-row-title) bol
                  (next-single-property-change bol 'org-air-row-title nil eol))))
      (if (and pos (get-text-property pos 'org-air-row-title)) pos
        (progn (org-air-view--beginning-of-visible) (point))))))

(defun org-air-view--goto-row-title ()
  "Move point to the TITLE column of the current row (R21-2)."
  (goto-char (org-air-view--row-title-pos)))
#+end_src
- Replace the trailing =org-air-view--beginning-of-visible= in =org-air-next-
  line=, =-prev-line=, =-next-item=, =-prev-item=, =-toggle-section= (and the
  project view's motion, which shares the core map) with =org-air-view--goto-
  row-title=.
- =org-air-view--goto-first-item= lands on the first item's TITLE too (open
  defaults to the title).
- A row with no title mark (a section heading, the empty board) falls back to
  first-visible — headings are unaffected.

- Motion commands call =--goto-row-title= → point lands on the title; the next

- The SAME-item branch still restores the user's SAVED column (R21-1), never
