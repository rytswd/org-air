* R23-1 — refile face-leak: the moved item's row renders in raw org heading face [BUG]

** Reproduction — =org-get-heading= returns a FONTIFIED title; the row faces leak
After refiling an inbox item (=r= → =⌂ Move to file…=), that item's row in the
dashboard renders in RAW org-mode heading format — a big/orange =org-level-1=
headline — instead of the calm one-line row, breaking the V6 pixel-lock.

Root mechanism, measured.  The title string org-air carries on each item comes
from =org-get-heading=, which returns the heading text WITH the buffer's
font-lock =face= text-properties whenever that Org buffer has been fontified:
#+begin_src text
;; org buffer fontified (font-lock-ensure), heading "* TODO Ship quarterly report"
(org-get-heading t t t t)
  => #("Ship quarterly report" 0 21 (face org-level-1))
  text-properties-at 0 => (face org-level-1)        ; the org-level-1 face RIDES ALONG
#+end_src
That fontified title flows verbatim into the renderer — =org-air-query--item-
at-point= (org-air-query.el L90) sets =:title (org-get-heading t t t t)=, and
=org-air-view--insert-item= (org-air-view.el L2209 =:title (org-air-item-title
item)=) passes it straight to the shared =org-air-view--insert-row= (L2077), which inserts the title string UNCHANGED (it only ADDS its own
=font-lock-face=).  Rendering that item directly:
#+begin_src text
;; item whose :title carries (face org-level-1), rendered via --insert-item
rendered row: "      TODO   Ship quarterly report ..."
  at the title:  face = org-level-1            <-- LEAKED from org-get-heading
                 font-lock-face = org-air-face-title   <-- org-air's own face
  org-level-1 present in the title's face: t   <-- the big/orange headline rides along
#+end_src
Both =face= (the leaked =org-level-1=, big/orange in most themes) AND =font-
lock-face= (org-air's title face) apply to the same glyphs; the display engine
honours the explicit =face= property, so the title renders as the org headline
and the row grows / recolours — exactly the report.

** Reproduction — WHY only after refile (the buffer becomes live + fontified)
Before any refile, =org-air-query-items= scans the configured files through
=org-ql=, which visits them in background buffers that are NOT fontified, so
=org-get-heading= returns plain (property-free) titles and the rows render
calm.  The refile path makes the moved item's file buffer LIVE: =org-air-
refile-item= (org-air-inbox.el) opens the source and target with =find-file-
noselect= and runs =org-back-to-heading= / =org-set-tags= / =org-schedule= /
=save-buffer= on them — under the user's interactive Emacs (=global-font-lock-
mode=) those buffers get fontified.  =org-air-refresh= (org-air-view.el L5087)
then re-queries =org-air-query-items=, and =org-ql= reuses the SAME now-live,
now-fontified buffer, so =org-get-heading= now returns the title with =face
org-level-1= — and only the moved item's file (freshly visited) is affected,
which is why the user sees it on "that item's row".  The brief's second
hypothesis ("the re-render reuses a buffer still in org-mode") is FALSE and was
verified: =org-air-refresh= re-renders the SAME =*org-air*= buffer in =org-air-
view-mode= via =org-air-view--render= (a full erase + re-insert); the fault is
purely the leaked title properties, not a stale buffer/mode.

** Decision — strip ALL text-properties off titles (and any re-extracted text)
Belt + suspenders: clean the title at the SOURCE (so the =org-air-item= struct
NEVER carries fontified text — the contract), AND defensively at the shared
render primitive (so any re-extracted text is clean no matter the caller).

*** (a) PRIMARY — clean the title where it is extracted
=org-air-query--item-at-point= (org-air-query.el L90):
#+begin_src elisp
:title (substring-no-properties (org-get-heading t t t t))
#+end_src
=org-air-inbox--interactive-item= (org-air-inbox.el L76) — the at-point item
built in an Org buffer (which IS fontified) — likewise:
#+begin_src elisp
:title (substring-no-properties (org-get-heading t t t t))
#+end_src
This makes the struct title a plain string at the data layer, so every consumer
(board rows, the inspector, messages, the pane header, sort keys) gets clean
text without each having to strip.

*** (b) SECONDARY — defensive strip in the shared row primitive
In =org-air-view--insert-row= (org-air-view.el L2096) normalise the incoming
title to plain text before any width math, so the row is rendered PURELY via
org-air's own =font-lock-face=/explicit propertize and never inherits a caller's
face/display/org property:
#+begin_src elisp
(title (substring-no-properties (or title "")))   ; was: (or title "")
#+end_src
The existing R21-2 step then re-adds ONLY org-air's own =org-air-row-title= mark
on the (now clean) copy, and the trailing =add-text-properties= adds ONLY org-
air's =font-lock-face= — so the row carries org-air faces ONLY.  Because the
project view also funnels its doc titles through =--insert-row=, this covers the
project rows too (defence in depth; the project titles come from a non-fontified
=with-temp-buffer= keyword read, so they were already clean — this just locks
it).

*** (c) Confirm the post-refile re-render is clean
No change needed: =org-air-refresh= already does a full clean re-render (re-query
→ =org-air-view--render= erase+reinsert) in the same =org-air-view-mode= buffer.
With (a) the re-queried items are property-free, so the re-render is calm.  (If
impl wants extra certainty it MAY also call =font-lock-unfontify-region= is NOT
needed — the strip is the fix.)

** Byte / batch contract — byte-INVISIBLE
=substring-no-properties= changes only the title's TEXT PROPERTIES, never its
characters; the byte goldens assert the TEXT layer (properties stripped) and so
are byte-identical.  The fix removes a leaked =face= property the goldens never
captured.  No fixture re-bless.

* R23-2 — drop the custom mode-line by default; fall back to the user's own [DEFAULT FLIP]

** Reproduction — the calm mode-line is installed by DEFAULT and overrides theirs
The user has asked (again) to be rid of the custom bottom mode-line ("org-air ·
583 items · filter none · source all items · sort date") and to fall back to
their OWN default mode-line.  Measured (source):
#+begin_src text
(default-value 'org-air-modeline-style)  => calm        ; the SHIPPED default
;; a fresh board buffer under the default style:
(local-variable-p 'mode-line-format)     => t           ; org-air OVERRODE it
mode-line-format = ((:eval (propertize (concat "  "
                    (org-air-view--mode-line-content) "  ")
                    'face 'org-air-face-modeline)))
#+end_src
So the default =org-air-modeline-style= = =calm= (org-air-view.el L162) makes
=org-air-view--install-modeline= (L895) =setq-local mode-line-format= the calm
nano construct, clobbering whatever mode-line the user runs.  =--install-
modeline= is called in FOUR buffers — the board (=org-air-view-mode=, L909), the
popped-out rail (=org-air-rail-mode=, L3601), the source/entry pane (=org-air-
entry-view-mode=, L4080) and the project (=org-air-project.el= L1339) — so the
override lands on every org-air surface.

** Reproduction — =default= already opts out cleanly; the default is just wrong
With the style explicitly set to =default=, =--install-modeline= is a no-op and
the buffer keeps the inherited mode-line (measured):
#+begin_src text
(let ((org-air-modeline-style 'default)) (org-air-view-mode)
  (local-variable-p 'mode-line-format))  => nil   ; NO override — the user's own
#+end_src
So the machinery to honour the user's mode-line ALREADY exists; the only fault
is that the SHIPPED default is =calm=.  The fix is a default flip (+ a small
robustness tweak so a runtime flip actively restores the inherited line).

** Decision — ship =default=; keep =calm= as opt-in; restore on the non-calm path
*** (1) Flip the default
=org-air-modeline-style= defcustom (org-air-view.el L162): default =calm= →
=default=.  Update the docstring so =default= (the new default) "leaves the
mode-line untouched (your own)" and =calm= is the opt-in nano-style.  Keep BOTH
the =calm= construct (=org-air-view--status-mode-line=) and =org-air-view--mode-
line-content= intact (no deletion) so anyone who liked the calm line just sets
=(setq org-air-modeline-style 'calm)=.
*** (2) Make the non-calm path actively restore the user's mode-line
=org-air-view--install-modeline= (L895) currently only ACTS on =calm= (a bare
=when=), so it never CLEARS a stale local override (harmless on a fresh buffer,
but a runtime =calm→default= flip would leave the old local set).  Make it
symmetric so =default=/=nil=/anything-non-=calm= drops any buffer-local override
and restores the inherited (user) line:
#+begin_src elisp
(defun org-air-view--install-modeline ()
  "Install the calm nano-style mode-line, or restore the user's own (R23-2).
`calm' installs the minimal faded nano construct; ANY other value
(`default'/nil) drops any buffer-local override so the user's normal
mode-line shows.  Single line either way, so the body-height derivation is
unchanged; byte-invisible (the mode-line is not buffer text)."
  (if (eq org-air-modeline-style 'calm)
      (setq-local mode-line-format (list org-air-view--status-mode-line))
    (kill-local-variable 'mode-line-format)))
#+end_src
This covers all four surfaces uniformly (board / rail / pane / project) — each
calls the one helper — so =default= cleanly restores the normal mode-line
everywhere, INCLUDING the rail/project/pane buffers the brief flagged.
*** (3) Leave the TOP header-line as-is
The "title bar" the user likes (=org-air … Fri 26 Jun · 583 items=) is the
in-buffer banner (the modes set =header-line-format nil= — there is NO real
header line); it is SEPARATE from the bottom mode-line and looks fine.  Per the
brief, leave it untouched — this item flips ONLY the bottom mode-line default.

** Byte / batch contract — byte-INVISIBLE
The mode-line is not part of the buffer-text fixtures (the goldens strip it), so
no board/project/rail/pane golden moves.  Only the mode-line ERTs re-bless (the
default value flips).  The mode-line stays a single line, so the body-height
derivation is unchanged.

** Testability (R23-2)
- ERT (default flipped, FAILS on trunk): =(default-value 'org-air-modeline-
  style)= = =default= (was =calm=).  This is the explicit re-bless of =org-air-
  r18-dp5-modeline-style-default-is-calm= (tests/org-air-round18-ui-test.el
  L304) → rename/retarget to assert =default=.
- ERT (default leaves the user line): with the (new default) =default= style,
  =org-air-view-mode= leaves =mode-line-format= NON-local (=local-variable-p= →
  nil), i.e. the inherited/user mode-line — in the board AND in =org-air-rail-
  mode= / =org-air-entry-view-mode= / =org-air-project-mode=.
- ERT (calm opt-in still works): with =org-air-modeline-style= bound to =calm=,
  the board installs =(list org-air-view--status-mode-line)= carrying =org-air-

- ERT (runtime restore): in a buffer where =calm= installed the local line,

- No byte fixtures (mode-line is not buffer text).  Note for the test seat:
  re-bless only the two L304/L308-area mode-line ERTs; every golden is

** Routing (R23-2)

*** (1) Guide construction (3-col cells, faded)
Each guide level is a fixed 3-col cell: a RAIL cell =│= + 2 spaces (=box-
vertical=), a BLANK cell = 3 spaces, a connector cell =├─= / =└─= + 1 space
(=box-tee-left=/=box-bottom-left= + =box-horizontal=).  All faced =org-air-face-
air-tree=; all via =org-air-layout-glyph= (so TTY/byte = =|  = / =+- =).  TOP
dirs (depth 0) keep the accent =org-air-project--marker= (=▌=) as the section
bullet — they are independent sections, blank-line separated, never railed.

*** (2) Thread rails + last-child through =--insert-dir-node=
Replace the unused =_topp= param with =rails= (the accumulated ancestor guide
string) + =lastp= (is this node the last of its siblings):
#+begin_src elisp
(defun org-air-project--insert-dir-node (node width &optional rails lastp)
  (let* ((depth (plist-get node :depth))
         (children (plist-get node :children))
         (dir (plist-get node :dir))
         (name (if (and dir (not (string-empty-p dir))) (concat dir "/") "·"))
         (guide (if (zerop depth)
                    (concat "  " (org-air-project--marker) " ")     ; top: marker
                  (concat "  "
                          (propertize rails 'face 'org-air-face-air-tree)
                          (propertize
                           (concat (org-air-layout-glyph
                                    (if lastp 'box-bottom-left 'box-tee-left))
                                   (org-air-layout-glyph 'box-horizontal) " ")
                           'face 'org-air-face-air-tree))))
         (start (point))
         (left (concat guide (propertize name 'face 'org-air-face-section)))
         (summary (org-air-project--dir-count-summary
