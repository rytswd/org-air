* R24-1 — refile "Under heading" prompt: complete over the file's real headings [UX]

** Reproduction — the heading is a FREE =read-string= (the user can't see the headings)
The dedicated =⌂ Move to file…= picker, after resolving the target file, asks
for the sub-heading with a *bare* =read-string= (org-air-inbox.el:169, inside
=org-air-inbox--read-move-target=):
#+begin_src elisp
(let* ((files  (org-air-inbox--target-files item))
       (cands  (append (org-air-inbox--file-candidates files) '("⌂ other file…")))
       (choice (completing-read "Move to file: " cands nil t))
       (file   (org-air-inbox--decode-file-choice choice item))
       (heading (read-string "Under heading (empty for file end): ")))   ; <-- free text
  (cons file (unless (string-empty-p heading) heading)))
#+end_src
The user has just picked a FILE they may not author — they have no idea which
top-level headings exist, so the free prompt is a guessing game.  Measured: the
candidates that =org-air-inbox--target-position= can actually resolve are the
file's headings, and they are trivially collectable:
#+begin_src text
;; target file with: "* Projects / ** Alpha / * Someday / * Reading list"
collected headings (org-heading-regexp + org-get-heading) =>
  ("Projects" "Alpha" "Someday" "Reading list")
(org-air-inbox--target-position FILE "Someday") => #<marker at 48>   ; resolves
(org-air-inbox--target-position FILE "")         => #<marker at 63>  ; = point-max (file end)
#+end_src
So the matcher already accepts a heading STRING (it builds
=org-complex-heading-regexp-format= from it) and already treats empty as
file-end — only the PROMPT is unhelpful.

** Decision — =completing-read= over the file's headings; default "(file end)"; skip when none
Replace the free =read-string= with a =completing-read= whose vocabulary is the
TARGET FILE's own headings, with a clear =(file end)= default that maps to the
current append-at-end behaviour, and SKIP the prompt entirely when the file has
no headings.

*** (1) A heading collector for the target file
Add =org-air-inbox--file-headings= (org-air-inbox.el, near =--target-position=
L53): visit the target with =find-file-noselect= in a widened buffer and collect
the heading TEXT via =org-get-heading= (property-stripped, so no face leak — the
R23-1 discipline), top-level AND nested (so a doc can be filed under =** Alpha=).
The candidate STRING is exactly what =--target-position= matches:
#+begin_src elisp
(defun org-air-inbox--file-headings (file)
  "Return FILE's heading titles (top-level + nested) as plain strings (R24-1).
Plain text (no fontification) so the completion vocabulary never carries an
org heading face; the order is buffer order so the list reads top-to-bottom."
  (when (and file (file-readable-p (expand-file-name file)))
    (with-current-buffer (find-file-noselect (expand-file-name file))
      (org-with-wide-buffer
       (let (out)
         (goto-char (point-min))
         (while (re-search-forward (concat "^" org-outline-regexp) nil t)
           (push (substring-no-properties (org-get-heading t t t t)) out))
         (nreverse out))))))
#+end_src

*** (2) The prompt uses it; =(file end)= is the default; no headings = skip
=org-air-inbox--read-move-target= (L157) builds the heading interactively from
the collected list, with a sentinel =(file end)= candidate FIRST (the default),
and skips the prompt when there are no headings:
#+begin_src elisp
(defun org-air-inbox--read-heading (file)
  "Read an optional target HEADING in FILE via completion (R24-1).
Candidates are FILE's real headings plus a leading `(file end)' default;
`(file end)' / empty / RET => nil (append at file end, the current
behaviour).  Returns nil with NO prompt when FILE has no headings."
  (let ((headings (org-air-inbox--file-headings file)))
    (when headings
      (let* ((file-end "(file end)")
             (choice (completing-read
                      "Under heading (default file end): "
                      (cons file-end headings) nil nil nil nil file-end)))
        (unless (or (string-empty-p choice) (string= choice file-end))
          choice)))))
;; in --read-move-target, replace the bare read-string with:
;;   (heading (org-air-inbox--read-heading file))
#+end_src
The =cons (file-end headings)= keeps =--target-position='s contract:
=--read-heading= returns either nil (file end) or a heading STRING that
=--target-position= resolves; nothing else in the move path changes
(=org-air-refile-item= still passes =target-heading= straight through, and the
=(cons file (unless ... heading))= shape is unchanged).

** Byte / batch contract — byte-INVISIBLE
The change is confined to the INTERACTIVE prompt; there is no render-path edit,
so every board + project byte golden is byte-identical.  =--file-headings= reads
with =substring-no-properties= (no face leak into a candidate string).

*** (1) Thread own-docs as children of the dir (so =├─=/=└─= are correct)
In =--insert-dir-node= the own-docs are emitted BEFORE the child dirs, so a
dir's children, in order, are =[own-docs… child-dirs…]=.  The =└─= corner goes
to the *last child overall*: the last child-dir, or — when the dir has NO child
dirs — the last own-doc.  Compute the child rail context ONCE (the existing
=child-rails=) and the running last-child flag across the combined list:
#+begin_src elisp
;; in org-air-project--insert-dir-node, replacing the bare own-docs loop:
(let* ((docs (plist-get node :own-docs))
       (kids (plist-get node :children))
       (ndocs (length docs)) (nkids (length kids))
       (i 0))
  ;; own-docs: never `last' while child dirs follow; the final own-doc is
  ;; `last' ONLY when there are no child dirs.
  (dolist (doc docs)
    (setq i (1+ i))
    (org-air-project--insert-doc-row
     doc width depth child-rails (and (= i ndocs) (zerop nkids))))
  ;; child dirs: unchanged, but `lastp' now accounts for the leading docs.
  (let ((j 0))
    (dolist (child kids)
      (setq j (1+ j))
      (org-air-project--insert-dir-node child width child-rails (= j nkids)))))
#+end_src
(=child-rails= is the rail string =--insert-dir-node= already computes for its
children; a TOP dir's =child-rails= is "" — its own-docs rail at the marker
column with no leading =│=, matching R23-3's "top dirs aren't railed" choice.)

*** (2) =--insert-doc-row= paints the gutter, keeping the state-cell column locked
=--insert-doc-row= takes the rail context instead of a bare indent and builds the
gutter to the SAME width the old =indent-cols= produced (so the state cell stays
at its V6 column), filling it with the faded rails + connector + padding:
#+begin_src elisp
(defun org-air-project--insert-doc-row (doc _width &optional depth rails lastp)
  ...
  (let* ((state  (org-air-doc-state doc))
         ;; The gutter occupies EXACTLY the old indent width so nothing to the
         ;; right moves: lead "  ", the faded ancestor rails, the doc's own
         ;; tee/corner connector, then pad to the old state-cell column.
         (margin-w (string-width (org-air-view--item-margin)))   ; the 6-col margin
         (old-indent (* 2 (1+ (or depth 0))))      ; the R21-5/R23-3 indent width
         (gutter-w (+ margin-w old-indent))        ; the V6-locked gutter total
         (guide-raw (concat "  " (or rails "")
                            (org-air-layout-glyph (if lastp 'box-bottom-left
                                                    'box-tee-left))
                            (org-air-layout-glyph 'box-horizontal) " "))
         (guide (org-air-view--pad-to
                 (propertize (truncate-string-to-width guide-raw gutter-w)
                             'face 'org-air-face-air-tree)
                 gutter-w))
         (prefix (concat guide (org-air-project--state-cell state)))
         ...)
    (org-air-view--insert-row :prefix prefix :title (org-air-doc-name doc) ...)))
#+end_src
The =guide= is faded =org-air-face-air-tree= and routes every glyph through
=org-air-layout-glyph= (so a TTY/batch frame gets =|  =/=+- =).  Because the
gutter width =gutter-w= == the old =item-margin + (* 2 (1+ depth))=, the state cell / title
/ right cluster are byte-stable.  (When a VERY deep rail string would exceed the
old indent — depth ≳ 4 in practice — the gutter grows by whole rail cells and
the state cell shifts right with it; this is the only case anything moves, it is
deliberate, and it still never touches the right-pinned date/tag/origin cluster.)

* R24-6 — free-text (content) filter: bare token = substring, =#token= = tag [FEATURE]

** Reproduction — the filter matches TAGS ONLY; a bare word finds nothing
The shared matcher =org-air-view--tags-pass-filter-p= (org-air-view.el:1137)
takes only the item/doc TAGS, so a query that the user expects to match a TITLE
yields nothing:
#+begin_src text
(org-air-project-filter '("feature"))   ; matches "Alpha feature" TITLE? -> docs 0
(org-air-project-filter '("ui"))         ; #ui is a real tag        -> docs 4
#+end_src
So =#git=-style tag filtering works, but the user's "type =git=, match anything
that mentions git" does not.  Both the board (=--passes-filter-p=, L1151) and the
project (the =--render= =seq-filter= over =org-air-doc-tags=) route through the
tags-only matcher.

** Decision — a tiny filter mini-language on the SHARED core (board + project)
Extend the filter so each active token is either a TAG match (=#token=, the
current AND/OR semantics) or a case-insensitive SUBSTRING match (a BARE token)
over the item/doc's searchable TEXT — title + origin/path + the tag NAMES (so a
bare tag name still finds its tagged items, preserving today's behaviour as a
subset).  Mixed tokens combine through the existing =org-air-filter-match=
all/any combinator (=M-/=).  One core, both views (no fork).

*** (1) The token matcher + the shared per-item predicate
#+begin_src elisp
(defun org-air-view--filter-token-match-p (token text tags)
  "Non-nil when TOKEN matches: a `#tag' token = exact TAG membership; a BARE
token = case-insensitive SUBSTRING of TEXT (which the caller builds from the
title + origin/path + tag names).  Case-insensitive throughout (R24-6)."
  (if (string-prefix-p "#" token)
      (let ((tag (downcase (substring token 1))))
        (and (member tag (mapcar #'downcase tags)) t))
    (and (string-search (downcase token)
                        (downcase (concat text " " (string-join tags " "))))
         t)))

(defun org-air-view--tokens-pass-filter-p (text tags)
  "Return non-nil when TEXT/TAGS satisfy the active filter tokens + combinator.
SHARED by the board (item title+file+tags) and the project (doc name+relpath+
tags) — the one matcher both views call (R24-6, generalising R18 D-P3)."
  (let ((tokens (org-air-view--filter-tags)))
    (or (null tokens)
        (funcall (if (eq org-air-filter-match 'all) #'seq-every-p #'seq-some)
                 (lambda (tok) (org-air-view--filter-token-match-p tok text tags))
                 tokens))))
#+end_src
=org-air-view--tags-pass-filter-p= (L1137) becomes a thin tags-only wrapper
(=(org-air-view--tokens-pass-filter-p "" item-tags)=) so any legacy caller still
works; the real call sites pass the text:
#+begin_src elisp
;; board (org-air-view.el:1151):
(defun org-air-view--passes-filter-p (item)
  (org-air-view--tokens-pass-filter-p
   (concat (org-air-item-title item) " " (org-air-view--origin item))
   (org-air-item-tags item)))
;; project (org-air-project--render seq-filter):
(org-air-view--tokens-pass-filter-p
 (concat (org-air-doc-name d) " " (org-air-doc-relpath d))
 (org-air-doc-tags d))
#+end_src

#+end_src
