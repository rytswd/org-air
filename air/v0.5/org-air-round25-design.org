* R25-2 — make the SVG state badge LETTER legible (bigger + bold), cell width fixed [POLISH]

** Reproduction — the 3-char =[R]= token is width-fitted into a 1-COLUMN inner box
R24-3 made the project state badge a filled colour SVG
(=org-air-project--state-svg-badge=, org-air-project.el:421) that overlays
=org-air-view--svg-pillify= on the 3-col token =[R]=/=[D]=/=[X]=… .  The chip
gets the right COLOUR (the state face) but the LETTER is tiny.  Root cause, read
in =--svg-pillify= (org-air-view.el:1656): the drawn label is =(string-trim
text)= = the FULL token =[D]= (3 columns), and the label is width-fitted into the
box INNER width, which is the cell minus the reserved pad columns on BOTH sides:
#+begin_src elisp
;; org-air-view--svg-pillify, today:
(ncols   (string-width text))                 ; = 3 for "[D]"
(pad     (max 0 org-air-pill-pad-cols))       ; default 1
(box-w   (* ncols cw))                         ; 3 cols wide (the cell box)
(inner-w (* (max 1 (- ncols (* 2 pad))) cw))  ; (3 - 2) = 1 COLUMN of inner room
(label   (string-trim text))                   ; "[D]" — 3 glyphs into 1 col
#+end_src
So a 3-glyph =[D]= is squeezed into ONE column: =fit-font-size= shrinks the font
until =[D]= fits 1 col, leaving the actual LETTER microscopic while the two
brackets eat the width.  That is exactly the user's "the LETTER is too small to
read" — and at that size =[D]= and =[X]= both read as a bracket-blob (feeding the
R25-4 "both look like D" complaint).  Measured: =desired-fs= starts at =(max 7
(round (* ch org-air-pill-font-scale)))= but the fit step then DIVIDES it by the
overrun ratio (=[D]= natural width / 1 col), so the rendered glyph is a fraction
of the line height.

** Decision — draw a SINGLE bold LETTER (not the bracket token), with room to grow
The cell TEXT stays =[D]= (the 3-col byte/TTY contract, the pixel-lock box, the
fallback) — but the SVG OVERLAY draws just the distinct state LETTER (=D=/=R=/
=W=/=C=/=X=, from =org-air-project--state-letter=, the R25-4 source) at a bigger,
BOLD font.  A 1-glyph label has far more inner room than the 3-glyph token, so
the fit step no longer shrinks it; bumping the font-scale + dropping the pad for
this chip makes the letter large and legible while the box stays =Ncols * cw= (3
cols) — so the cell width, the title left edge and the R25-1 rails never move.

*** (1) =--svg-pillify= gains =:label= + =:font-weight= (drawn glyph != cell text)
Extend =org-air-view--svg-pillify= (org-air-view.el:1656) with two optional
keywords, both fully back-compatible (defaults reproduce today's output exactly,
so every existing pill/badge caller is byte-identical):
#+begin_src elisp
(cl-defun org-air-view--svg-pillify (text face &key (align 'center) border-color
                                         label font-weight)
  "... LABEL overrides the drawn glyph string (default: TEXT trimmed) so a chip
can show a glyph DIFFERENT from its text-cell contract (R25-2: the project state
badge keeps the `[D]' cell text for the byte/pixel-lock box but draws just `D').
FONT-WEIGHT (e.g. `bold') is passed to `svg-text' (default: normal). ..."
  ...
  (let* (... (label (string-trim (or label text))) ...)        ; <- override
    ...
    ;; cache key MUST include the override + weight + the effective scale/pad so a
    ;; badge image is never confused with a same-text board pill:
    (org-air-view--svg-image-cached
     (list 'pill text label font-weight fg border align cw ch
           (and border-color t) org-air-pill-pad-cols org-air-pill-font-scale
           org-air-view--pill-style-sig)
     (lambda () ... (svg-text svg label ... :font-size font-size
                              :font-weight (or font-weight 'normal)) ...))))
#+end_src
The label is still width-FITTED to =inner-w= (the clip guard is untouched), so a

=font-weight=, =org-air-pill-pad-cols= and =org-air-pill-font-scale= so a chip
rendered with a dynamically-bumped scale/pad (below) never reuses a board pill's
cached image.

*** (2) =--state-svg-badge= passes the LETTER, bold, with room

content (=back-ptr= -> =*org-air-project*=).  That is exactly the user's
screenshot — an inline rail + a side-window rail, the side rail leaking the OTHER
view's content.

** Root cause — the side rail is a frame SINGLETON, but show/hide is gated on the SELF render
- =*org-air-rail*= is ONE buffer in ONE frame side window (a frame-global
  resource); =org-air-rail--board-buffer= (the back-pointer) records its current
  OWNER.  But the popped-out state =org-air-view--rail-popped-out= is BUFFER-LOCAL
  per view, and the only code that creates/destroys the side window is each
  view's OWN render tail (org-air-view.el:4818 / org-air-project.el:1325):
#+begin_src elisp
;; render tail today (board AND project) — acts ONLY on the SELF buffer:
(cond ((eq org-air-view--orientation 'side-window) (org-air-rail--show (current-buffer) width))
      ((eq org-air-view--orientation 'board-only)  (org-air-rail--hide (current-buffer))))
#+end_src
- When the board renders =two-pane=/=stacked= (its own rail INLINE) it takes the
  =cond='s default — it "leaves any rail buffer untouched".  But there IS a rail
  buffer (the PROJECT's side window from before the switch).  Nothing reconciles
  it, so it is STRANDED — a second rail, showing the project while the board is in
  the main window.
- =org-air-rail--reconcile= (org-air-view.el:3970) is purely REACTIVE to a
  user-close (rail window vanished while the SELF view stays popped); it has no
  notion of "the side window belongs to ANOTHER view than the one now active",
  so it never fires here (the SELF board's flag is nil; the project's flag is t
  but the project is not the active main view).
So: the singleton side rail follows whichever view rendered it LAST and is never
re-pointed/torn-down when the ACTIVE main view changes — hence both a second rail
AND a cross-view content leak.

** Decision — a single-owner rail invariant, reconciled to the ACTIVE view
Model the rail with ONE clean invariant and a reconciler that ENFORCES it on
every window-config change and at each render tail:

  INVARIANT.  At most ONE =*org-air-rail*= side window exists on the frame.  It
  belongs to exactly one OWNER (the active org-air main view) and exists IFF
  that active view's =org-air-view--rail-popped-out= is t (and the view is wide
  enough).  Every other org-air view renders its rail INLINE.  A view that is
  popped but NOT the active main view has its side window SUSPENDED (hidden,
  flag kept) so returning to it cleanly re-pops.

State per view (buffer-local):
- =org-air-view--rail-popped-out= : t = wants the side-window rail; nil = inline.
  (Unchanged; still the per-view toggle target — board and project independent.)
- =org-air-view--rail-suspended= : NEW.  t = this view is popped (flag t) but its
  side window is currently hidden because ANOTHER view is the active main view.
  Distinguishes "hidden for a cross-view switch" (re-pop on return) from "the
  user natively CLOSED the rail" (fall back inline).  Cleared whenever this
  view's rail is consistent (owns the side window) or toggled inline.

*** (1) Helpers — the active view + the singleton side window
#+begin_src elisp
(defun org-air-rail--host-buffer-p (buf)
  "Non-nil when BUF is an org-air board/project (rail HOST) buffer."
  (and (buffer-live-p buf)
       (with-current-buffer buf (derived-mode-p 'org-air-view-mode 'org-air-project-mode))))

(defun org-air-rail--active-view (&optional frame)
  "Return the org-air HOST buffer shown in a MAIN (non-side) window on FRAME.
Prefers the selected window; else the first non-side window hosting an org-air
view.  The *org-air-rail* and *org-air-view* panes are side windows, so they are
skipped — only the BOARD/PROJECT main view counts."
  (setq frame (or frame (selected-frame)))
  (let ((sel (window-buffer (frame-selected-window frame))))
    (if (and (not (window-parameter (frame-selected-window frame) 'window-side))
             (org-air-rail--host-buffer-p sel))
        sel
      (catch 'hit
        (dolist (w (window-list frame 'no-mini))
          (unless (window-parameter w 'window-side)
            (when (org-air-rail--host-buffer-p (window-buffer w))
              (throw 'hit (window-buffer w)))))
        nil))))

(defun org-air-rail--side-window (&optional frame)
  "Return the live *org-air-rail* side window on FRAME, or nil."
  (let ((rb (get-buffer org-air-rail-buffer-name)))
    (and rb (get-buffer-window rb (or frame (selected-frame))))))

(defun org-air-rail--side-owner (&optional frame)
  "Return the OWNER (back-pointer) buffer of the side rail on FRAME, or nil."
  (let ((win (org-air-rail--side-window frame)))
    (and win (buffer-local-value 'org-air-rail--board-buffer (window-buffer win)))))
#+end_src

*** (2) The reconciler — enforce the invariant for the ACTIVE view
=org-air-rail--reconcile= (org-air-view.el:3970) is generalised from "user-close
only" to the full single-owner reconcile, dispatched per-mode and deferred out of
the hook (window mutation never runs INSIDE =window-configuration-change-hook=):
#+begin_src elisp
(defun org-air-rail--reconcile ()
  "Enforce the single-owner rail invariant for the ACTIVE view (R25-6).
Buffer-local on each board/project `window-configuration-change-hook'.  Defers
the (window-mutating) reconcile to a 0s timer so it runs AFTER the window config
settles."
  (when (and (not noninteractive) (not org-air-rail--reconciling))
    (let ((frame (selected-frame)))
      (run-with-timer 0 nil
        (lambda () (when (frame-live-p frame)
                     (org-air-rail--reconcile-frame frame)))))))

(defun org-air-rail--reconcile-frame (frame)
  "Reconcile the singleton side rail to the ACTIVE org-air view on FRAME (R25-6)."
  (when (and (not noninteractive) (not org-air-rail--reconciling))
    (let* ((org-air-rail--reconciling t)
           (active (org-air-rail--active-view frame))
           (side   (org-air-rail--side-window frame))
           (owner  (org-air-rail--side-owner frame)))
      (cond
       ;; No active org-air main view: any side rail is an orphan -> hide it,
       ;; mark its owner suspended so re-entry re-pops.
       ((not (buffer-live-p active))
        (when (window-live-p side)
          (when (buffer-live-p owner)
            (with-current-buffer owner (setq-local org-air-view--rail-suspended t)))
          (org-air-rail--hide (or owner active))))
       (t
        (with-current-buffer active
          (let ((width (org-air-view--render-width)))
            (cond
             ;; (A) active WANTS the side rail.
             (org-air-view--rail-popped-out
              (cond
               ((eq owner active)                       ; already ours -> consistent
                (setq-local org-air-view--rail-suspended nil))
               ((window-live-p side)                    ; owned by another view -> re-own
                (when (buffer-live-p owner)
                  (with-current-buffer owner (setq-local org-air-view--rail-suspended t)))
                (setq-local org-air-view--rail-suspended nil)
                (org-air-rail--show active width))
               ((org-air-view--board-only-p width) nil) ; responsive-narrow: keep flag
               (org-air-view--rail-suspended            ; hidden for a switch -> re-pop
                (setq-local org-air-view--rail-suspended nil)
                (org-air-rail--show active width))
               (t                                       ; user CLOSED it -> go inline
                (setq-local org-air-view--rail-popped-out nil
                            org-air-view--rail-suspended nil)
                (org-air-view--refresh-current))))
             ;; (B) active is INLINE: no side rail may show.
             (t
              (when (window-live-p side)
                (when (buffer-live-p owner)
                  (with-current-buffer owner (setq-local org-air-view--rail-suspended t)))
                (org-air-rail--hide (or owner active))))))))))))
#+end_src
=org-air-rail--user-closed-p= is folded into the (A)"no side window & not
suspended & not board-only" branch: a genuine native close leaves the flag t,
suspended nil, and the rail window gone while the popped view is active -> fall
inline (the brief's "closing the side window reconciles to inline cleanly").

*** (3) Render tails route through the reconciler (drop the ad-hoc cond)
Replace the self-only show/hide cond at BOTH render tails (org-air-view.el:4818,
org-air-project.el:1325) with the existing self show/hide PLUS a cross-view
sweep, so a re-render of an INLINE view also evicts a stale foreign side rail:
#+begin_src elisp
;; render tail (board + project):
(cond ((eq org-air-view--orientation 'side-window) (org-air-rail--show (current-buffer) width))
      ((eq org-air-view--orientation 'board-only)  (org-air-rail--hide (current-buffer))))
;; R25-6: an INLINE (two-pane/stacked) self-render must also drop a stale
;; side rail owned by ANOTHER view (the cross-view sweep).
(org-air-rail--evict-foreign-rail (current-buffer))

(defun org-air-rail--evict-foreign-rail (self)
  "Hide a *org-air-rail* side window that does NOT belong to SELF (R25-6).
Suspends its owner (flag kept) so returning to that owner re-pops cleanly."
  (let* ((side  (org-air-rail--side-window (selected-frame)))
         (owner (org-air-rail--side-owner (selected-frame))))
    (when (and (window-live-p side) (not (eq owner self)))
      (when (buffer-live-p owner)
        (with-current-buffer owner (setq-local org-air-view--rail-suspended t)))
      (org-air-rail--hide (or owner self)))))
#+end_src
When SELF is popped (=side-window=) =--show= owns the window first, so the sweep
finds =owner == self= and no-ops.  When SELF is inline, the sweep drops a
lingering foreign rail.  (=board-only= keeps the SELF flag as today — the
responsive-narrow teardown is untouched.)

*** (4) Toggle / popin stay thin; both modes install the hook (already true)
=org-air-rail-toggle= (L3899), =org-air-rail-popin= (L3936) and the per-mode
render dispatch via =org-air-view--refresh-current= are UNCHANGED in shape — they
flip =org-air-view--rail-popped-out= + clear =--rail-suspended= and let the
reconciler enforce the invariant.  The board (org-air-view.el:958) and project
(org-air-project.el:1521) already add =org-air-rail--reconcile= to
=window-configuration-change-hook= (R24-5); both now run the generalised
reconcile.

Walkthrough of the reproduced bug under the new model:
#+begin_src text
project popped (flag t, owns side, suspended nil); switch main window -> board (flag nil):
  board's window-config-change -> reconcile-frame: active=board, flag nil, side owned by project
  -> (B): hide the side window, project.suspended=t  => ONE rail (board inline), no leak
switch back -> project:
  reconcile-frame: active=project, flag t, side not live, project.suspended t
  -> (A): re-pop -> side window reappears with PROJECT  => project preserved its popped state
user hits C-x 0 on the project's rail window:
  reconcile-frame: active=project, flag t, side not live, suspended nil, not board-only
  -> (A) user-close: project flag nil, refresh inline  => closes cleanly to inline
#+end_src

** Testability (R25-6) — DRIVE toggles + view switches; assert exactly ONE rail

directly to assert synchronously).

  drive =|= in the project (popped), switch the main window to the board + reconcile;
  assert EXACTLY ONE =*org-air-rail*= side window does NOT show project content
  while the board is active — i.e. the side window is GONE (board is inline) OR (if
  the board is popped) its =back-ptr= is the BOARD, never the project.  On trunk
  the side window survives with =back-ptr=*org-air-project*= beside an inline board

- ERT (board<->project independent): board popped (=|=), switch to project + back;

- ERT (close reconciles to inline): project popped; delete the rail side window

- ERT (no orphan when navigating away): popped project, then =switch-to-buffer= a

** Open questions (R25-6)
- When BOTH board and project are split-VISIBLE at once (two main windows), which
  is "active"?  Proposal: the SELECTED window's view wins (=--active-view= prefers
  it); the side rail follows the selected main view.  This is unambiguous and
  matches "the CURRENT view".  Flag if a user wants a pinned rail per visible
  view (out of scope — would need a second side window, breaking the singleton).
- Re-owning on every board<->project switch re-renders the side rail — a flicker
  risk.  Proposal: acceptable (re-own only fires on an actual owner mismatch, and
  the R18 caches make the rail re-render cheap + text-only).  Flag if the test
  seat sees thrash; the =org-air-rail--reconciling= latch + the deferred timer
  bound it to one settle.
- Keep the =org-air-view--rail-suspended= flag, or accept that visiting an inline
  view DEMOTES a popped view to inline (simpler, still leak-free)?  Proposal:
  KEEP suspended — it preserves each view's popped preference across a glance at
  the other view, which is the "board and project independent" spirit; it is one
  buffer-local + a single branch, and it cleanly disambiguates cross-view-hide
  from a genuine user close (the only correctness-critical distinction).
