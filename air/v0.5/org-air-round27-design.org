* R27-1 — project rail: flicker / random resize / random refresh [BUG]

** Reproduction A — the geometry feedback loop has no fixpoint (suspect d)
The rail side-window column width is derived from the MAIN window's width
tier (=org-air-rail--window-cols=, org-air-view.el:3857–3863 →
=org-air-view--rail-width=, :2640–2648: ≥150→42, 120–149→32, <120→28), but
the main window's width DEPENDS on the rail's width.  At frame width F the
fixpoint fails whenever =tier(F−42) ≠ tier(F−32)= — i.e. 182 ≤ F < 192 and
148 ≤ F < 152 at defaults.  The user's GUI-ish frame (190 in the drive)
sits in the band.  Measured (board, demo, frame 190, rail popped, ALL
timers cancelled so only render geometry shows; 6 explicit re-renders):
#+begin_src text
render 1..6: rail-w=32 main-body-w=157 rendered-w=147
             resizes = ("*org-air-rail*" +10 t), ("*org-air-rail*" -10 t)
#+end_src
EVERY render resizes the rail TWICE: =org-air-view--render= (:5088–5096)
calls =org-air-rail--ensure-window= at the PRE-shrink width (157→tier 42,
rail grows +10), re-measures the board at 147 and composes, then the render
tail (:5173) calls =org-air-rail--show= at the POST-shrink width (147→tier
32, rail shrinks −10).  Two visible rail resizes per repaint = the flicker.
=display-buffer-in-side-window= re-applies =window-width= on every call
(:4023, via the params at :3865–3873); nothing pins the rail
(=window-preserve-size= is used nowhere).

ETERNAL loop.  "Flickers and resizes randomly" + "refreshes randomly" is
this one cycle, plus reproduction C/D below stacking on top.

** Decision — stable rail geometry: one owner, created once, convergent by construction
Four spec points; together every reproduction above becomes a no-op loop.

*S1. Rail columns derive from the FRAME, not the main window.*
=org-air-rail--window-cols= takes the frame's total column width
(=frame-width= of the host's frame) — an input the rail's own existence
cannot change — so ensure/tail/reconcile all agree by construction and a
fixpoint always exists.  =org-air-rail-window-width= still wins when set.
The tier function itself (≥150→wide / ≥120→mid / narrow) is unchanged, now
fed the frame width.  Both call sites in the board render and both project
call sites route through the one function (shared primitive, no fork).

*S2. The side window is created ONCE, reused, and pinned.*
=org-air-rail--ensure-window= becomes convergent: when a live rail side
window already exists on the frame it is returned UNTOUCHED — no
=display-buffer-in-side-window= call at all — unless =desired-cols ≠
actual-cols=, in which case ONE =window-resize= delta adjusts it.  After
creation the window is pinned: =(window-preserve-size win t t)= plus the
existing dedicated/no-delete parameters, so redisplay and sibling churn
cannot drift its width.  =org-air-rail--hide= keeps =delete-window= (pop-in
is a real teardown); the show path NEVER deletes+recreates.

*S3. Reconcile: one pending timer, render-latched, edge-triggered user-close.*
- ONE timer slot: =org-air-rail--reconcile-timer= (frame-keyed or global);
  a hook fire while one is pending RESCHEDULES it instead of stacking (5
  fires → 1 timer; measured trunk: 5).
- Render latch: the full extent of =org-air-view--render= /
  =org-air-project--render= binds =org-air-rail--reconciling= t, so a
  nested reconcile timer no-ops (and re-arms the single slot for after the
  render) instead of mutating state mid-render — kills reproduction C.
- Edge-triggered user-close: the reconciler records per-frame whether the
  side window was live at its last run (=org-air-rail--side-was-live=,
  also updated by the render tail and =org-air-rail--show/--hide=).  The
  user-close branch (flag cleared, fall inline) may fire ONLY on an
  observed live→dead transition with the host window still wide enough —
  never on mere absence (absence + flag t + was-live nil = a popout in
  flight or a suspended view: leave state alone; the render tail owns it).
- Convergence: when owner==active and the window geometry already matches,
  reconcile-frame changes NOTHING (no show, no hide, no resize) — the
  existing no-op branch plus S1/S2 make this the steady state.

*S4. Repaints happen exactly at swap; one scanner at a time.*
- =org-air-view--render-current= must NOT run the synchronous fallback
  query while the R26-8 machine is refreshing: when
  =org-air-view--refresh-state= is =refreshing=, render items-as-is (the
  swap will repaint); when additionally cold (=--loading= t), repaint the
  skeleton via =org-air-view--render-loading= instead.  ONE scanner at a
  time — kills reproduction D (the machine can no longer be raced by its
  own debounce).
- Rail content repaint guard: =org-air-rail--show= skips the erase+
  re-insert when its input stamp — (owner buffer, =org-air-view--items=
  identity, items-key, filter, scope, expanded, cal-month, cols, height,
  descriptor identity) — equals the stamp of the last paint; any component
  change repaints.  With S1–S3 the steady state is zero rail repaints when
  nothing changed, and exactly ONE at the R26-8 swap (via the swap's
  normal render tail).

Batch: =noninteractive= never creates windows/timers — all four points are
interactive-only; the batch orientation dance and every golden are
untouched.

** Decision — compose at the REAL body width, measured AFTER geometry settles

  resolves width through the same helper before binding =org-air-view-

  ACTUAL window width.  Batch seams (=org-air-view-width= /
  =org-air-project-view-width= set) bypass the helper exactly as today.
- Re-fit on pop in/out and resize: the toggle and reconcile paths already

  existing ones terminate.
