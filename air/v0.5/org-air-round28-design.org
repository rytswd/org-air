* R28-1 — dimmer dims the preview pane: naming + soft-dep integration [BUG]

** Reproduction — the ONE org-air buffer without the =*org-air= prefix is the pane
The user excludes org-air from dimmer exactly as
=air/context/interface-design.md= recommends: =(add-to-list
'dimmer-buffer-exclusion-regexps "\\*org-air")= (anchored =\`\*org-air= in
their config).  Measured over every org-air-owned buffer (batch, the
regexp applied as dimmer applies it — =string-match-p= over
=buffer-name=, dimmer.el =dimmer-filtered-buffer-list=):

  all match — excluded, exactly what the user sees (board/rail undimmed).

- Context-doc audit: interface-design.md:8 sells the promise "buffer

  The pane broke the FIRST promise; this round revises the SECOND (the
  user asked for zero-config behaviour and the R27-4 evil setup set the
  soft-dep precedent).

** Decision — every owned buffer carries the prefix; org-air registers its own exclusion
Two layers, both small:
- *(a) Naming contract.*  =org-air-view-pane--indirect= drops the leading
  space: =(concat "*org-air-pane:" title "*")= (still through
  =generate-new-buffer-name=).  NEW INVARIANT, recorded in
  interface-design.md: every buffer org-air creates and shows in a window
  is named with the =*org-air= prefix — board =*org-air*=, rail
  =*org-air-rail*=, snapshot pane =*org-air-view*=, editable pane
  =*org-air-pane:TITLE*=, project =*org-air-project*=.  Trade-off
  accepted: the pane indirect becomes visible in buffer lists — it is
  transient (killed by the R20-3 teardown / rebuilt by follow), and
  consistency IS the contract the user configured against.  The doc-
  session and R20 return-mode host buffers are the USER'S file buffers —
  never renamed, never excluded (dimming those is the user's own policy).
- *(b) Soft-dep dimmer integration* (zero config, R27-4 idiom):
  - =org-air-dimmer-buffer-p (buf)= (org-air-view.el, view-core, next to
    the evil setup): non-nil when =(buffer-name buf)= matches
    =\`[ ]?\*org-air= — the optional-space belt keeps any legacy/hidden
    org-air internals covered no matter what (a) renames.
  - At load, =(with-eval-after-load 'dimmer (add-to-list
    'dimmer-buffer-exclusion-predicates #'org-air-dimmer-buffer-p))= —
    dimmer 0.4's per-buffer predicate seam (called with the buffer;
    truthy = never dimmed), the exact seam dimmer's own
    =dimmer-configure-*= helpers use.  =add-to-list= is idempotent; no
    =require=; when dimmer is absent the form never runs and no dimmer
    variable is created.  Users with the manual regexp keep working —
    layer (a) makes their regexp true again; layer (b) makes it
    unnecessary.
  - interface-design.md: the recipe paragraph is replaced by the shipped-
    integration statement (manual regexp kept as an alternative), and the
    naming invariant from (a) is recorded where the prefix promise lives.
- Test dep: =dimmer= joins =org-air-test-deps= (the evil precedent —
  MELPA, tiny) so ONE ERT can assert against the REAL
  =dimmer-filtered-buffer-list=; every other ERT is stub-based and
  gate-deterministic.

* R28-4 — rail outline highlights the current heading [NICE-TO-HAVE]

** Reproduction — baseline: no mechanism exists at all
Live (real Air repo session, rail popped, DOC context, 18 outline rows):
point moved from heading 0 to heading 17, timers given 0.6s — the rail
outline rows carry NO face and are byte- and face-identical before and
after (measured row-by-row over the =org-air-doc-heading-pos= rows).
Grep: zero highlight/overlay/current-heading code anywhere in the rail.
The building blocks are already there: every outline row carries
=org-air-doc-heading-pos= (org-air-project.el:1736–1744) — the same
property RET-jump uses (=org-air-rail-return=, org-air-view.el:3868).

** Decision — one hook, one timer slot, one overlay, one face; defer if it balloons
Explicitly OPTIONAL per the user; scoped to the minimum that cannot
flicker:
- Face: =org-air-face-outline-current= (org-air-faces.el) — a quiet
  current-row treatment following the two-background precedent (subtle
  background per light/dark class, no foreground change; =(t :inherit
  highlight)= terminal fallback).  NOT =org-air-face-faded='s failure
  mode: this is a background, so it never fights the row's own faces.
- Trigger: a BUFFER-LOCAL =post-command-hook= installed by
  =org-air-doc-session-mode= (and removed by its off-branch + the R26-5
  cleanup), debounced through ONE idle-timer slot
  (=org-air-rail--outline-timer=, ~0.1s, reschedule-not-stack — the
  R27-1 S3 timer discipline).  Interactive-only: =noninteractive= never
  installs the hook.
- Resolve: current heading = the LAST outline row whose
  =org-air-doc-heading-pos= ≤ =point= (a linear scan over the rail's few
  dozen rows; no Org re-parse, no =org-back-to-heading= in the doc
  needed).  Point before the first heading → no current row.
- Paint: ONE overlay (=org-air-rail--outline-overlay=) in the rail
  buffer, =move-overlay= onto the matching row's line, =face= +
  =evaporate=.  NO re-render, NO buffer text change: the R27-1 stamp
  guard sees nothing (point motion is not a stamp input — measured: zero
  rail repaints across the drive's moves), and rail byte goldens read
  =buffer-substring=, which overlays never touch.
- Degrade: the whole update wrapped in =condition-case= → on ANY error
  the overlay is deleted (no highlight, never a flicker or a message).
  Stale positions after doc edits simply highlight the nearest stale row
  until the next rail repaint rebuilds the outline — acceptable by
  design; live outline refresh stays out of scope.
- Teardown: session end / doc kill removes the hook and deletes the
  overlay; a rail repaint (=erase-buffer= in =org-air-rail--show=)
  collapses the overlay to zero length and the next tick re-places it.
- DEFER CLAUSE: if impl finds this interacting with the R27-1 rail
  machinery (repaints, reconcile, stamp) in ANY way that costs more than
  the mechanism above, ship R28-1/2/3/5 and defer this item to a later
  round — the user explicitly marked it optional.

- =r28-4-highlight-follows-point=: live session, rail popped: place
