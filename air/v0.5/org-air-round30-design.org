* R30-1 — rail inspector: wrap the title, never truncate; state+tags in a compact header block [POLISH]

** Reproduction — the title caps at maxtitle and buries state/tags
=org-air-view--inspector-title-lines= word-wraps the title but caps at
=org-air-inspector-max-title-lines= (default 4) and ellipsis-truncates
the overflow line.  Both the board (=org-air-view--inspector-item-fields=)
and the project (=org-air-project--inspector-doc-fields=) call it, so
both views truncate long titles.  The current field ORDER also scatters
the identity signals:
- board: title / state+priority / origin / *tags* / blank / dates …
- project: title / State / Path / *tags* / Group / blank / Created …
The state sits under the title but TAGS come after origin/path — the
user wants both STATE and TAGS in a compact block right at the top,
beside/under the title, before the metadata KV rows.

** Decision — full-wrap title + a compact identity header block (shared, both views)
Two shared changes in the core inspector primitives (no fork; the
project fields fn already delegates the title to the shared helper):

1. *Full-wrap title.*  Let =org-air-inspector-max-title-lines= accept
   =nil= = NO cap (wrap the whole title), and make =nil= the DEFAULT.
   =org-air-view--inspector-title-lines= returns all wrapped lines when
   the cap is nil; a positive integer keeps the old ellipsis-cap
   behaviour (back-compat knob, defcustom :type extended to
   =(choice (const :tag "wrap fully" nil) integer)=).  The reserved
   mid-rail region still bounds the whole inspector height
   (=org-air-view--inspector-rail-lines= seq-take), so a pathological
   title cannot push the rail — it simply consumes more of the region
   (breathing tail shrinks first).  A tall side-window rail shows the
   full title; a short one shows as much as the region holds — but the
   TITLE itself never carries a mid-word `…' lie.
2. *Compact identity header block.*  Reorder the leading fields of
   BOTH fields fns to a single top block:
   =title (wrapped) → state[+priority] → tags (wrapped)= — THEN the
   metadata KV rows (origin/path, blank, dates …).  The block is the
   row's identity; the KV rows are its metadata.  Tags move UP from
   after origin/path to directly under state.  No new lines are added
   in the common case (state and tags already exist) — they are
   REORDERED; the change is layout, within the same rail width and the
   same =org-air-view--pad-to= width bound at every tier.

* R30-2 — main-window C-c leader for the rail actions [BUG]

** Reproduction — the advertised keys are window-local; the doc buffer self-inserts
The rail Actions legend advertises verbs whose keys are bound in the
RAIL buffer's map (=org-air-rail-mode-map=: =q= quit/back, =RET=
jump-to-heading, =|= pop-in) or the board/project maps.  They only fire
when the SIDE WINDOW (or the board/project) is the selected window.  In
a doc session the user is editing the ACTUAL org file buffer, where:
- =RET= -> =org-return= (newline), =|= -> =self-insert-command=,
  single letters self-insert — so every advertised rail action is DEAD
  from the content buffer;
- only =C-c C-q= (R28-3's back verb) is reachable, because it is the
  one thing bound as a =C-c= leader in =org-air-doc-session-mode-map=.
R28-3 already established the pattern (a =C-c= leader for =back=, with
the legend deriving the key via =where-is-internal=); R30-2 GENERALISES
it to the other useful rail actions and to the board/project content
buffers.

** Decision — one shared leader prefix map, reused commands, context-correct legend
A single shared prefix keymap, installed on all three content buffers,
binding the EXISTING command symbols (no fork):

1. *Leader prefix* — a defcustom =org-air-leader-key= (default
   ="C-c C-a"=, mnemonic: Air; a clean, org-safe =C-c C-<letter>=
   leader that does not collide with org-mode's own =C-c= bindings in
   the doc session).  =org-air-leader-map= is the prefix keymap it
   points at.
2. *Bindings* (all reuse existing commands):
   | sub-key | command                       | context               |
   | =|=     | =org-air-rail-toggle=         | all three             |
   | =o=     | =org-air-rail-return= / open  | jump to outline/open  |
   | =n= =p= | outline next / prev heading   | doc session           |
   | =q=     | =org-air-project-back=        | doc session           |
   | =/=     | =org-air-filter= / project    | board / project       |
   | =s=     | =org-air-view-sort-cycle=     | board / project       |
   The prefix map is populated per host: the doc-session installs the
   nav/back/rail subset, the board/project install the filter/sort/rail
   subset.  =RET jump= from the rail becomes =C-c C-a o= from the doc
   buffer (jump the main window to the outline heading nearest point /
   the next heading) — reusing =org-air-rail-return='s target logic.
   Outline next/prev reuse a shared heading-motion primitive (the same
   =org-air-doc-heading-pos= scan the R28-4 highlight uses — no fork).
3. *Context-correct legend* — generalise R28-3's
   =org-air-project--doc-back-key= into =org-air-view--legend-key=
   (COMMAND, BUFFER): return =where-is-internal='s FIRSTONLY key for
   COMMAND resolved in BUFFER's own keymaps (so an evil/custom rebind
   shows what is really bound), formatted via =key-description=.  Each
   legend cell is built from the command's live key in the buffer the
   legend describes: in the read-only rail it returns the BARE key
   (=RET=, =|=); in the editable doc buffer it returns the LEADER form
   (=C-c C-a o=, =C-c C-a |=).  The legend never lies about
   reachability again — same derivation for every cell, not just back.
4. *Evil* — a =C-c= leader is state-agnostic (evil leaves =C-c=
   prefixes alone in normal AND insert state), so the leader works
   without any evil-specific handling; the existing R27-4 overriding
   maps keep the bare keys working in the read-only board/project/rail.

* R30-3 — dashboard column toggles (defcustom-backed) [FEATURE]

** Reproduction — the board always shows origin; no toggles exist
The board renders four data cells per row through the V6 fixed-column
table: the flex title, then the DATE / TAGS / ORIGIN cluster, sized by
=org-air-view--compute-meta-widths= (=dw= / =tw= / =ow=) and consumed
by =org-air-view--insert-item= (=dcol= / =tcol= / =ocol=).  Today =ow=
is accumulated unconditionally, so the origin (filename) column ALWAYS
shows and always claims width; there is no user control over any of the
three cluster columns.  The user wants the origin OFF by default
(filename is noise on the board) and dates/tags toggleable.

** Decision — three typed defcustoms + a display-toggle prefix; gate at the meta pass
Three clean boolean defcustoms (release-ready) and a runtime toggle
command each, all funnelling through the EXISTING compute-once / V6
relock (no new render path, no fork):

1. *Defcustoms* (board scope):
   - =org-air-show-origin= — default =nil= (filename column HIDDEN).
   - =org-air-show-dates= — default =t=.
   - =org-air-show-tags= — default =t=.
   All =:type boolean :group 'org-air=.
2. *Gate at the width pass* — in =org-air-view--compute-meta-widths=,
   seed/accumulate each column only when its toggle is on:
   =dw= starts at =org-air-date-column= only when =org-air-show-dates=
   (else 0, and the repeat reserve =rep= too); =tw= accumulates only
   when =org-air-show-tags=; =ow= only when =org-air-show-origin=.  A
   zeroed width makes =org-air-view--insert-item='s =dcol/tcol/ocol=
   zero, so =org-air-view--insert-row= skips that cell entirely (its
   =(when (> col 0) …)= guards already exist) and the freed columns
   flow to the flex title via the SAME title-min fit pass — V6
   alignment holds by construction (relock is automatic: the widths
   are recomputed every render).
3. *Toggle commands + keys* — a small display-column prefix keeps the
   flat board namespace clean and self-documents as a group.  Bind a
   prefix =z= (free on the board map; the vim "view/fold" family, and
   ours wins under the R27-4 overriding map) to
   =org-air-columns-prefix-map=:
   - =z f= =org-air-toggle-origin= (Filename)
   - =z d= =org-air-toggle-dates=
   - =z t= =org-air-toggle-tags=
   Each flips its defcustom buffer-locally and re-renders via the
   existing =org-air-view--refresh-current= (compute-once partition +
   V6 relock reused); each echoes the new state.  Documented in the
   rail Actions legend (a new "columns" hint) and in =?= help.
4. *Data stays queryable* — the toggles are DISPLAY-only: filter/scope
   read =org-air-item-tags= / dates / origin from the item structs, not
   the rendered cells, so hiding a column never removes it from
   =org-air-filter= / =org-air-scope= (a hidden tag column still
   filters by tag; a hidden date column still sorts by date).
5. *Project scope* — the project already dropped origin in R25-5 and
   composes its own date/tag cluster via the V6 =--insert-row=; a
   symmetric toggle COULD apply but is OUT OF SCOPE this round (the
   user scoped R30-3 to the board).  Noted for a follow-up; the
   defcustoms are board-named (=org-air-show-*=) so a future project
   variant is additive.

* R30-4 — outline rail for any org file: assessment + light scaffold [ASSESSMENT]

** Assessment — is the seam clean? YES, and the doc-session already proves it
The user asks whether the doc-session rail outline + R28-4
current-heading highlight could work for ANY org buffer, and whether it
belongs in a separate project.  Auditing the coupling:

- *Outline row build* — =org-air-project--doc-outline= is a pure
  =^\*+ [ \t]+= heading scan over the source buffer returning
  =(level title pos)=; it touches NO Air struct, NO project, NO airctl.
  Already generic.
- *Outline render* — =org-air-project--insert-doc-context= mixes a
  generic part (the Outline header + indented rows carrying
  =org-air-doc-heading-pos=) with an Air-specific meta block
  (=org-air-doc-state/-name/-tags=, the state badge).  The meta block
  is the only Air coupling and is trivially replaceable for a generic
  buffer (its =#+title:= / buffer name; skip the state badge).
- *Highlight core* — =org-air-rail--outline-highlight-update= scans the
  rail rows for =org-air-doc-heading-pos <= point= and =move-overlay='s
  ONE overlay; the CORE is generic.  Its GUARDS
  (=org-air-doc-session-mode=, =org-air-project--session-tree=) are the
  only Air coupling — loosened to "the source buffer's outline-owning
  minor mode is on".
- *Rail ownership* — the decisive finding: the DOC SESSION is ALREADY
  a non-board, plain org FILE buffer that owns the rail through the
  R26-5 descriptor seam (=:outline-fn= / =:actions-fn=) and the R27-1
  convergent machinery (back-pointer, stamp guard, reconcile).  A
  generic org buffer owning the rail is the SAME shape minus the tree/
  Air coupling.  The seam is genuinely clean: the rail renders only
  what the descriptor supplies.

Conclusion: the outline + highlight are separable from the Air/project
machinery TODAY, at low cost, because the doc-session is the existence
proof.  The dependency that remains is on org-air's OWN rail/layout
primitives (=org-air-view= / =org-air-layout=) — which is expected and
fine ("no Air dependency" = no dependency on the Air PROJECT machinery,
not on org-air's rail).  RECOMMENDATION: *(a) implement as a LIGHT
SCAFFOLD this round* — an opt-in =org-air-outline-mode= reusing the
extracted generic primitives + the rail descriptor seam; defer only the
