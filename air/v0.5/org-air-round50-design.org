* R50-1 — Legend key mislabel: investigation, fix, audit

** The true bindings (investigated, batch-verified)

- *Board* (=org-air-view-mode-map=, installer-owned R35-1 specs): ="g"= is
  bound to the *PREFIX* =org-air-g-prefix-map= (B4, org-air-view.el ~1111)
  — an evil-style g-prefix: =g r= → =org-air-refresh=, =g g= →
  =org-air-goto-top=, =g R= → =org-air-refresh-all=, =g RET= →
  =org-air-visit-item=, =g o= → =org-air-visit-item-stay=.
  =(lookup-key org-air-view-mode-map (kbd "g"))= is a keymap;
  =(where-is-internal #'org-air-refresh org-air-view-mode-map t)= →
  ="g r"=. The legend cell (=org-air-view--insert-actions-default=,
  org-air-view.el ~3826) hardcodes the STRING ="g" "refresh"= → *MISLABEL*.
- *Project* (=org-air-project-mode-map=): ="g"= is bound DIRECTLY to
  =org-air-project-refresh= — the project legend's =g refresh= cell
  (=org-air-project--actions-table=) is *TRUE*. No change.
- *Doc-session / outline rails*: every cell already derives its key text
  from the LIVE binding via =org-air-view--legend-key= (the R30-2
  =where-is= seam) — *TRUE by construction*. No change.
- History note: R8/B4 blessed =gr refresh=, D5f deliberately re-blessed it
  to the "primary key" =g refresh= (see
  =org-air-b4-rail-hint-shows-g-prefix= in tests/org-air-bugs-test.el).
  R50 rules that D5f display choice a LIE: a legend key must be the real
  key-to-action sequence, never a bare prefix.

** The fix — derive the board legend like the doc legend (no more strings)

=org-air-view--insert-actions-default= stops hardcoding key texts. Every
cell's key derives from the LIVE binding through the ONE existing seam,
=org-air-view--legend-key= (COMMAND, BUFFER, FALLBACK), resolved in the
*BOARD* buffer (=(get-buffer org-air-view-buffer-name)= — the buffer where
these keys actually fire; the legend may render in the rail side window,
whose own map does not carry the board verbs):

- =c= → =org-air-capture= (fallback ="c"=), =/= → =org-air-filter=
  (="/"=), =s= → =org-air-scope= (="s"=), refresh → =org-air-refresh=
  (fallback ="g r"= — the true sequence even when the buffer is dead),
  =TAB= → =org-air-toggle-section= (="TAB"=), =S= → =org-air-scope-clear=
  (="S"=), =?= → =org-air-help= (="?"=).
- Column widths =c1=/=c2= are computed from the DERIVED cell strings
  (=string-width=), not from hardcoded lengths — ="g r"= widens column 1
  by 2 and the layout follows automatically at every rail tier
  (wide/mid/narrow gap rules unchanged).
- Consequence: the legend now respects =org-air-use-default-keybindings=
  (knob off → =where-is= finds nothing; fallbacks keep the legend
  readable, same behaviour class as the doc legend today), a user
  =define-key= rebinding, =org-air-leader-key= moves, and evil (the R29-2
  overriding-map makes =where-is= in the board buffer return the same
  sequences evil actually dispatches). Under the default setup the ONLY
  visible change is =g refresh= → =g r refresh=.

Prose-marker fixes (same mislabel, same round): the header failed marker
and the three echo messages become =refresh failed (g r retries)= /
="org-air: refresh failed: %s (g r retries)"=. The off-by-default footer
band string becomes =[g r] refresh= (bracket-key idiom kept for the other
cells). Docstring mentions of "=g= mid-refresh"/"=g= retries" in
org-air-view.el are tidied to =g r= (comment-only, no behaviour).

Guard so this class never returns: the project legend-truth ERT
(=org-air-r26-3-legend-truth-table-driven=) gains a conjunct — every table
key must resolve via =key-binding= to a COMMAND and *NOT* to a keymap
(=(not (keymapp …))=); the new board test asserts the same over the board
legend's derived keys. A future prefixization of any legend key fails the
gate instead of silently mislabelling.

* R50-2 — =?= help → a proper =*org-air-help*= buffer

** Behaviour

=org-air-help= (SAME command symbol — every existing =?= binding and test
hook keeps working) stops =message='ing and instead pops a dedicated
=*org-air-help*= buffer, mu4e/magit style:

- *Context-aware*: the command captures the ORIGIN buffer and picks the
  group set by context — =org-air-view-mode= → board;
  =org-air-project-mode= → project; =org-air-doc-session-mode= (minor, in
  the editable doc file buffer) → doc-session; anything else falls back to
  the board set (matches today's echo fallback). The header line names it:
  =org-air help — board / project / doc session=.
- *Formatted + scrollable*: a normal read-only buffer in a new
  =org-air-help-mode= (derived from =special-mode=), grouped sections with
  the rail header idiom (=org-air-view--rail-header= face family), one
  binding per row: KEY (keycap face =org-air-face-rail-key=, right-padded
  to the widest key in the section) + description (=org-air-face-faded=).
  Blank line between groups; the buffer scrolls like any other (SPC/DEL
  from =special-mode=, evil motions under evil).
- *Derived from the ACTUAL keymaps*: each row's key text comes from
  =org-air-view--legend-key= (COMMAND, ORIGIN-BUFFER) — =where-is= against
  the origin buffer's LIVE active maps. Prefix sequences render naturally
  (=g r=, =g R=, =z f=, =C-c C-a |=); an evil rebinding, a custom
  =org-air-leader-key=, or a user =define-key= all show what is REALLY
  bound. A command with NO live key (e.g. knob off, or a user unbind)
  renders a faded =M-x command-name= cell instead of a lie — help stays
  honest AND useful.
- *=q= to quit back*: =org-air-help-mode= inherits =special-mode='s =q= →
  =quit-window= (a PARENT binding, so it works even with
  =org-air-use-default-keybindings= nil — the knob only clears
  installer-owned keys). The buffer is displayed via =pop-to-buffer= so
  =quit-window= restores the origin window/buffer.
- *Gating*: the =?= keys are ALREADY installer-owned
  (=org-air-view-mode-map= ~1431, =org-air-project-mode-map= ~2301) —
  knob off removes them, =M-x org-air-help= still works. NEW: the
  doc-session leader map (=org-air-doc-leader-map=) gains ="?"= →
  =org-air-help= (installer-owned, so knob-gated), making help reachable
  from the EDITABLE doc org buffer as =C-c C-a ?= (bare =?= must keep
  self-inserting there — R20-3a rule).

** Content — the group tables are THE source (data, not prose)

Three data tables (=org-air-help--board-groups= /
=--project-groups= / =--doc-groups=), each a list of
=(GROUP-TITLE . ((COMMAND . DESCRIPTION) …))=. Key text is NEVER stored —
always derived at render time. Groups per the ask (navigation, triage,
filter/sort, rail, refresh, session):

- *Board*: Navigation (=org-air-next-item= / =-prev-item=,
  =org-air-toggle-section=, =M-TAB= / =backtab= section hops,
  =org-air-goto-top= (=g g=), =org-air-goto-bottom=, =org-air-peek-item=,
  =org-air-visit-item= + =-stay=, calendar =<= / =>= / =.=) · Triage
  (capture, refile, deadline, tag, todo-cycle, archive, done, kill, undo,
  mark, =org-air-process-inbox=) · Filter & sort (=org-air-filter=,
  =-filter-clear=, =-filter-toggle-match=, =org-air-view-sort-cycle= /
  =-reverse=) · Source & scope (=org-air-scope=, =org-air-scope-clear=) ·
  Columns (=z f= / =z d= / =z t= toggles) · Rail (=org-air-rail-toggle=,
  the leader forms) · Refresh (=org-air-refresh= → =g r=,
  =org-air-refresh-all= → =g R=) · Session (=org-air-project=,
  =org-air-quit=, =org-air-help=).
- *Project*: Navigation (=org-air-project-next= / =-prev=,
  =org-air-project-open=, =-visit=, =-toggle-dropped=) · Display
  (=-toggle-filenames=, group by state/dir/tag, sort cycle/reverse) ·
  Filter (=org-air-project-filter=, clear, combinator) · Rail
  (=org-air-rail-toggle=) · Refresh (=org-air-project-refresh= → =g=) ·
  Session (=org-air-project-quit=, =org-air-help=).
- *Doc-session*: Session (=org-air-project-back= → =C-c C-q= + the leader
  =q=) · Navigation (leader =n= / =p= outline motions — the R39-4
  repeatable wrappers) · Rail (leader =|=) · Help (leader =?=).

The old one-line echo text is DELETED (both branches). The two existing
