* R51-1 — Drop the strike-through completely

** Root cause of the full-width rule (investigated)

=org-air-view--insert-row= applies the caller's =:face= as =font-lock-face=
over the ENTIRE row extent (org-air-view.el ~3155: "keeps the FULL row
extent so click/RET resolution … are untouched") — title, the flex pad
between title and the meta cluster, and the trailing pad.
=:strike-through= is a face attribute drawn across every glyph of the run
*including spaces*, so on a dropped row the strike line runs from the
title's last character clear across the fill to the date column — the
horizontal RULE in the user's screenshot.  The face is the bug, not the
row primitive: any whole-row face with =:strike-through= draws this rule
by construction.

** The change: remove =:strike-through= from BOTH dropped faces

org-air-faces.el:

- =org-air-face-project-dropped= (~793): =((t :inherit org-air-face-faded
  :strike-through t))= → =((t :inherit org-air-face-faded))=.  The row
  treatment is now grey ONLY.
- =org-air-face-air-state-dropped= (~785, the badge-only face): same
  removal → =((t :inherit org-air-face-faded))=.  This face colours every
  OTHER dropped surface, and de-striking it fixes them all at once:
  - the TTY =DROP= token / =[X]= state cell (=--state-token= /
    =--state-cell=);
  - the GUI pill (=--state-svg-badge= derives only the COLOUR from the
    face foreground — strike never rendered there; no visual change);
  - the per-dir rollup letter =X= in =--dir-count-summary= (struck today);
  - the =Dropped= state-section heading icon;
  - the INSPECTOR's =State= line — =org-air-project--inspector-doc-fields=
    (~1469) faces the label via =org-air-project--state-face= → this face,
    so the struck =Dropped= label the round calls out de-strikes here, by
    the same one-face fix.

Audit (grep-verified): these two face specs are the ONLY
=:strike-through= applications in the codebase reachable from a dropped
doc.  =org-air-face-done= carries no strike (faded only); the round-33
attribute-iteration test merely ENUMERATES the attr; nothing else sets it.

* R51-2 — Dropped items sort to the group bottom

** The canonical within-group state ordering (this round defines it)

ready → work-in-progress → complete → draft → (unknown states) →
*dropped LAST*.

Dropped ranks below draft AND below unknown/non-canonical states — "below
every other state".  Rationale for unknown-before-dropped: an unknown
state is a metadata bug on a LIVE doc (fix the header); dropped is
deliberately dead — dead sorts after broken.

** Why a NEW rank source (and not reordering the existing constants)

- =org-air-project--state-display-order= (=ready wip complete dropped
  draft=) also drives the =--dir-count-summary= LETTER order, whose byte
  parity with =airctl status -Da= (=R4(+1) C14(+14) X1(+9) D2(+8)= ↔
  =🎯 ✅ 🗑️ 📝=) was re-verified and pinned at the R48 closeout.
  Reordering it would break that header contract.  It stays UNTOUCHED and
  becomes counts-only; its R20-5 docstring ("drives BOTH … so the two can
  never drift") is rewritten: the split is now INTENTIONAL — letter order
  is the airctl parity contract, row order is the R51-2 UX ordering;
  cross-link the new constant.
- =org-air-project-sections= (=draft ready wip complete dropped=) is the
  user-owned STATE-grouping section order and the current
  =--doc-compare= rank source — reordering the defcustom would move
  users' section layouts.  It stays untouched too.

New, in org-air-project.el (sort block):

- =defconst org-air-project--state-sort-order= —
  ='("ready" "work-in-progress" "complete" "draft")= — the R51-2 row
  ordering for the CANONICAL live states.
- =org-air-project--state-sort-rank (state)= — the ONE rank fn both
  comparators call: ="dropped"= → 5 (absolute last, PAST unknown); a
  member of =--state-sort-order= → its position (0–3); anything else
  (unknown/non-canonical) → 4 (one shared rank; ordering among distinct
  unknown states stays the existing state-string tiebreak).

** Wiring (both comparators; the two orders can no longer disagree)

- =org-air-project--state-first-lessp= (~646, the DIR tree own-docs
  primary): =--state-display-rank= → =--state-sort-rank=.
  =--state-display-rank= loses its only caller and is DELETED.
- =org-air-project--doc-compare= (~1190, the state/tag SECTION
  comparator): =--state-rank= → =--state-sort-rank=; the both-unknown
  string-order clause compares against the new shared unknown rank (4).
  =--state-rank= loses its only caller and is DELETED.
- State grouping SECTION order: unchanged (=--sections-by-state= reads
  =org-air-project-sections= directly).  The =Dropped= section already
  sits last of the canonical lifecycle; hoisting it below the
  dynamically-appended unknown-state sections would let a typo-state
  outrank a real lifecycle bucket — explicitly OUT of scope, noted.

* R51-3 — TAB/RET on the fold row itself expands

** Investigated baseline (probed in batch, this round's evidence)

- BOARD =…and N more — press TAB on the title to expand= row
  (=org-air-view--insert-section= ~3420): the row carries NO text
  property at all (faded label + margin only).  TAB there runs
  =org-air-toggle-section= → =org-air-view--line-section= finds no
  =org-air-section= on the line → falls through to
  =org-air-next-section=: point DRIFTS to the next section header (probe:
  line 16 → 18) and =org-air-view--expanded-sections= stays nil.  RET
  there is =org-air-view-pane-return= (the pane verb) — not the fold.
  The row teaches a key that does nothing where it is read.  BUG.
- PROJECT =… N dropped — TAB to show= row: WORKS on trunk.  The row
  carries =org-air-dropped-fold= over its full extent;
  =org-air-project-toggle-dropped= (TAB, rule 1) toggles and
  =org-air-project-open= (RET/mouse-1) has the R48-3 fold branch.  Probe:
  TAB binding at the fold row resolves to the toggle, expansion key set,
  visible docs 6 → 7.  NO code change; a lock ERT keeps it true.

** Fix (board only)

- =org-air-view--insert-section=: propertize the more row with
  =org-air-more-row BUCKET= (the section's bucket symbol, whole row —
  the dispatch handle, board twin of =org-air-dropped-fold=) and
  =mouse-face 'org-air-face-cursor= over the label text (the row is
  text-only, so the R47 no-mouse-face-over-images invariant is trivially
  safe).  NO =org-air-item= — n/p item motion and the inspector keep
  skipping the row by construction.  The label TEXT does not change
  ("press TAB on the title to expand" stays byte-frozen — the affordance
  catches up to the copy; every board golden stays byte-identical).
- =org-air-toggle-section= precedence (after the loading guard):
  1. on a section HEADER: toggle — unchanged;
  2. NEW: on a more row (=org-air-view--row-property 'org-air-more-row=
     → BUCKET): EXPAND that bucket (the row exists only while collapsed,
     so this branch never collapses), through the EXISTING render seam
     (=--render-section= for board-only/side-window orientations, else
     the full render — the same fork the header branch takes).  Point:
     remember the first HIDDEN item (index =org-air-view--section-limit=
     of the bucket's displayed-order list) BEFORE the render, then land
     on its row title after (the revealed rows replace the more row, so
     point stays put visually); fallback to the section header via
     =org-air-view--find-property 'org-air-section= (never worse than
     today).
  3. anywhere else: =org-air-next-section= safe motion — unchanged.
- =org-air-view-pane-return= (RET and =<mouse-1>= — same command, ~6419):
  a more-row branch BEFORE the pane logic — when
  =org-air-view--row-property 'org-air-more-row= is non-nil, dispatch to
  =org-air-toggle-section= and do ONLY that (nothing opens, no pane) —
  the exact shape of the R48-3 fold branch in =org-air-project-open=.
