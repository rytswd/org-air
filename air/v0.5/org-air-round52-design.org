* R52-1 — Investigation: where the rollup is justified to the RHS

The ONE render site is =org-air-project--insert-dir-node=
(org-air-project.el ~894).  Per directory node it builds:

- =left=  — the guide (top dir: margin + accent marker; child dir: margin
  + faded ancestor rails + tee/corner connector) followed by the =dir/=
  name in =org-air-face-section=;
- =summary= — =org-air-project--dir-count-summary= (~772): the quiet
  letter-count rollup (=R4(+1) C14(+14) …=), state letter in the state
  face, own count in =org-air-face-count=, faded =(+M)= descendant
  rollup, display order =org-air-project--state-display-order=;
- =header= (~933) — the detachment happens HERE:

  : (header (if (string-empty-p summary)
  :             left
  :           (org-air-view--justify left summary width)))

=org-air-view--justify= pads LEFT out to =width - (string-width summary)=
and flushes the summary to the pane's right edge.  WIDTH is the doc-pane
content width, so the detachment scales with the frame: at the fixture
width 100 (inline rail) the summary lands ~col 69; with the rail popped
to a side window (R49-2) the pane composes at the full host width and the
rollup floats out by the doc rows' date column (the user's ~col 145) —
maximally far from the name it describes.  R22-6 chose this deliberately
("sibling dir headers line up vertically"); R52 rules that columnar
alignment loses to ADJACENCY: at real widths the rollup reads as a stray
cell of the neighbouring doc rows' meta cluster, not as the header's own
annotation.

The state/tag SECTION headings are NOT affected and need no change: their
count badge already sits immediately after the title
(=org-air-project--insert-section-heading= — marker + icon + title + " " +
count).  Only the directory tree ever right-justified its rollup.

* R52-1 — The change (one expression + prose)

In =org-air-project--insert-dir-node=, replace the justify branch with
LEFT-anchored composition — the name, a two-space gap, the summary —
clamped to WIDTH with the shared =more= ellipsis (the exact clamp idiom of
the R48-3 fold row):

: (header (if (string-empty-p summary)
:             left
:           (let ((h (concat left "  " summary)))
:             (if (> (string-width h) width)
:                 (truncate-string-to-width h width nil nil
:                                           (org-air-view--glyph 'more))
:               h))))

Decisions, pinned:

- *Gap = two literal spaces.*  One space would read as another token in
  the letter-count run (=v0.1/ R4(+1)= scans as one cluster); two is the
  view's established cluster gap (the meta-cluster =gap 2= in
  =--fit-meta-widths=, the header-line pad).  Not a defcustom — the R22-6
  summary itself is not knob-controlled either.
- *No pad to WIDTH.*  The header now ENDS after the summary (plus =\n=).
  Downstream is indifferent: the =org-air-section= text property spans
  start..point regardless of line length, and in the two-pane composition
  =org-air-view--compose-columns= re-pads every doc-pane line to
  item-width via =--pad-to= — so the divider column and the rail are
  byte-untouched (verified in the probe render: only in-pane spaces
  move).
- *Overflow clamp, not overflow.*  A long =dir/= name (or a deep child's
  rails + name) plus the summary can exceed WIDTH; the clamp truncates at
  WIDTH with the =more= glyph exactly like
  =org-air-project--insert-dropped-fold-row= clamps its label — the
  header can never spill past the pane / push the divider.  Degenerate
  reading is name-first (the summary tail clips), which is correct: the
  NAME is the identity, the rollup the annotation.  Under the old justify
  the same degenerate case clipped the summary's right end too
  (=--pad-to='s truncate), so nothing regresses.
- *Nested subgroups for free.*  =left= already carries the child's
  ancestor rails + connector at its own indent, so a child header reads
  =+- air-context/  D1= — the summary adjacent to ITS name at ITS depth.
  No depth-conditional logic.
- *Root-docs node unchanged in kind.*  The rootless =·= node (empty
  :path) composes the same way: =·  D2= when it has counts.
- *Empty summary branch unchanged* — a (hypothetical) all-unknown dir
  keeps the bare =left= header.
- *The rollup builder is UNTOUCHED.*  =org-air-project--dir-count-summary=
  keeps its tokens, faces, =(+N)= semantics and letter ORDER
  (=--state-display-order= — the airctl =status -Da= parity contract
  R22-6 pinned and R51-2 explicitly preserves as the counts-only order).
  Numeric parity ERTs (r22-6-dir-count-summary-matches-airctl,
  r26-2-rollup-letters-unchanged) stay green by construction.
