** Root cause — the render tails are ungoverned

R62 taught the RECONCILER that review is a host
(=org-air-rail--host-buffer-p= :6027).  But the reconciler is only
one of the rail's mutators.  The board's full render
(=org-air-view--render=) unconditionally drives the shared rail
whenever its OWN popped flag is up:

- orientation cond :7056 tests only =org-air-rail--popped-p= —
  never "am I the active view", never the suspension flag;
- the width resolution :7071 calls =org-air-rail--host-width= which
  ENSURES (creates/resizes) the side window;
- the render tail :7170 calls =org-air-rail--show=, which re-owns
  the window and REWRITES the shared rail buffer's content
  (=org-air-rail--render=) — and via the R58 undisplayed-host carve
  (:5560) it rewrites the CONTENT even when the board has no window
  at all, so in the single-main-window shape the visible review rail
  flips to board content with no window event whatsoever;
- =org-air-rail--evict-foreign-rail= :6077 lets ANY view's render
  tail sweep a rail it does not own.

During the load, two board-side paths reach that tail while REVIEW
is the user's view:

1. /C1 resize-refresh/: review's rail pop resizes the board's
   still-live window → the layout hook re-renders the board — with
   the board's window HOOK-SELECTED (=window-size-change-functions=
   context), which is why an instantaneous
   =org-air-rail--active-view= test inside the tail misreads the
   board as active (measured: prototype A's +0.01 s steal).
2. /R56 progressive + finish repaints/: timer-driven, selection
   settled on review, but the tail never asks.

Each steal re-owns the rail buffer's back-pointer, so the NEXT
window-config change lets the reconciler re-own it for review
(branch A), and each review re-render/resize does the same — the
observed ping-pong.  The reconciler itself is NOT the bug: its
single timer slot (R27-1 S3) held (≤ 1 pending timer throughout the
run); it repeatedly REPAIRS a theft the render tails keep
committing.

The same class covers every paced surface: the revisit and review
cold fills and the project doc refresh all end in the same choke
points, so the fix is placed there, not in the board.

** The fix — a deterministic two-belt single-owner rule (R63-1)

/The rule/: the shared =*org-air-rail*= may be mutated ONLY by (1)
the reconciler (which already resolves the settled active view from
a 0 s timer) and (2) a render tail whose view currently OWNS the
rail claim.  Ownership is transferred synchronously, never inferred
from transient window selection.

*R63-1a — the tail-owner gate.*  New predicate
=org-air-rail--tail-owner-p (self &optional frame)=:

#+begin_example
non-suspended?  (buffer-local org-air-view--rail-suspended of SELF is nil)
AND (active is nil OR active == SELF)
    where active = (org-air-rail--active-view frame)
#+end_example

Gated call sites (the three choke points — every render tail in
board/project/revisit/review and the doc-session rail routes through
them):

- =org-air-rail--show= (:5820): gate fails ⇒ full no-op — no window
  ensure, NO content render (the R58 carve is subordinate to the
  gate, see R63-1c), returns nil — and SELF self-suspends
  (=org-air-view--rail-suspended= t) so every later background
  render during the load is skipped by the first conjunct without
  re-resolving anything.
- =org-air-rail--host-width= (:5776): gate fails ⇒ skip the
  =--ensure-window= call; the width measure falls through to the
  live-window/fallback branches unchanged (the host window's usable
  columns are already rail-adjusted, since the rail lives on the
  frame under its real owner).
- =org-air-rail--evict-foreign-rail= (:6077): gate fails ⇒ no sweep.
  Sweeping a foreign rail is an owner/active privilege; without this
  the gated board tail (owner ≠ self, no =--show= re-own) would fall
  through to the evict and DELETE review's rail — the same bug with
  the opposite sign.

The reconciler's own calls to =--show= are exempt by construction:
branch A (re-own) and the suspended re-pop branch first clear the
target's suspended flag and run for the SETTLED active view, so the
gate passes.  =org-air-rail-toggle= clears the flag before its
refresh (it already does), so a user toggle always passes.

*R63-1b — ownership-transfer suspension.*  =org-air-rail--show=
gains one step at the top: when a live rail's owner
(=org-air-rail--side-owner=) differs from the incoming host, the
PREVIOUS owner is marked =org-air-view--rail-suspended= t before the
re-own — synchronously, in the same call that takes the rail.  This
mirrors exactly what the reconciler's re-own branch does (:6167
region) and is what makes the rule deterministic: the instant review
takes the rail on =W=, the board is suspended, and belt 2's
hook-selection blind spot is closed BEFORE the C1 render can fire.
Measured: prototype A (gate only) leaked the +0.01 s steal;
prototype B (both belts) leaked nothing — 0 owner flips.

*R63-1c — precedence over R58.*  The R58 undisplayed-host carve
(=--show= still renders rail CONTENT for a windowless host so a
bookmark restore hands the restorer a fresh buffer) is subordinated:
gate first, carve second.  In the restore flow no other org-air host
is active (active = nil ⇒ gate passes), so R58 behaviour is
unchanged there; in the mid-fill flow the carve was the
content-flip vector and must lose.  Corner accepted + documented: a
bookmark restoring view B undisplayed WHILE view A is active keeps
A's rail content; B's rail freshens on the render that fires when
the restorer displays B (the C1 path R58 already relies on).

*R63-1d — the un-suspend path (already exists, now load-bearing).*
A suspended view re-pops ONLY via the reconciler's suspended branch
(settled active view, 0 s timer) — measured in the prototype run:
after =q= the board's own quit-path render was gated (still
suspended) and the reconciler performed the re-pop; end state owner
= board, rail live, suspended nil.  No new mechanism; the R25-6
contract "the reconciler owns the suspension flag's falling edge"
is simply now stated and pinned (T5).

/Bounded residual (documented, not fixed)/: a THIRD view mid-fill
that has never owned the rail could, in the narrow hook-selection
window of ITS OWN resize, pass the gate and steal once; belt 1 then
suspends the true owner, the 0 s reconcile re-owns for the settled
active view, and the thief is suspended by transfer — one bounded
flip, self-healing, no oscillation.  The reported two-view scenario
has zero flips (verified).

Ruled out:

- /Coalescing/debouncing the reconcile/: the reconciler already runs
  one pending timer (R27-1 S3; ≤ 1 measured throughout) — it is the
  repair crew, not the thief; slowing it only lengthens each theft.
- /Gating only the progressive paint/: fixes steal #2, leaves #1
  (the C1 resize render) and every future background render path
  open.  The choke-point gate covers the class.
- /An instantaneous active-view check alone/: measured insufficient
  (prototype A) — hook-time window selection lies.
- /Suspension flag alone (no active check)/: leaves the
  never-owned-third-view fills ungated; the active check blocks
  those timer-driven repaints (selection settled), so both belts
  stay.
