* New findings (this round)

** [HIGH] Date labels are sign-inverted — overdue ⇄ future swapped
- *Where:* ~org-air-view.el~ ~org-air-view--date-label~, the two "OVERDUE"
  ~cond~ branches.
- *What:* every *future* deadline/schedule is labelled "OVERDUE Nd", and
  every *actually-overdue* item is shown as a benign upcoming date. This
  is the precise signal round 2 asked for — inverted, so it is worse than
  having no label: it actively misleads.
- *Live evidence (frozen now = 2026-06-15):*
  | item                         | fixture date        | renders     | correct      |
  | Ship quarterly report        | DEADLINE 06-17 (+2) | OVERDUE 2d  | in 2 days    |
  | Fix production outage runbook | DEADLINE 06-10 (-5) | 10 Jun      | OVERDUE 5d   |
  | Book dentist appointment     | DEADLINE 06-12 (-3) | 12 Jun      | OVERDUE 3d   |
  | Email finance about budget   | SCHEDULED 06-16 (+1)| OVERDUE 1d  | Tomorrow     |
  | Prepare standup notes        | SCHEDULED 06-16 (+1)| OVERDUE 1d  | Tomorrow     |
- *Root cause:* ~org-air-view--days-between(then now)~ returns ~now − then~
  (positive for the *past*). The stale branch and ~--human-date~ use it
  correctly (note ~--human-date~ deliberately calls it as ~(now time)~ to
  get future-positive). But the overdue branches test
  ~(< (org-air-view--days-between deadline now) 0)~, which is true for the
  *future*, not the past.
  - Verified: ~days-between(06-17,06-15) = -2~ (caught as overdue, wrong);
    ~days-between(06-10,06-15) = 5~ (not caught, wrong).
- *Fix (minimal):* flip the comparison in both overdue branches from
  ~<~ to ~>~ — i.e. an item is overdue when ~(> (days-between date now) 0)~.
  No other change needed; ~--human-date~ and the stale label already use
  the correct sign, so do not touch them.

** [MINOR] Calendar legend is misleading and ungrammatical
- *Where:* ~org-air-calendar.el~ — the trailing legend renders as
  ~"o items, # today"~.
- *What:* "~o items~" is ungrammatical, and "~# today~" references a "#"
  marker that does not exist on the grid — today is shown by colour +
  underline (15), not a "#". The legend keys do not match the rendering.
- *Fix:* either drop the legend or make it match, e.g.
  "~• has items   today is underlined~" (GUI) / a TTY-appropriate variant.
  (The day marker itself — "o" in batch, "•" in GUI — is fine and keeps
  column alignment.)

** [INFO] Adjacent tags can share an accent hue
- *Where:* deterministic hashing in ~org-air-faces-tag-face~.
- *What:* with six hues, ~#projects~ and ~#work~ both map to accent-1 and
  sit side-by-side on many rows, so the two chips are the same colour.
  Not a bug (mapping is stable by design) and not blocking — noting as a
  cosmetic ceiling of a 6-hue space. Optional mitigation: rely on the
  chip box/background (already present) for separation, or special-case a
  small set of very common tags. Low priority.

** [INFO] High-priority section count is neutral
- The High priority section can hold overdue ~[#A]~ items yet uses the
  neutral count badge. Arguably it merits ~count-attention~ too. Purely a
  judgement call; leaving as INFO.
